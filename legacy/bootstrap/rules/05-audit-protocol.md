# 05 — 论文审计协议

> 来源：Hermes skill `mathmodel/paper-writer` → `references/paper-audit-protocol.md`
> 日常与阶段审计按对象路由到相关章节；里程碑、节点收尾和终稿阶段必须逐条执行全文。
>
> **唯一职责：**对已有成果取证、分类缺陷并作通过判定。本文件引用建设规范但不重写
> 它们，也不承担初稿生成、终稿打包或方法选择。成果是否修改取决于当前阶段授权。
> 审计 `06`、`13` 时必须读取其规则强度：A 为硬门，B 为默认质量门，C 先验证触发
> 条件，D 只能作诊断，E 不得用作不通过判据。不得因规则来自讲座或优秀论文而整体
> 降级，也不得因来源知名而整体升级。

---

## 强度

本文件不把 D/E 项升级为失败条件。A/B 提供失败依据，C 先验证触发条件，D 仅发现风险。
审计范围服从阶段：局部工作可按文件导航读取相关章节，但项目启用、断点恢复、里程碑、
节点收尾和终稿闭环必须执行规定的全项目读取与全量审计。

## 文件导航

| 审计对象 | 读取范围 |
|---|---|
| 题意、planning 与端到端证据链 | `-1` 至 `0.2` |
| 数字、精度、文风与摘要 | `1` 至 `6.2` |
| 图表、标题和公式—代码一致性 | `8` 至 `10.3` |
| 图表回应、全文连贯和逐句语言 | `11` 至 `12.1` |
| 页面、脚本和数字追踪 | `12.2` 至文件末 |

终稿与里程碑仍须全量读取。本导航只用于普通阶段定位，不允许用局部检查宣称全文通过。
文件超过 500 行仅构成待重构信号；未经用户确认具体迁移和删除项，不拆除原规则。

## 执行步骤

### -2. 读者优先结构门

论文内容审计开始前，完整执行 `17-reader-first-manuscript-audit.md`。先验证完整阅读
证明和全文结构，再进入题意、证据、公式、语言与版面检查。结构门失败时，不得用后续
数字复算、代码验证、编译成功或页面正常把模块标为通过。

模块判定必须使用 `17` 规定的七级状态机。只有“表达与证据均通过，待人工审计”可以
提交负责人审阅；只有负责人明确确认后才能记为“人工审计通过”。用户指出缺少背景、
全文术语难懂或数据没有解释时，按可泛化缺陷回退所有受影响模块，不得只修暴露句。

### -1. 建模前题意概念审计

在端到端证据链之前，先检查项目是否形成独立于模型和结果的题意语义底稿。该底稿必须
逐项记录：

- 题目核心名词的现实含义、本文限定和相邻概念区别；
- 各主体的职能边界及未纳入模型的外部系统；
- 每问的对象、动作、量词、时态、情景、输出和与其他小问的继承关系；
- 数据字段能够观察的能力与无法观察的能力；
- “合理、有效、最优、可行、安全”等评价词的指标、基准、阈值和适用范围；
- 题面明示要求、隐含可执行性、主动增强、适用边界和范围外扩展的分类；
- 对存在重要量词、范围、极端条件或外推风险的主张，构造边界反例并判断它否定原题
  命题还是仅否定额外扩展；没有此类风险时，直接检查边界与适用范围，不机械制造反例。

执行双向检查：

1. 从题目到模型：每个变量、目标和约束能否追溯到明确任务、可执行性要求或已声明的
   主动增强；
2. 从模型到题目：每项模型能力是否被误写成研究对象的全部现实职能，每项模型结论
   是否扩大了题目量词、情景或系统边界。

另执行题号与任务边界检查：分别记录竞赛/年份、所选赛题编号或字母、题内问题编号和
小问编号；逐项比对原题、任务矩阵和论文标题。原题未出现的内部问题不得由文件名、
旧代码目录、模板或流程惯例补出。任何“下一问”、新增 `qN` 路径或新增题号标题在
落地前都必须通过该检查；不一致时以原题修正派生文档，而不是多数表决。

若核心名词尚无唯一含义，或“评价合理性”尚未操作化，应暂停建模。先把分析写入内部
文档并接受审计；未经确认，不得把探索性概念分析直接升级为论文主张。

### -0.5 Planning 权威层级审计

审计 `planning/` 是否按职责而非时间堆放：

- 所有 `.md` 使用 Markdown 标题、列表、链接、表格、行内代码或围栏代码块，不含
  LaTeX 文档命令、环境、引用命令、交叉引用命令和数学定界符；
- 所有 `.tex` 使用有效 LaTeX，不把 Markdown 标题、强调、链接、管道表格和围栏代码块
  当作正文结构；从 Markdown 迁移的内容已经显式转换而非只改扩展名；
- 根目录只保留当前权威文档和持续日志；
- `analysis/` 只放待审专题分析，并标注是否允许进入论文；
- `audits/` 只放带日期的版本审计，不把旧“终稿审计”当作当前通过证明；
- `archive/` 只放已被替代的历史材料；
- `planning/README.md` 能让新会话判断先读什么、什么仍待确认、什么只供追溯；
- 同一职责不存在两个均自称“当前”或“最终”的文件；
- 文件移动后，README、HANDOFF、日志和正文引用中没有旧路径残留。
- 长论文或协作稿拆分 body 时，文件边界按评审可见的稳定章节职责或模型任务划分，
  不按历史起草顺序跨章混装；模块名与实际标题范围一致，唯一入口按最终阅读顺序调用；
- 拆分后逐模块执行 `03` 的章节职责审计。问题分析中的选型理由与模型章节中的公式、
  计算、结果没有同职能重复，模型求解没有承载本应前置的整段问题分析；
- 检查跨文件命令参数、环境、标签和引用未被机械截断；重新编译至引用稳定，并确认旧
  模块不再被入口、导航、日志或镜像引用。

进行术语审计前，必须由上述权威导航定位并完整读取唯一术语口径表。不得先从摘要、
符号表、正文多数用法、代码变量或历史审计归纳“规范术语”，再让唯一口径表迁就该
推断；这些载体只能用于发现和修复不一致。若项目尚未建立唯一术语源，应先形成候选
口径并由用户确认，不得在审计过程中自行把某一现有写法升级为权威。

### 0. 端到端证据链与缺陷分级审计

项目成果必须遵循并能够复核以下正向生产链：

`题意概念审计 → 题目与原始数据 → 各子问题分析 → 方法论与数学模型 → 代码实现
→ 冻结结果 → 论文汇编`

各层职责不得倒置：

- 题目与原始数据确定显式任务、评价对象和不可更改的事实；
- 题意概念审计限定现实对象、职能、量词、情景、数据能力和评价词的含义；
- 子问题分析识别现实矛盾、显式要求、隐含可执行性要求和问题间依赖；
- 方法论文档确定对象映射、变量、目标、约束、假设、算法及验证计划；
- 代码应忠实实现已经说明的方法，而不能反过来用现有代码定义方法；
- 冻结结果只能由代码从可追溯输入生成；
- 论文是评审可见的自足汇编，必须呈现理解和核验结论所需的模型、证据与边界。

老师、评审或用户只能看见论文时，存在于 `docs/`、`planning/`、源码注释、运行日志或
聊天记录中的解释均不能视为已经写入论文。这些内部材料只能作为真实性核验和论文改写
的素材，不能替代论文表达。

审计必须同时执行反向追溯：

`论文声明 → 冻结结果 → 代码实现 → 方法论文档 → 子问题分析 → 题目与原始数据`

发现疑问后，先分类再修复：

| 缺陷类别 | 判定 | 处理原则 |
|---|---|---|
| 表达缺失 | 方法、代码和结果成立，但论文没有充分呈现 | 将必要解释和证据写入论文正文或附录 |
| 实现不一致 | 代码未忠实实现方法，或同一方法在不同脚本中口径不一 | 统一方法定义，修正代码并重跑所有下游产物 |
| 建模疏漏 | 子分析或方法遗漏影响可行性、现实执行或结论的对象、目标或约束 | 回到最早出错层修模，重新求解、验证和写作 |

禁止把后两类问题仅改写成“论文表达不足”，也禁止通过降低论文结论强度掩盖仍会改变
答案的模型或实现缺陷。

#### 0.1 显式要求与隐含可执行性

审计每个子问题时，应分别列出：

1. 题目明示的决策、目标、约束和输出；
2. 从现实对象自然产生的可执行性要求，例如辖区连通、路线可达、容量、时间一致性、
   边界完整、互斥责任或守恒；
3. 方法主动加入的偏好、正则化、次级目标和简化假设。

题目未逐字写出某项现实要求，不足以证明该要求无关。也不得因现实中通常存在某项要求，
就未经证据把它提升为原题硬约束。应结合任务语义、数据粒度、领域资料和反例，判定其为：

- 必须满足的可行性条件；
- 值得加入并比较的现实性增强；
- 可定量说明影响后保留的模型边界；
- 与本题评价对象无关的范围外因素。

#### 0.2 疑似建模疏漏的影响审计

对每项疑似疏漏，不得直接写入“模型缺点”后结束。至少回答：

- 它影响的是数学可行性、现实可执行性、最优性，还是仅影响解释和展示；
- 当前最优方案是否真正违反该性质，违反范围和严重程度如何；
- 现有后处理是否真实修复该问题，还是只改变展示、没有改变原决策；
- 能否构造最小反例或独立诊断指标暴露问题；
- 加入相应约束或替代模型后，主要方案和关键指标改变多少；
- 能否通过局部调整修复，是否牺牲更高优先级目标；
- 原论文的哪些数字、图表、结论和创新声明会随之失效。

处理结论只能在证据充分后选择：

1. **必须修模**：现方案不可执行、违反题意或使主要结论失真；
2. **增强并重算**：原模型可回答题意，但增强模型显著改善现实性；
3. **保留并量化边界**：影响有限且不改变主要结论，在论文中明确适用范围；
4. **排除误报**：进一步检查证明该性质已由其他约束或后处理保证。

只检查最终方案是否“看起来合理”不合格。若新增约束可能改变答案，应实际重求解或给出
严格等价论证；若计算规模暂时阻止重求解，应明确记录为未解决风险。

#### 0.3 修复顺序与下游失效

缺陷应在最早出错层修复，并使全部下游产物失效后重新生成：

`子分析/方法修正 → 代码修正 → 独立验证 → 冻结结果更新 → 图表更新 → 论文更新
→ PDF 全文复审`

不得只修改论文使其与旧结果“表面一致”。同样，不得只修改代码而保留已经失真的方法
文档、结果文件、图片、表格、摘要或结论。

### 1. 提取所有关键数字声明

从论文逐节提取数值声明（R²、相关系数、阈值、百分比、距离、时间等）。

### 2. 逐数字追溯到冻结证据

对每个数字，定位其身份相符的来源与稳定位置，例如题面页码、外部文献、参数表、冻结
结果文件及字段路径。比较标准由数值性质、单位、声明精度、显示舍入和项目批准容差
共同决定；精确计数和精确结果必须一致，显示值则按声明的舍入规则核对，不使用统一
的 `0.01` 阈值。

### 3. 数值精度专项检查

```bash
pdftotext paper.pdf - | grep -oP '.{0,2}约.{0,10}' | grep -v "约束\|制约\|条约\|公约"
```
逐项判断数字属于精确计数、精确计算、测量、统计估计还是显示舍入。前两类不得用“约”掩盖错误；后三类应说明误差、区间或舍入规则。文本扫描只能发现候选位置，不能代替语义判断。

### 4. 常见审计发现

| 类型 | 示例 | 严重性 |
|------|------|--------|
| 手估值错误 | "最大出警时间约5分钟" 实际4.2分钟 | 致命 |
| 虚构数字 | 论文数字无法回到与其身份相符的权威证据源 | 致命 |
| 未冻结数字 | stdout-only 入了文档 | 严重 |
| 精度语义错误 | 将测量估计伪装成精确值，或用“约”掩盖抄录错误 | 严重 |
| 模糊词掩盖错误 | 将精确计数 18 写成“约20” | 致命 |
| 方程序号混乱 | 编号不连续 | 严重 |

### 5. 文风审计

- 方程序号与计量表达不冲突
- 无口语/非正式用语
- 摘要与题目各项独立任务逐项映射，每项具有与原题标识一致的加粗入口；多问题且原题
  采用“问题一、第（1）小问”等编号时，极其推荐使用加粗的“针对问题一，”“针对
  问题一第（1）小问，”等直接映射形式。检查入口没有虚构层级、合并独立任务或加粗
  后续整段；原题采用其他任务结构时，不把该中文题号句式作为失败条件
- 长段落需拆分

### 6. 摘要专项审计

- 覆盖题目原文的全部问题与小问，不能依据文件夹名、旧代码或既有草稿缩减范围；
- 摘要—正文—结果双向追踪不得指定某一处为孤立基准。逐项比较题意与已确认任务、
  方法定义、公式、代码、冻结结果、图表、正文、摘要和结论；若不一致，先判定最早的
  无证据或错误层，再从该层修正并使全部下游重新接受审计。禁止只让摘要迁就正文、
  只让正文迁就结果文件，或按出现次数决定正确口径；
- 对任何已接受的修改执行“一修全修”：搜索术语全称、简称、同义表达、关联数字和
  条件在全项目的全部出现位置，同步检查摘要、正文首次定义、公式解释、表头图注、
  结果讨论、结论、声明映射、当前审计、复现文档与交付副本。只有全部相关位置一致且
  证据链重新闭合，问题才可标记为已修复；
- 先列正文候选工作并按 A/B/C 三级分类：A 级全部进入摘要，B 级按其对结论理解的
  增益选择，C 级回到正文；不得把完成成本或算法名称当成进入摘要的理由；
- A/B/C 是否按最小信息单元而非整句或整段分类；被移回正文的检验主张所附带的
  证明边界是否同步移回，保留的边界是否紧邻其限定对象；
- 合理性评价、问题诊断或方案比较的核心指标、比较基准和判断规则是否作为 A 级保留，
  而不是只剩“评价现状”“进行分析”等抽象动作；
- 每问先给出规范的分析方法或模型名称，再解释其具体动作与核心结果；
- 不能只列模型名称，也不能为了降低术语密度而完全隐去技术路线；
- 一个小问列出多个模型时，是否分别说明各模型的本题职能，并按“模型及作用—结果—
  决策含义”重排整段，而非把模型名机械插入原有句子；
- 跨小问沿用多级目标时，是否保留会改变方案排序的顺序差异，并删除前文已经解释过的
  完整目标清单；
- 正文存在有证据的结构性亮点时，摘要应说明其解决的具体缺陷；不存在足够证据时，
  不按数量制造亮点或自称创新；
- 首次出现的术语可由本句或邻近上文直接理解，避免连续名词化表达；
- 摘要与关键词之间有一行视觉留白；
- 编译后逐页检查：关键词留在摘要页，正文从下一页开始；
- 将摘要单独交给不了解正文的读者时，仍能复述每问工作、核心结果与主要贡献；
- 每个模型、检验和边界句是否至少交代对象、动作与结论；是否存在“复核最优值”
  “验证可靠”等读者无法知道复核对象、反例和意义的悬空表达；
- 每问是否依次交代“模型与问题—关键动作—核心结果—必要边界”；检验或灵敏度只有
  达到 A/B 级准入标准且能自足解释时才进入摘要；
- 按 `03-paper-content-rules.md` 的“摘要数据—结论闭环”将关键数字组成结论数据组；
  每组是否在同句或紧邻下一句说明数据身份、比较或阈值关系、支持的实质判断及其对
  题目回答的作用；是否存在只报最优值、改善量、资源数或临界值而不解释其含义的
  数字清单；
- 对摘要及正文首次出现的关键概念、字段和指标执行“现实锚定门”：是否同时说明现实
  载体、数学口径、决策含义和不可外推边界；遮去术语、公式和数字后，读者能否复述
  谁在什么条件下发生何种变化及其管理后果；
- 是否因追求高度凝练而删掉了 A 级约束、目标逻辑、核心结果或成立条件；C 级实现
  步骤与重复检验不受“必须进入摘要”保护。
- 开头句是否直接、具体地说明研究对象和工作主线，避免空泛背景、长定语与模板化判断；
- 正文认定的主要结构性亮点是否在摘要中清晰出现，并能在正文找到同名机制和证据。
- “覆盖所有小问”与“覆盖全部 A 级关键工作”分别检查；五个题号齐全不能替代内容
  准入和双向映射检查。
- 逐问建立“摘要术语—正文首次定义—数学表达—结果证据”映射；摘要中的每个术语在
  对应小问正文均有白话机制和规范定义，不能只列五级目标而不解释“词典序”的含义；
- 双向映射中的任一空项或冲突都必须沿证据链定位原因；补齐一格后重新检查同一声明
  的全部入链与出链，不能把映射表自身当作高于题意、方法、代码或冻结结果的权威；
- 除题号、数学表达、文献引用和必要缩写外，括号是否已最小化；括号中的完整条件、
  结论和分面说明是否已改写成正常句子。
- 出现关键词跨页或摘要过密时，是否只标记 C 级内容、局部诊断、次要数字和重复验证
  为候选删减项，并提交用户确认；不得自动删改，也不得以压缩版式换取容量。
- 每轮获准删减后是否脱离旧上下文重新执行语义闭合检查：所有评价、分析、优化、验证、
  诊断和比较是否仍有对象与判据，每个原因判断是否仍保留评价口径或对照关系。

### 6.1 评审可理解性专项审计

该检查面向只阅读最终论文、看不到内部文档和代码的评审。逐项确认：

- 审计问题分析时执行 `03-paper-content-rules.md` 的“逐句人工审计程序”，先检查当前
  句及邻近上文，再查看后文正式展开以核对重复、错位和口径冲突；不得用后文解释判定
  当前概念无需解释，也不得孤立摘句判错；
- 审计基本假设时执行 `03-paper-content-rules.md` 的“基本假设逐项审计程序”，把题面
  事实、数据缺口假设、指标定义、模型约束、章节安排和适用边界拆开判定，并追踪每条
  保留假设的下游用途；
- 基本假设是否使用模板允许的黑体选择性突出核心条件及必要的关键边界；只读黑体能否
  形成成立条件清单，且没有把依据、套语、编号或整条长句一并加粗；各条强调粒度是否
  一致，并已在最终 PDF 中检查实际字重与换行；
- 对问题分析、基本假设、模型建立、检验和结论中的重复概念，执行
  `03-paper-content-rules.md` 的“相邻章节职责与必要复现”：按句子功能而非词面重复
  判定，保留维持局部推理所需的最短提示，删除相邻章节同职能的逐字复述；
- 问题分析首段解释了大问与小问的划分依据、继承关系和递进逻辑；
- 每个子问题说明其问题类别、常见方法族、关键差异和本文选型依据；
- 逐小问建立“问题分析外部主张—引用—支持内容”矩阵；现实领域概括、问题类别、
  常见方法、评价维度及方法优缺点是否在首次出现处由直接相关来源就近支撑；是否存在
  某小问完全依赖另一小问、后文或参考文献表补足引用的情况；
- 题面事实、附件数据和本文独立推理是否避免无意义引用；每条引用是否真正支持其邻近
  主张，而不是段末统一挂载、只因主题相近或为满足篇数而添加；
- 任一术语首次出现时均有不依赖该术语本身的白话解释；
- 对正文首次实质使用执行就地解释门：只考察读者读到当前位置时能够获得的信息。
  后文定义不能倒推补足前文；只有当前句或紧邻上文已经说明对象、动作和判据，后文
  仅负责形式化时才算通过；
- 技术术语遵循“先说明两类对象、操作步骤和判定标准，再给术语名称”的顺序；不得
  用“二分图匹配、单商品流、反事实、连续松弛”等名称代替机制说明；
- 反向检查是否因追求通俗而删除了必要的标准术语；模型类别、核心算法、关键约束和
  独立检验方法必须同时具有规范名称与白话机制，二者缺一不可；
- 不存在只写“某条件的存在性”“方案有效性”等、却未说明判断对象和条件的抽象句；
- 同一模型、目标和算法步骤在摘要、问题分析、模型建立、求解与结论中名称一致；
- 被宣称为亮点的结构在正文中具有醒目的完整解释，而非散落在公式或步骤里；
- 多级目标的名称与先后顺序逐项对应，逐级固定过程可由正文独立复述；
- 每个容差、安全余量或近似量说明了来源、方向、数值尺度、作用及敏感性；
- 每个权重说明了对象间是否不同、来源、量纲、归一化方式、优化作用和现实意义；
- 当抽象机制难以由定义、公式和直接结果理解，或作用主张需要独立证据时，检查是否
  配有真实小实例、阶段对比、边界情景或消融结果；已经清楚闭合时不机械配例；
- 具体案例能够区分整体模型的作用与某一新增目标或约束的边际作用；
- 摘要第一句和各问题总括段通过“对象—动作—条件—结果”检查，不是通用套话。

发现评审“看不懂”时，不能默认是读者缺乏背景。先检查是否存在术语未定义、名称漂移、
因果链缺失、例子缺失或模型尚未真正理解；只有模型与代码经复审成立后，才归为纯表达
问题。

### 6.2 摘要缺陷的全文迁移审计

完成摘要专项审计后，建立“摘要暴露缺陷—可复用规则—正文候选位置—实质影响”表，
把摘要中发现的对象、动作、指标、条件、基线、数值身份、概念层级和证明强度问题
反查到问题分析、假设、模型建立、求解、结果、图表、检验、评价与结论。逐项判断：

1. 同类表达在正文中是否会使读者误认主体、评价对象、比较基准或适用情景；
2. 关键术语是否只在摘要修清，而正文首次定义、公式解释或表头仍保留旧口径；
3. 结果数字是否缺少基线、成立条件、最优性身份或边界含义；
4. 不同决策前提下的数字是否被放在同一层级比较或相减；
5. 修正是否需要沿证据链回到方法、代码或冻结结果，而非仅改文字。

只记录具有语义或证据影响的缺陷，不把“可以写得更详细”自动判为问题。若指代对象
在邻近上文中唯一、简称已在此前定义、条件在当前段落持续有效，则允许正常回指和省略。
审计阶段先形成问题清单并按“表达缺失、实现不一致、建模疏漏”分类；未经用户确认，
不得把可选风格改写混入实质修复。

实时编译是诊断步骤，不产生新的修改授权。若摘要超过一页、正文超过规定页数，或发生
关键词跨页、标题/句子孤悬、图表漂移、大块留白等冲突，先报告现象、位置和原因。
仅可在不降低可读性、不改变图像内容与视觉语义时先行调整图像显示尺寸；压缩、删除、
合并或改写文字，以及调整字号、字体、行距、字距、页边距、段落/标题间距、分页、
图表顺序或浮动参数，均须作为独立方案提交用户确认后实施。不得把恢复旧页数视为
默认目标。

### 7. 修复流程

发现错误 → 修正生产过程并冻结适合结构的证据产物 → 重跑 → 更新论文 → 编译 → 重审

### 8. 图像与表格三组审计

不能以 PDF 成功编译、图片达到 600 dpi、表格数值可复制或无 overfull 警告代替
审计。先审全稿完整性与载体选择，再对逐幅图、逐张表填写内容和质量结论；任一组失败
则图表体系未通过。

#### 8.0 完整性与载体选择

- 从原题任务矩阵、声明台账、模型结构、主要方案与结论反向列出应被评审直接看见的
  空间关系、路径、趋势、分布、阈值、权衡、完整清单和精确对照；
- 检查是否缺少必要图像、必要表格，或关键信息只存在于内部文件、代码、公式和长段
  正文中；
- 逐项判断正文、公式、表格和图像哪种载体最适合：精确查询与完整清单优先表格，
  空间/路径/趋势/分布/阈值/权衡优先图像，简单单值结论优先正文；
- 专门查找“已有表格但图像更合适”“已有图像但表格更合适”以及图表完整重复三类
  错配，记录保留、替换、补充或删除的理由；
- 不按小问或模型机械凑图表数量。决定不补图表时，也要确认关键关系能够被当前载体
  快速理解和核查。

#### 8.1 内容与证据功能

- 记录图表编号、所回答任务、支持声明、数据来源、生成方式和正文引用位置；
- 从冻结结果复核对象集合、数值、单位、筛选、排序、舍入、合计、阈值、基准和方案
  版本，检查漏项、错配、重复、过期数据和手工抄数；
- 逐项解释图形编码或表格字段，检查标题、图注/表注与正文的对象、情景、条件和例外
  是否一致；
- 将正文结论反查到图表中可观察的证据，不允许由局部案例、相关关系或单一情景推出
  无条件整体结论；
- 对图、表和相邻正文执行双向删除检验，确认各自具有不可替代的信息职责。

#### 8.2 呈现与技术质量

- 单独检查图像清晰度、比例、裁切、标签碰撞、图例遮挡、线点覆盖、颜色语义、坐标
  和单位；
- 检查表格列宽、对齐、小数位、换行、单位、表注、分页与信息密度，排除越界、截断、
  跨页断裂和难以追踪的行列；
- 将最终PDF含图表页面渲染为图像，按论文实际尺寸检查最小文字、细线和表格内容；
- 检查编号、交叉引用和浮动顺序；逐项确认首次实质引用、图表及其后就地解释形成连续
  局部闭环，中间没有无关标题、其他图表或论证；同时检查整页压迫、大块空白、孤行
  与孤题；
- 进行灰度、低对比和普通打印退化检查；颜色必须有形状、线型、明度或标签冗余；
- 修复后重新生成图表、重新编译，并再次检查受影响页面和相邻页面。

### 9. 标题层级审计

- 先列出模型建立的实际步骤及并列、从属、依赖关系，再核对标题是否忠实表达该逻辑；
- 多任务论文中的每项任务是否有醒目、无歧义且与原题一致的标题入口；隐藏正文后能否
  快速找到各项任务、主要模型、关键结果和检验，单一任务或短论文是否避免机械增设
  “问题一”；
- 是否建立“摘要亮点—正文标题—公式、结果或检验证据”映射；摘要中的主要模型、
  机制、约束、证明、反事实或诊断能否通过标题快速定位，名称是否一致；
- 对确有独特机制、现实约束、证明、反事实、阈值、权衡或诊断的章节，子标题是否
  选择性展示了这一信息；只读二至四级标题能否识别论文的少量核心亮点，而不是只见
  “模型建立—模型求解—结果分析”等通用流程；
- 标题中的亮点是否能由本节正文、公式、结果或检验直接支持；是否避免无证据的
  “创新、先进、显著、最优”等自评、结果数字堆叠和算法名清单；
- 普通组织性标题是否在没有独特信息时正常保留；是否避免为亮点展示而机械改写全部
  标题、增加空层级或拆断完整推理；
- 模型建立、求解、结果解释、检验和必要小结等内容职能是否得到覆盖；不得因未采用
  五个同名三级标题而判错，也不得以标题形式自由为由遗漏内容；
- 相邻标题只触发层级必要性检查，不自动判错：纯归类的上级标题可直接接第一个子标题；
  若上级标题只有一个子项、连续嵌套多级标题或层级不表达新的并列/从属关系，则合并、
  降级或删除，不得为隔开标题补写空洞报幕段；
- 每个真正展开内容的问题标题后有模型总括段，“模型求解”前已说明完整模型的输入、
  决策、目标和输出；
- 先读取指定模板，不根据个人审美猜测标题字号；
- 对照正文基准字号检查一级至四级标题；
- 指定模板要求二至四级标题同为小四时，不得把三级、四级缩为五号；
- 同字号层级使用黑体、编号、段前后间距和缩进区分；
- 黑体可以增强醒目度，但不能抵消违反模板字号的事实。

### 10. 公式与数理—代码一致性审计

- 审计新增约束前，先检查目标性质是否已由基准规则、变量定义或其他约束自然推出；
  分别说明在基准模型与放宽后的优化模型中是否成立，不把“可能失效”误写成“基础
  约束必然导致失效”；
- 需要证明约束必要性时执行单因素受控反事实：固定数据、基本约束、目标定义与顺序、
  容差，只切换该约束并重新求解；随后用不同于求解器声明的独立方法检查目标性质，
  冻结改变条件、保持条件、违反对象及局部成因；
- 每个独立公式或同职能公式组都有就近的目的或对象说明，以及作用、现实含义或结论
  落点；同职能公式组可以共享解释，不按 LaTeX 环境、编号或换行数量机械逐式判定；
  承担不同职能、改变对象、引入新现实规则或支撑不同结论的相邻公式已分别解释；
- 已知量、未知量、参数、单位、取值和来源在首次使用附近可找到；
- 每个关键公式均从原始指标或现实关系逐步化到可计算形式，决定指标含义、现实对象、
  约束作用、等价性和求解形式的中间关系均已展示；已知常量、集合规模和统计总量来源
  可定位，只有代入有助于理解来源、检查单位与数量级、判断等价性或复核关键结果时才
  在正文展开。简单算术、重复代入、参数表已唯一界定的数值替换及大规模矩阵或清单的
  机械展开可以省略；省略决定数学含义或等价性的关系判为推导链缺失，未逐项展示机械
  代入本身不判错；
- 决策变量的定义域、目标顺序、关键约束、容差方向和并列方案处理与真实代码一致；
- 对多级目标逐级核对“规范名称—原始数学量—辅助变量求解式—结果表述”；区分优化
  指标与评价指标，禁止因改写而用同义词替换成另一个统计量；
- 最大值上界化、绝对值线性化等变形按“现实量—原始指标—辅助变量关系—求解式—
  最优处等价理由”检查，辅助符号不得先于定义出现；
- 情景分析明确区分“固定原方案后代入新参数”和“参数变化后重新优化”；
- 参数变化的解释执行 `03-paper-content-rules.md` 的“参数变化与方案切换的解释”：
  区分不变的候选集合与变化的瓶颈或最优决策，比较代表情景的完整重优化结果，并用
  旧方案反事实说明直接参数效应和耦合重分配效应；
- 论文只描述代码实施的数学逻辑，不以库名、接口、命令、路径或运行状态代替推导；
- 重新计算、局部不可删、同值复核、上下界闭合和全局最优分别按其实际证明能力表述。

### 10.1 解释充分性审计

逐模型遮去模型名、算法名和结果数字，检查剩余文字能否回答：

- 现实矛盾是什么，为什么简单直觉方案不足；
- 为什么当前模型结构适合，关键替代方案为什么不采用；
- 现实对象怎样映射为变量，变量之间怎样联动；
- 每组关键约束违反后会产生什么错误方案；
- 目标函数怎样推动方案变化，多目标怎样限制彼此；
- 全部公式合起来如何从输入生成输出；
- 结果为什么形成，改善、代价和未解决问题分别是什么。

只出现“采用某模型”“通过某方法求解”“得到某结果”的段落判为不合格。增加字数若
没有补充上述因果链，同样判为不合格。

对辅助约束另做篇幅删除检验：正文至少保留现实理由、性质为何不再自动成立、必要的
事实证据和约束作用；若删除某句后这四项仍完整，则该句不应因“显得严谨”而保留。
受控反事实的实现细节和完整局部编号应留在可复现材料，只有承担正文论证时才进入论文。

### 10.1.1 逐段逻辑闭环检查

对正在人工审计的段落建立“句子—主要职能—直接上文—判断依据—新增信息—处理动作”
六列表，并逐项确认：

- 题面事实、模型选择、定义、约束、目标、求解和检验没有互相代替或错误归因；
- 每个“因此、导致、等价、最优”附近都有足以推出它的原因，而不只是话题相关；
- 固定决策下的数学等价与在全部可行决策中的优化已经分层说明；
- 删除或放宽某个关系时，只陈述该关系消失后能够证明的后果；
- “最优值、最坏对象、该指标、与前文相同”等表达具有唯一、邻近的先行对象；
- 相邻同职能重复通过删除检验，跨节必要回指只保留闭合当前推理的最小信息；
- 用户提出疑问、压缩建议或比较请求时，先提交具体方案；只有明确确认后才修改正文。

完成一组逐句修改后，必须对修改后的整段重新执行六列表检查，不能把各次局部通过直接
视为整段通过。特别区分：

- 组合枚举或界证明提供的不可能性、数量下界或穷尽性；
- 完整模型提供的全约束可行性与多目标最优性；
- 独立复算提供的数值一致性；
- 固定方案扰动与参数变化后重新优化各自支持的敏感性结论。

一种证据不得越权替代另一种证据。若整段复审发现累积重复或证明对象混杂，应重新提交
整体改写方案并再次确认。

若问题只是正常回指或可选文风，不得升级为实质错误；若问题暴露目标、约束或代码口径
不一致，则沿证据链回到最早出错层，不能只润色当前句。

### 10.2 常量、情景参数与计算结果审计

程序中的数字必须按来源区分，不能把所有数字一概视为“硬编码”，也不能因运行结果
暂时稳定就把派生结果写回源码。

- 题设给定或经论文明确补充的场景常量可以写入程序，但应使用有语义的集中命名，并
  在输出中保存其取值，例如报警延迟、警车速度和案发节点；
- 灵敏度范围、步长、展示精度和安全余量属于分析设计参数，应集中配置并说明选择
  目的，不能散落为无法辨认的裸数字；
- 临界速度、最优值、瓶颈节点和推荐方案属于计算结果，必须由输入和模型实时求得，
  禁止把上一次运行得到的数值直接作为下一次运行的输入；
- 若展示情景依赖计算结果，例如“临界值后的第一个整十速度”，应先求临界值，再由
  明确的取整规则自动生成展示点；
- 审计时搜索论文关键结果在源码中的字面出现位置；除测试期望值或带来源说明的回归
  基准外，派生数值出现在求解逻辑中应判为严重问题。

### 10.3 离散决策对象与连续现实对象审计

- 明确决策变量究竟覆盖节点、道路、区域、时段还是个体，禁止把节点集合未经说明
  直接称为完整连续辖区；
- 若原始数据和目标只定义在离散对象上，应说明离散化的适用范围，以及未直接建模的
  连续对象是否需要后处理；
- 后处理规则必须说明输入、比较准则、边界条件、无交点或多交点情形，并区分其是否
  会反向改变原优化变量和目标值；
- 若论文给出连续分界公式，真实程序也应生成对应区间，并检验区间无遗漏、无重叠、
  责任主体合法和边界条件成立；
- 图中用连线表示节点归属时，图注不得把这些连线误称为实际地理边界。

### 11. 图表回应审计

- 每幅关键图表在正文中明确回答了哪个题目关切；
- 解读覆盖“图表关系—可见现象—推导结论—决策作用（可选）”；
- 结论来自图中可观察证据，不只复述图题、图例或数据表；
- 检验图说明扰动机制、是否重新优化以及结论在哪个区间内成立。

### 11.1 图表信息增量审计

图和表不能仅因载体不同就被视为互补。同一组数据若在表中完整列出、又在图中逐项
重画，而两者导出的判断相同，应判为信息重复。

逐组执行双向删除检验：

- 删除表格后，图像是否仍能回答全部精确结果或方案明细；
- 删除图像后，表格是否仍能揭示全部空间结构、趋势、阈值、异常或机制；
- 若两个答案都是“能”，判定存在载体重复，并提出删除其中一个或重构信息职责的
  候选方案；是否实施服从当前阶段授权；
- 若同时保留，正文须明确表格提供的精确查询信息和图像新增的空间、趋势或机制信息。

优先分工为：完整清单、精确方案和多指标查询用表格；空间关系、路线、趋势、阈值、
拐点和权衡用图像。图中已经标注全部少量数据点时，通常不再另设同数据表格。

### 11.2 逐问主证据链审计

按 `03-paper-content-rules.md` 的“逐问主证据链收束”逐问建立映射，并检查：

- 每个题目主张是否有唯一、可定位的主证据和紧邻的直接回答；
- 每项保留的次要统计量、图表或稳健性检验是否检查了不同于主证据的实质风险；
- 是否存在多个指标只重复方向、多个载体完整重画同一信息，或按程序产物顺序堆叠正文；
- 降级到后台的诊断是否仍有生产者、结构化结果、复算路径和明确用途；
- 精简后是否仍保留关键例外、模型可复推所需定义、结论成立条件和禁止外推边界。

若删除任一次要证据后题目答案、失败风险判断和复现能力均不受影响，则将其列为正文
降级候选；当前阶段有明确修订授权时实施，否则只记录。不得把“计算成本高”“名称
专业”或“已经做过”作为正文保留依据。

### 12. 全文连贯性审读

全文定稿前必须脱离代码和章节清单，从摘要到结论连续阅读一遍。审读目标不是只找
病句，而是检查读者能否沿着“题目关切—现实矛盾—模型选择—变量联动—求解判断—
结果证据—决策含义”的路径自然前进。

- 每段只承担一个主要功能；段首说明本段为什么出现，段末交代结论或引出下一步；
- 相邻问题之间用正文说明评价口径如何继承、研究尺度如何变化，不能依赖标题硬切换；
- 模型名首次出现时同时解释它解决的矛盾，以及简单直觉方案为什么不够；
- 代词、简称和“该方案”“这一结果”等指代必须能在邻近上文中找到唯一先行对象；
- 同一事实若已由图、表或问题结论完整表达，小结不再复述数字，而承担阶段归纳和
  下文过渡；
- 连续两段若删除任一段都不影响推理，应合并或删除重复段；
- 政策建议必须对应真实求解过的情景；“从零重构”“固定数量搬迁”和“保留原址
  增量建设”的数字不得互相替代；
- 逐句检查主语、条件、比较基准和结论强度，尤其避免把软目标写成硬约束、把局部
  检验写成全局证明、把模型输出写成现实必然。

最终采用“遮标题复述检验”：暂时忽略标题，只读各段首尾句，若仍能复述每问为何
建模、怎样推进、由什么证据得到何种结论，才视为文章主线连贯。

### 12.1 逐句语言审校

内容与结构稳定后，再从摘要到结论连续执行一轮语言审校。该轮不以机械缩短句子为
目标，而以“准确、无歧义、容易一次读懂”为标准。

审校前读取 `13-excellent-paper-expression.md`。常态语言审校先判断各段主要职责，再
检查句子的功能、对象和上下文连接是否可辨，不机械生成逐句标签。段落过长或功能混杂，
多个模型、对象或条件导致指代不清，因果、比较或证据关系难以辨认，文本属于摘要、
核心模型解释、关键结果或结论等高风险位置，或者用户明确要求深度逐句审校时，才为
相关句子标注“来意、定义、动作、理由、证据、落点”之一或相邻两项。无法归类只触发
进一步检查，不自动要求删除；确认没有信息职能、删除后不损害推理或只模仿论文腔的
句子，才判为删除或重写候选。只读审计阶段记录证据与方案，已授权修订阶段才实施。
参考优秀论文时同时记录“吸收点”和“拒绝点”，禁止以获奖身份替代独立判断。

- 执行 `13-excellent-paper-expression.md` 的“逐句因果闭合检查”，为分类、等价、
  上下界、分支排除、最优性、改善原因、稳健性和适用性等判断定位同句或紧邻前句的
  真实理由；先解释本题机制再给规范术语，并把证明范围紧邻结论；
- 句子的语法主语应与当前讨论对象一致，避免出现“方向早于警方失守”“平台有节点
  无法到达”等主客体错位；
- “因此、由此、说明、证明、导致”等连接词只在前句确实支持后句时使用，并检查
  结论强度是否超过证据；
- 优先使用含义确定的动词，如“降低、固定、覆盖、重新求解”，少用“压低、摆放、
  触及、换取”等可能口语化或隐含错误交换关系的词；
- 同一指标全文使用同一名称，如“发案率覆盖比例、最大响应时间、负荷变异系数”，
  不在相邻章节随意改称；
- 技术名称必须与变量类型和真实计算一致，例如同时含连续变量与整数变量的模型不能
  简称为“0--1线性优化”；
- 代词“其、该、这一”在邻近上文中必须只有一个合理先行对象；若存在两个候选对象，
  直接重复名词；
- 长句按“条件—动作—结果”拆分，但不能删掉选模理由、约束作用和适用边界；
- 对重复说明先判断章节距离和当前职能：紧邻同职能内容可删除，跨节且承担当前公式或
  结论入口时保留最短回指；删除后不得遗留孤悬句、无先行对象或突兀公式；
- 公式展开遵循 `03-paper-content-rules.md` 的“公式展开尺度审计”：补齐决定指标含义、
  等价变形和阶段继承的关系，不重复已定义集合、简单换算和大规模机械代入；
- 图表解读继续保持“关系—现象—结论—作用”，避免为了句式整齐而写出图中不可见的
  因果关系；
- 敏感性结果中的区间、分位数和情景数值必须说明其比较基准或相对变化，并紧邻说明
  这些数字支持什么判断；离散情景不得扩写为连续区间结论，探索性扰动不得包装成
  未经题目或数据支持的真实运行条件；
- 完成修改后重新编译，检查新增换行是否造成摘要跨页、关键词落单、标题孤行或图表
  漂移。

### 12.2 页面留白与浮动体定点审计

“图表没有跨节”并不等于页面合格。最终 PDF 还要逐页检查异常大块留白，尤其关注
表格之后、图像之前、`\FloatBarrier` 前后和使用 `[H]` 的页面。

发现半页级留白时按以下顺序处理：

1. 检查后续图表的实际高度、浮动参数和屏障是否把图及其分析整体推到下一页；
2. 只有图像缩放后仍能辨认节点、路线、图例、坐标、数字和标注时，才可先行调整其
   论文显示尺寸；
3. 不得裁剪或改变图像内容，不得为了填页把无关文字移入、重复结论或把图缩到失去
   信息表达能力；
4. 修正后同时渲染该页与前后页，检查是否造成标题/句子孤悬、新空白或解释分离；
5. 调整内容职责与顺序、移动解释段、改变浮动参数或采用其他版面方案，必须先提交
   用户确认。
