# 合格 Skill 的验收标准

合格 Skill 不是“写得很严”，而是能让错误路径难以被解释、难以被伪造，并能在复发时
明确暴露。V5 按以下标准验收。

1. **触发明确**：description 与入口能判断何时启用，恢复、审计、修改和交付不会混淆。
2. **权威明确**：阶段与权限只有一个控制器；详细模块可以交叉核验，但触发路由与冲突
   优先级必须唯一，历史材料不能反向授权。
3. **状态可判定**：状态枚举、进入条件、退出证据、允许动作和禁止动作均可检查，不用
   “基本完成”“已大致阅读”等自由文本代替。
4. **证据结构化**：关键门禁具有固定字段、身份、数量、哈希和范围；摘要、旧回执与
   自我声明不代替原始证据。
5. **验证覆盖语义**：验证器检查字段之间和字段与当前文件系统之间的关系，不只搜索
   关键词或检查文件存在。
6. **失败路径有回归**：每次真实失误都转成最小负面用例；规则、结构、验证器和测试
   四层缺一不可。
7. **权限不能旁路**：用户授权、阶段许可、前置证据和人工决定必须同时满足；“继续”、
   沉默、成功运行、外部范例和 AI 建议不能扩大权限。
8. **最早错误层回退**：不能用论文措辞掩盖题意、数据、模型或实现缺陷；变更传播到
   所有直接与传递消费者。
9. **诚实声明边界**：自动化能证明清单、哈希和记录覆盖，不能证明私有认知或实际理解；
   Skill 必须明确自动化不能证明什么。
10. **可执行且不过载**：入口保持简洁，细节按职责路由；高风险步骤使用确定性脚本，
    但脚本通过不替代实质审查。
11. **迁移可追溯**：旧义务的保留、合并、替换和删除均有来源与去向；只有通过负面测试
    的覆盖才能在迁移台账中标为已恢复。
12. **前向验证**：结构校验、语法检查、正例、负例和真实接口调用均通过后，才称 Skill
    可用；局部测试不能宣称整个工作流有效。
13. **精确验收层**：旧版精简规则若承担独立验收职责，优先按哈希保留为活动验收层；
    只有逐义务映射和对应负面回归同时存在时，才允许改用语义压缩。详细操作规则与精简
    验收规则重叠时必须同时满足，不得互相降级。

判断一个约束能否被直接绕过时，依次问：它是否只有自然语言、是否没有结构字段、是否
没有验证器、是否没有失败回归、是否依赖执行者自觉。任一答案为“是”，都只能算软约束；
涉及权限、恢复、证据和正式交付时，软约束不能单独构成门禁。
