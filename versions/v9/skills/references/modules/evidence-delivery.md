# 08 — 文献调研方法

> 来源：Hermes skill `mathmodel/literature-search`

---

## 职责与强度

本文件设计检索轮次、来源纳入、阅读状态和证据记录。引用位置归 `03`，真实性与位阶归
`12`。不伪造、区分阅读状态、保存原始链接和支撑主张为 A/B；平台、语言、类型、记录
载体和评分方式为 C/D。

## 搜索策略

### 逐问文献导向门

多问题项目完成共享题意和数据底座后，每个问题在提出正式基线、候选模型或现实解释前，
先判断是否触发本问文献调查。以下任一情形触发：

- 团队不熟悉题目的物理、化学、生物、经济、工程、制度或业务背景；
- 数据包含仅凭题面无法解释其作用的辅助变量、中间产物或代理指标；
- 需要用机理、现实过程或领域惯例解释相关、趋势、异常和边界；
- 需要识别公认问题类别、主要方法族或可靠的验证方式；
- 参数、阈值、扰动范围、评价指标或适用边界需要外部依据；
- 论文的问题背景、问题分析或选模理由将使用“通常、已有研究、机理表明”等外部主张。

触发后，本问的最小顺序为：

`题意与数据事实 → 领域背景/机理语义轮 → 方法谱系选模轮 → 文献启发与边界
→ 基线 → 候选方法 → 人工决定`

不得先凭常识固定模型，再只寻找支持既定选择的文献。已经形成的文献前候选可作为检索
关键词来源，但必须标记为初步想法，并在调查后允许新增、修改或淘汰。

若没有触发文献调查，也要记录理由，例如任务完全由题面定义、只需确定性枚举且不使用
外部主张。不能用“时间紧”“已经有代码”或“AI知道相关知识”作为跳过理由。

### 来源选择

根据领域、证据类型、可访问性和官方要求选择数据库与机构网站。中文和英文检索用于
扩大证据覆盖，不是每次检索的固定双语步骤；标准、法规、赛事规则、教材、数据说明、
原始论文、综述、期刊、会议和学位论文分别承担不同证据职责。Crossref、arXiv、知网、
万方或通用搜索引擎只是候选入口，不形成固定顺序。

搜索不是只发生在“选模型之前”的一次性阶段。按问题推进四轮定向检索：

1. 语义轮：核查题目实体、制度职能、指标含义和系统边界；
2. 选模轮：识别主要方法族、适用条件和替代方案；
3. 规格轮：核查假设、参数区间、评价指标、基线和验证设计；
4. 边界轮：核查结果能否推广、现实中遗漏了哪些机制。

每轮只收集会改变任务解释、模型规格、验证或论文主张的来源。新问题暴露新概念时允许
回到检索，不得把 EVIDENCE 误解成一次完成后永久关闭。

### 关键词构造

按“研究对象 + 数学结构 + 目标/约束 + 场景同义词”组合中英文关键词。例如设施选址类可组合 `facility location`、`covering`、`p-center`、`equity`、`emergency response`；统计类应加入响应变量、数据类型和检验方法。关键词属于项目规划，不在通用 skill 固定某道题名。

### 搜索纳入标准

1. 日期范围：经典定义追溯原始或权威来源，时效性主张覆盖当前进展；
2. 语言：按对象、证据覆盖和官方要求选择，不设双语配额；
3. 类型：纳入与主张身份相符的原始论文、综述、期刊、会议、学位论文、教材、标准、
   官方规则和数据说明；
4. 主题：由题意概念、数学结构、目标、约束和验证风险生成关键词，不预设项目方法族。

---

## 显性记录规范

聊天记录和搜索结果页不能作为项目证据。每篇文献至少同步写入：

- `references/README.md`：人可读、可点击的总表；
- `references/literature.json`：机器可读元数据；
- `references/references.bib`：论文引用条目；
- `references/notes/<id>.md`：支撑主张、适用边界、阅读状态和页码；
- `references/refs/`：仅保存合法取得的全文。

```markdown
| ID | 标题 | 作者 | 年份 | DOI | 原始URL | 访问日期 | 本地文件 | 阅读状态 | 支撑主张 |
|----|------|------|------|-----|---------|---------|---------|---------|---------|
| ... | ... | ... | ... | ... | ... | YYYY-MM-DD | refs/... | 全文/摘要/待核验 | ... |
```

优先记录 DOI 和出版社/机构原始页面，不记录搜索结果 URL。`literature.json` 还应保存来源类型、落点章节、开放获取许可、本地文件 SHA-256；只有摘要可读时不得声称已阅读全文。

每个触发调查的问题还应形成一份人可审阅的文献导向稿，可写入
`planning/analysis/YYYY-MM-DD_<task>_literature_orientation.md`，至少包含：

1. 本问需要外部证据回答的具体问题；
2. 领域背景、变量或中间产物的现实作用及候选机理；
3. 主要方法族、适用条件、局限和与本题数据结构的匹配；
4. 文献给数据分析、派生指标、图表、模型和验证带来的具体启发；
5. 本题证据与文献机理相容、矛盾或无法区分之处；
6. 可进入论文的问题背景与问题分析主张；
7. 禁止照搬的其他体系结论和仍未解决的问题；
8. “外部主张—来源—来源等级—阅读状态—支持范围”矩阵。

该导向稿是人工讨论材料，不因写入文件自动成为模型权威。

### 证据质量

官方规则和标准用于合规主张；原始论文用于算法来源；综述用于领域脉络；教材用于基础定义。往届答案、营销教程和 AI 生成材料只能启发方法，不能作为事实或最优性依据。

---

## 产出

`planning/inspiration.md`：

- 候选方法数量由问题结构决定，不为凑数设下限
- 每个方法附：核心思想、适用条件、限制、证据来源和比较理由
- 可按可行性、题意贴合、证明能力、计算成本、数据要求和文献支撑比较；是否量化、
  使用何种量表和聚合方式取决于决策需要，不固定为 1–5 分或乘积排序

## 完成门

触发文献调查的问题只有同时满足以下条件，才可进入正式基线和候选模型决定：

1. 关键外部主张能够回到原始论文、权威综述、教材、标准或官方来源；
2. 搜索结果页和AI回答没有被当作项目证据；
3. DOI/原始URL、访问日期、阅读状态、支持主张和限制已同步到 `references/`；
4. 文献导向稿明确说明调查怎样改变或约束本问分析，而不是只罗列文献；
5. 其他体系、其他尺度或其他实验条件的结论没有被无条件移植；
6. 基线、候选方法、验证与论文背景中需要文献支持的主张均有来源或已收缩表述；
7. 用户已看懂文献带来的关键方法启发和声明边界。

文献调查通过只证明证据准备充分，不替用户选择模型。

# 10 — 可追溯产物交接规范

> 来源：Hermes skill `methodology/pipeline-json-handoff`

---

## 职责与强度

本文件维护机器产物的生产者、模式、消费者、版本、失效和真实性。格式、编号和路径是
实现选择，不能反向定义证据链。生产者—消费者、输入版本、真实性和失效传播为 A/B；
JSON/NPZ/CSV、编号与头部格式为 C/D。

## 核心规则

每段跨脚本流转的数据必须有明确生产者、消费者和模式。JSON 用于小型结构化元数据；
矩阵可用 NPZ，表格可用 CSV/Parquet。数据图、统计图和数值结果图必须追溯到冻结的
数据产物及生成程序；流程图、结构图、几何或机制示意图等非数据图，必须追溯到明确的
模型定义、公式、拓扑关系、设计说明或其他权威来源，并登记生成方式与版本。不得为
满足形式要求虚构数据产物，也不得仅靠 stdout 或从论文反向抄数。

每个当前有效的生成产物都必须登记生产者、用途、版本以及至少一个直接消费者。消费者
可以是下游脚本、图表生成过程、论文或方法文档中的声明、独立验证、审计检查或者最终
交付材料，不限于脚本。无生产者、无登记用途、无有效消费者、版本状态不明，被新版本
替代却仍标为当前权威，或者临时调试文件混入正式输出目录时，判为孤儿文件；没有下游
脚本读取本身不构成孤儿，终端证据必须登记其支撑的声明、图表、验证或交付职责。

## 依赖顺序

- 用清单、入口脚本、工作流配置或明确文档表达无环依赖图；文件名可使用编号帮助阅读，
  但不要求连续，也不以编号大小证明生产者先于消费者

## 脚本头部规范

产生结论、冻结产物或被其他脚本调用的程序必须提供中文可读的输入、输出和职责声明；
可用中文 docstring、文件头注释、集中清单或工作流配置表达，不固定载体。无论采用
哪种载体，都必须能从脚本快速定位，且与真实读写行为一致；集中载体中的字段也必须
具有足以让人理解的中文解释。单文件脚本或没有集中工作流清单时，极其推荐使用：
```
# 输入: upstream_file_1.json + upstream_file_2.npz
# 输出: output_file.json
# 职责: 用中文说明该脚本完成的数学或数据动作
```

输入：列出所有读取的文件
输出：列出冻结输出文件

支撑论文声明、供下游消费或复核所需的数字不得只存在于 stdout；进度、调试和临时
诊断可以只打印，不因“值得打印”就全部冻结。

## 基线模式

下游脚本需要“基线”时，应由数据准备或前期基线脚本生成独立、冻结且带版本的权威
基线产物。产物格式根据结构选择 JSON、NPZ、CSV、Parquet 或其他可复核格式，不固定
为 JSON。

- 下游模型、验证和比较程序读取同一权威基线产物，不分别重算出多个口径；
- 不读取后期模型选择、优化或结果汇总产物来反向定义基线；
- 登记基线的生成时点、输入版本、定义口径、生产者和消费者；
- 保持依赖关系无环。

## 审计检查清单

流水线完成后从正式产物清单出发逐项核对，不从某一种写入函数反推产物是否完整：

1. 每个正式产物具有生产者、实际生成路径、格式或模式、输入版本、产物版本和哈希；
2. 声明输出与实际文件一致，文件能够读取且内容非空；
3. 每个产物具有有效消费者或终端证据职责；
4. JSON、NPZ、CSV、Parquet、图像对应数据及其他正式格式都进入检查范围；
5. 写入函数搜索只用于发现可能遗漏的读写点，不能单独作为通过依据。

辅助搜索可按项目实际库和封装方式调整，例如：

```bash
rg "json\\.dump|savez|to_csv|to_parquet|savefig" src/
rg "KEPT\\s*=\\s*\\[" src/  # 结果须逐项做数字角色与来源审计
```

搜索未命中不证明没有输出，命中也不证明声明、模式、版本和消费者闭合。

## 运行清单与版本

每次正式运行保存运行清单：脚本版本或 Git 提交、输入文件哈希、参数、随机种子、求解器版本、开始结束时间和产物哈希。升级时优先保持单一代码源和可区分的运行目录，避免复制整套脚本造成分叉漂移。

每个冻结产物还应登记生产者、直接消费者和支撑的声明。上游解释、数据、假设、目标、
约束或参数发生实质变化时，将直接消费者和传递消费者写入
`project_state.json.invalidation_queue`；完成重跑、复核或确认不受影响后，才能关闭。
旧产物可以保留追溯，但不得继续标记为当前权威。

## 工作日志的真实性边界

- 从项目开始按实际发生顺序记录关键修改、运行、验证和交付，记录时间、对象、原因与结果；
- 不得为补齐档案而虚构过去的时间戳或操作。只能根据文件哈希、运行清单和产物依赖重建
  “可确认的历史”，并显式标为事后重建；
- 区分“完整流水线重跑”“局部脚本重跑”“只修改并编译论文”，不得用一次编译冒充全部
  数值重新生成；
- 论文或结果改变后同步更新运行清单和产物哈希，使工作日志、冻结结果与最终交付版本一致。

# 11 — 论文终稿组装

> 来源：Hermes skill `mathmodel/paper-finalizer`
>
> **唯一职责：**把已通过内容与证据审计的材料组装成合规提交包，并判定交付边界。
> 本文件不替代 `03` 的内容规范，也不重复 `05` 的全文审计。

---

## 强度

当届提交、匿名、文件完整性和已核验 AI 义务为 A/C；标准目录、附录形态、固定流程和
句法检查为 D。

## 论文结构示例

终稿必须从项目唯一 LaTeX 主入口编译生成，不接受从 Word、Markdown 或其他平行主稿
导出的 PDF 冒充当前论文版本。排版固定执行 `02` 中经用户确认的《数模论文模板
（修改版）》正文明示条款；DOCX 隐藏页面设置不得冒充模板要求。若当届官方文件与之
冲突，先提交用户裁决。下列结构用于检查常见组成；文档类、标题层级和章节组织按
`02` 执行，摘要段数、页边距、分页命令和附录形态按已确认项目设置与官方要求审计：

```latex
\documentclass[12pt,a4paper]{ctexart}
% preamble 见 rules/02-latex-setup.md

\begin{document}

% === 摘要（无编号，独占一页）===
\section*{摘要}
... [按实际问题数量组织]
\textbf{关键词}：从摘要中选取能够检索论文主题与核心方法的规范术语

\newpage

% === 正文 ===
\section{问题重述}
\subsection{问题背景}
\subsection{问题提出}

\section{问题分析}

\section{基本假设}

\section{符号说明}         % 表格或逐项说明须服从指定模板

\section{模型建立与求解}
% 按原题任务设置醒目入口；内部标题按实际模型、求解、结果和检验组织
% 检验紧邻其支撑的模型、结果或结论，不机械集中到独立总章

\section{模型评价与推广}
\subsection{模型评价}
% 评价优势、局限、成立条件和适用范围
\subsection{模型推广}
% 说明可迁移对象、必要调整和不能直接外推的边界

\section{结论}

% === 参考文献 ===
\begin{thebibliography}{99}
\bibitem{...} ...
\end{thebibliography}

% === 附录 ===
\newpage
\section*{附录}
% 源码、文件清单与复现材料的形态服从项目用途和当届官方规则

\end{document}
```

只有多个任务共享同一组不确定性来源，且统一分析能够形成新的跨任务结论时，才单独
设置稳健性章节；即使单设，也必须逐项回指其检验的模型、结果和结论。否则将灵敏度、
独立验证、反事实或复算放在对应任务附近，形成就地证据闭环。

## 先执行官方提交检查

本节仅适用于正式 CUMCM 参赛提交。教学练习、课程报告或期刊投稿应先在项目 README 中声明适用规范，不得把竞赛提交要求无条件套用到所有项目。

项目启动时记录“项目用途—适用年份—附录源码要求—支撑材料要求”，终稿阶段重新
核验。正式参加要求在论文附录中列出完整可运行源码的竞赛时，必须嵌入全部建模源码
及必要运行命令，文件清单不能替代源码正文，并按规定在支撑材料中提交对应可运行文件。
当适用规范允许源码只放独立支撑材料，或项目属于教学练习、往届复盘、期刊等其他用途
时，不机械把全部源码塞入论文附录；附录至少提供适用规则要求的文件清单、复现说明和
正文实际引用的必要材料。

- 摘要页、正文页数、电子文件格式和大小符合当届规范；
- 论文与支撑材料中无身份、学校和赛区信息；
- 附录和支撑材料按当届规则放置源码、文件清单与复现说明；不把“全部源码必须打印在
  正文附录”当作通用要求；
- 自主查阅的数据资料随支撑材料提交；
- 所有公开资料在正文标注并列入参考文献；
- AI 使用方式符合当届专项规定，作者对原创性、真实性和准确性负责。

### AI 使用专项检查

现有依据为《全国大学生数学建模竞赛人工智能工具使用规定（2025 年试行）》，且 2026 竞赛规则继续要求遵守该规定。提交前仍需检查是否有新版。

使用 AI 时：

- [ ] AI 生成内容已在正文相应位置标注；
- [ ] 参考文献列出工具名称、版本或型号、开发机构或公司、使用日期；
- [ ] 支撑材料中存在文件名为 `AI 工具使用详情.pdf` 的说明文件；
- [ ] 说明文件列出所有工具名称和版本；
- [ ] 逐项说明具体使用目的和环节；
- [ ] 保存关键交互记录，包括重要提示词与回复；
- [ ] 说明哪些内容被采纳、哪些未采纳以及人工修改情况；
- [ ] 核心建模与分析由参赛队独立完成。
- [ ] AI披露说明辅助范围、采纳程度、人工判断、修改和验证，没有把AI参与过的整章
      笼统标成AI生成，也没有把工具启发误写成AI对成果或思想的所有权；
- [ ] AI辅助代码生成的确定性数据图按代码辅助披露，未误标为生成式AI图像；只有AI
      直接生成或实质修改图像内容时，才在对应图件位置披露图像生成或编辑；
- [ ] “人工审计后采用”具体说明核查了哪些假设、推导、边界和结果，而不是用一句
      “已审核”替代采纳、修改和验证记录；
- [ ] 以人类是否具有理解、选择、修改、验证和责任能力判断实质控制；空白纸推导、
      反例、变式、纠错和迁移只作为参赛者自检，不声称AI能够认证人的内在思考或
      裁定成果归属。

未使用 AI 时：

- [ ] 在参考文献之后明确声明“本参赛队未使用任何 AI 工具”。

上述披露要求缺失会被视为违反竞赛规则，并导致取消评奖资格。

### 用 Nature Portfolio 框架解释 AI 使用边界

该框架既可用于教学练习和科研报告，也可帮助解释 CUMCM 规则未定义的概念，但不能
取代或削弱竞赛正文标注、工具书目和详情文件等明文义务。规则位阶与解释原则见
`12-source-audit-and-provenance.md`。

- 大语言模型不具备作者资格，作者对最终内容承担责任。
- 仅用于可读性、风格、语法、拼写、标点和语气改进的 AI-assisted copy editing，
  按 Nature 政策不属于需要声明的实质性生成；若竞赛详情文件要求记录全部用途，仍
  应如实记录为“表达整理”。
- 模型讨论、代码生成、数据分析、图表生成或自主生成正文属于实质性使用，应在 Methods 中记录；没有 Methods 时可放在等效的独立说明中。
- Nature 场景通常可集中披露；正式竞赛是否还需对应位置标注，以当届竞赛明文为准。
- 说明至少包括工具名称和版本、使用范围、作者如何复核与修改。
- AI 辅助编写确定性绘图代码属于代码辅助，不自动把程序图转化为生成式 AI 图像；
  AI 直接合成或实质修改像素时，才按生成式图像处理并审查来源和可追溯性。

建议集中声明：

> 本文在模型讨论、程序实现与文字初稿整理过程中使用了大语言模型辅助。所有数学定义、算法选择、程序输出、图表和结论均由作者结合原始数据独立检查、复算并修改，作者对最终内容承担全部责任。

## 摘要的工作版与定稿

摘要可在早期建立工作版，用于任务映射、术语统一和缺口检查，但不得把工作版视为最终
证据。正文、主要结果、检验或文献发生变化后，必须同步更新摘要；只有这些内容稳定且
完成摘要与正文、结果之间的双向追踪后，摘要方可定稿。具体日程服从项目进度与依赖，
不固定为三天流程。

摘要定稿必须同时通过内容检查与版面检查。内容检查关注全题覆盖、具体动作、结果和
亮点；版面检查必须查看最终 PDF，确认摘要不跨页、关键词醒目、正文从下一页开始。
超过一页时按 A/B/C 级别列出套话、实现信息、局部诊断和重复验证等候选删减项，不能
把解释主要模型如何工作的 A 级短语作为单纯版面压缩对象；所有文字精简必须经用户
确认，不得通过压缩规范版式解决。

版面检查只报告问题，不自动授权修复。若摘要超过一页、正文超过规定页数，或出现跨页、
孤悬、留白、图表漂移，必须保留已确认内容并报告变化。仅可在图件仍清晰完整且不改变
内容和视觉语义时先行调整其论文显示尺寸；未经用户明确确认，不得删改正文，也不得
调整字号、字体、行距、字距、页边距、段间距、标题间距、分页、图表顺序或浮动参数。
既有页数不是高于内容完整性的硬约束。

## 常见反模式

| 反模式 | 修正 |
|--------|------|
| "我们的模型最优" | "在测试方案中，X 方法在 Y 指标表现最好" |
| 长段落无结构 | 主题句 → 证据 → 过渡 |
| 图无文中解释 | 每图在正文引用并解读 |
| 结论 = 摘要翻版 | 逐项回答题目并说明核心证据、条件和边界；有依据时再写贡献、启示或开放问题 |
| 附录与支撑材料不合规 | 按当届规则放置真实源码、清单和复现说明 |
| 引用未在正文出现 | 所有 bibitem 有 \cite 引用 |
| 软件接口和运行状态代替模型求解 | 写出候选方案、筛选规则、界、停止条件和最优性依据 |
| 把“当前解不可删”写成“全局最少” | 分别给出局部不可删检验与全局下界闭合证明 |
| 只报算法名称 | 说明该算法在本题中的输入、关键步骤、判定规则和结果还原 |

# 12 — 资料审计与知识迁移

## 职责与强度

本文件负责来源真实性、规则位阶、知识迁移、反馈沉淀、AI 使用边界和删除治理。流程归
`15`，恢复归 `14`，论文写法归 `03`，提交归 `11`。不得伪造、官方优先、阅读状态
真实、项目事实不污染通用 Skill 和删除须确认均为 A；外部伦理框架条件触发。

通用 Skill 不保存“当前没有删除项”等会随审计变化的状态结论。每轮发现的待删除项、
保留理由、替代规则和用户确认状态记录在当次审计清单、项目决策日志或交接文件中；
Skill 只保存“删除必须逐项确认”的治理程序。所有带年份或网页链接的政策陈述在正式
使用前仍须重新核验。

## 目的

资料目录通常混有官方规则、教材、论文、讲座、模板、AI 提示词、示例代码、压缩包和无关文件。迁移到 skill 前必须先审计来源、正确性与适用范围，不能把“已有文件”误当成“可靠知识”。

## AI 规则的解释层级

处理竞赛 AI 规则时，区分“规则位阶”和“概念解释力”：

1. 当届竞赛文件对参赛作品具有形式约束力。正文标注、参考文献、使用详情文件、文件名
   和提交位置等明文义务必须按竞赛规定执行，不能引用期刊政策予以取消。
2. 当竞赛文件没有定义“AI 生成内容”“辅助编辑”“作者责任”“生成式图像”或标注
   颗粒度时，参考 Nature Portfolio 的成熟科研出版伦理解释这些概念。
3. Nature 的作用是澄清边界和责任，不是取得高于竞赛主办方的规则位阶。若二者存在
   明确冲突，先满足竞赛明文要求，同时在说明文件中准确限定 AI 的真实作用。
4. 不采用“只要工作链出现 AI，全部下游成果都算 AI 生成”的无限扩张解释。按 AI
   实际执行的动作、被采纳的内容和人类实质控制逐项分类。

提交前核验并保存下列官方原始页面及访问日期，不只引用二手解读：

- 全国大学生数学建模竞赛当届规则及
  [AI 工具使用规定](https://www.mcm.edu.cn/html_cn/node/eebcfb6dc37fd2de9603dc16026fdf01.html)；
- [Nature Portfolio authorship policy](https://www.nature.com/nature-portfolio/editorial-policies/authorship)：
  作者身份同时意味着贡献与责任，LLM 不具备作者资格；
- [Nature Portfolio AI policy](https://www.nature.com/sdata/policies/ai)：区分人类原文的
  AI-assisted copy editing 与实质性内容生成；
- [Nature 关于生成式图像的政策说明](https://www.nature.com/articles/d41586-023-01546-4)：
  重点审查生成像素的来源、真实性和可追溯性；
- [Nature Methods 的 AI 编辑说明](https://www.nature.com/articles/s41592-026-03020-1)：
  人类作者必须检查、修改并对最终版本负责。

核心判定句为：

> 竞赛明文义务依竞赛文件执行；未定义概念和责任边界参考 Nature，以人类的理解、
> 选择、修改、验证和最终责任为中心解释。

## 逐文件审计字段

记录相对路径、文件类型、大小、哈希、作者或机构、日期、可提取性、主题、证据等级、适用题型、已核验结论、已发现问题和处理决定。处理决定限定为：

- `adopt`：可直接吸收的通用原则；
- `adapt`：纠错或限定适用范围后吸收；
- `project-only`：只属于当前题目；
- `reference-only`：保留查阅，不写入规则；
- `exclude`：重复、无关、危险、来源不明或不可验证。

### 全项目复读的内容去重

全项目复读是会话启用、断点恢复、里程碑收尾和终稿同步的强制门，不可由
`HANDOFF.md`、状态文件或摘要替代。去重只减少同一内容的重复解析，不减少文件覆盖
范围，也不允许从局部样本推断全项目状态。

先建立文件清单并按哈希分组，再区分权威源文件、镜像副本、压缩归档、缓存、编译中间
文件和生成产物。逐字阅读每组唯一的正文、代码和配置；镜像副本以哈希一致性证明内容
相同，压缩包核对成员与校验值，缓存和编译产物检查其生产来源，不把同一字节内容重复
计作多份证据。图片和最终 PDF 需要视觉检查，结构化数据和二进制矩阵需要检查模式、
维度、范围与关键不变量，不能因其不可直接显示为文本而跳过。

## 知识迁移规则

规则来源与规则强度必须分开记录。讲座、优秀论文或写作中心可以提供 A/B/C/D/E 中的
任何一种候选内容；强度取决于官方依据、数学正确性、真实性、适用条件和可验证后果，
不取决于来源名称。审计来源型规则组合时，逐条记录稳定 ID、原文、来源、适用条件、
强度、规范归属和阅读状态。

若规则缺陷与替代写法均明确，且改写保留其合理目的，可以直接改写并同步关联 Skill。
只有完全删除且没有替代规则，或合并、迁移会使独立含义或竞争版本消失时，才须向用户
逐项提交稳定 ID、原文、分类、理由、保留覆盖和影响。未获确认的纯删除项留在
“待人工确认”区，不得静默删除，也不得作为 A/B 级失败门执行。

1. 官方规则只写官方明确要求并注明年份；下一届必须重新核验。
2. 教材中的定义和算法需核对名称、假设、复杂度与软件接口。
3. 讲座和模板中的篇幅、字体、文献数、公式数属于经验建议，除非官方文件明确规定。
4. AI 提示词只可提炼为检查维度，不可迁移其中的虚拟数字、“高奖公式”或未经运行的模型组合。
5. 示例代码必须实际运行并核对数学含义；示例文字与输出冲突时，以独立复算为准。
6. 当前赛题的节点号、参数、文件路径和最终答案不得写入通用 skill。
7. 安装程序、破解补丁、序列号、无关行政文件和重复压缩包不构成知识来源，不执行、不传播。
8. AI 使用记录应从项目开始持续保存，不能在终稿阶段凭记忆补写；记录至少包含工具与版本、日期、用途、关键交互、采纳内容和人工修改。
9. 题目范围必须从题目原文逐项建立任务清单；目录名、README 摘要、已有代码和迁移来的
   项目状态只能帮助定位材料，不能作为删减问题的依据。
10. 版式规则应从实际交付模板或官方文件提取，并记录其来源与适用范围；通用论文范式
    只能补充模板未规定之处，不能覆盖模板对章节、符号说明、字号或页边距的明确要求。
11. 用户反馈和项目迭代可提炼为检查维度，但只有跨题成立、能够操作和验证的原则才进入
    skill；本题节点、结果、路径、个人偏好和一次性补丁留在项目文档。
12. 迁移前为每条候选规则回答三问：是否至少适用于另一类项目，是否有明确触发条件，
    是否能通过检查清单或产物验证。任一答案为否时，不写入通用 skill。
13. 优先补充职责最接近的现有 skill，避免为一次反馈新建碎片化文件；新增规则应写成
    可执行动作、验证标准和反模式，而不是保留原项目叙事。
14. 回顾历史时区分显式日志与产物推断：日志可陈述实际操作，哈希、时间线和依赖只能
    支撑“可推断的变化”，不得据此虚构人员、动机、时间戳或未留痕的运行过程。
15. AI 披露规则属于时效性高的竞赛规则，正式提交前必须重新核对当届官方文件，不能
    用期刊、学校或往届规范替代。若规则要求正文对应位置标注、工具书目和独立详情
    文件，论文末尾的一段集中说明不能替代这些材料。
16. AI 使用详情只能基于真实保存的交互、工作日志和产物编写。能够逐字恢复的提示词
    与回复可原文记录；只能由日志确认主题时，应标注为“依据日志重建的摘要”，不得
    伪造逐字对话、模型版本、使用日期或采纳过程。
17. 教学练习可以参照竞赛披露结构，但必须明确“形式对齐”不等于“正式参赛合规”；
    项目用途一旦改变，应重新审计身份信息、正文标注、参考文献、支撑材料文件名和
    当届提交要求。

## 外部反馈的只读方法论沉淀

当用户把当前阶段限定为“只根据导师、评审或用户反馈总结方法论，不修改成果”时，
启用反馈只读模式。该模式的授权对象仅是通用 skill；论文、模型、代码、冻结输出、
图表、规划权威、交接状态、工作日志和交付镜像均保持不变。

按以下顺序处理：

1. 逐条读取原始反馈及其指向的上下文，分开记录反馈原话所指出的现象、反馈者给出的
   理由，以及AI据此作出的推论；不得把推论冒充反馈原意。
2. 将反馈分类为任务关系、背景与问题类别、方法比较、模型机制、参数依据、术语解释、
   证据充分性、结构组织、语言可读性或版面呈现；一条反馈可有多个类别，但不得因此
   自动扩大修改范围。
3. 对每条反馈执行“个案—判据”转换：删除题目名称、节点、数值、人物和具体句子，
   写出跨项目触发条件、检查动作、通过标准及典型反模式。
4. 先搜索现有 skill。若已有规则能够直接检出同类问题，只记录“已覆盖”，不增加
   同义条款；只有现有规则无法触发、无法执行或无法验证时才补充最小规则。
5. 把新规则写入职责最接近的现有文件。问题关系、方法类别和解释充分性归论文内容
   或审计协议；反馈来源、适用边界和知识迁移归本文件；不得为一轮反馈新建碎片化
   skill。
6. 修改后只验证 skill 的结构、触发条件、可执行性、去重和项目专用信息泄漏。只读
   模式不得以“顺便验证效果”为由编译论文、重跑模型、改状态文件或同步成果目录。
7. 向用户报告“已有规则覆盖、实际新增规则、拒绝迁移内容和仍需澄清之处”。只有
   用户另行授权成果审计或修订后，才把反馈映射回具体项目并沿最早受影响阶段处理。

完成标准：

- 原始反馈的含义未被AI扩写成新的评价要求；
- 每条新增规则至少适用于另一类项目，并具有触发条件、动作和可检查结果；
- skill 中没有当前项目的专用事实、个人偏好或一次性改句；
- 本轮除 skill 外没有任何文件发生变化。

反模式包括：听到“看不懂”便直接改论文；把某个具体术语列为永久禁词；重复写入已有
的“白话解释”规则；从一次表扬推导通用评分权重；以及先修改成果、再把修改过程包装
成方法论。

## AI 辅助与人类主导

AI 是工具，不是论文作者、责任主体或成果权利主体。披露的目的，是说明工具在研究
流程中的辅助范围和最终内容如何受到人类控制，而不是把观点、公式或模型的“主权”
按首次输出时间分配给AI。

### 项目决策权

所有进入当前权威文档、冻结结果解释、论文和交付物的实质内容，都必须经过与用户的
深交互后确立。AI可以提出候选、整理证据、执行推导、编写已确认模型的代码、运行试验、
复核结果和改善表达，但不得自行批准题意解释、评价标准、假设、模型族、参数依据、
验证命题、结论强度或推广范围。

交互记录应区分：

- AI提出了什么候选及依据；
- 用户理解并决定了什么；
- 哪些内容仍为待审草稿；
- AI随后代为执行了哪些机械或分析工作；
- 新证据是否触发重新决策。

“用户未反对”“AI已生成”“旧稿已采用”都不等于当前授权。人工主导不是在终稿阶段
补一句“已审核”，而是在人会改变研究方向的节点真正拥有知情选择权。

不得把“工作链中出现过AI”直接改写成“整项内容由AI生成”；也不得因为AI提供了重要
启发，就否定人类在提出问题、理解方案、选择方向、整合证据、修改模型、验证结论和
承担责任方面的贡献。

### 人类实质控制

评价成果是否由人类主导，重点检查：

1. 人类是否决定要解决的现实问题和评价标准；
2. 人类是否理解模型假设、变量、目标、约束和适用边界；
3. 人类是否能够拒绝、修改或组合AI建议，而非被动照搬；
4. 人类是否根据题目、数据和现实条件决定最终方案；
5. 人类是否核查公式、程序、图表和结论；
6. 人类是否能够解释反例、失败条件和替代方案；
7. 人类是否对最终作品的真实性、准确性和完整性承担责任。

满足这些条件时，合理表述是“人类主导、AI辅助”。即使AI参与核心方案启发，也不
因此成为成果主体。若人类不理解、无法解释且未经核验地直接采用输出，应记录为
真实性与独立完成风险，而不是表述为“成果归AI所有”。

### 辅助范围记录

对重要环节记录以下事实，不制作思想产权分配表：

- AI用于问题讨论、候选方案启发、数学表达、代码草拟、调试、检查还是语言整理；
- AI建议被全部采纳、部分采纳、修改后采纳还是拒绝；
- 人类作了哪些判断、修改、补充和验证；
- 最终内容由什么数据、推导、程序或独立检验证据支持；
- 谁决定写入作品并承担责任。

典型写法：

- 人类已有观点，AI只改善结构与语言：写“AI辅助表达整理”，不写“观点由AI生成”；
- 人类发现问题，在人机讨论中形成形式化方案，人类理解、修改并验证：写“人类提出
  问题并主导最终建模，AI参与候选方案讨论与形式化辅助”；
- AI只批评、检查或提出未采纳建议：在详情中记录用途和未采纳情况，不把最终内容
  标为AI生成；
- AI辅助编写代码，程序依据真实数据确定性绘图：披露代码辅助，不把图件称为生成式
  AI图像；
- AI直接生成或实质修改图片内容：在对应图件位置披露图像生成或编辑。

分类时进一步执行以下边界：

- **辅助编辑**：人类已形成原始观点和实质内容，AI仅改善可读性、风格、语法、拼写、
  标点、语气、措辞或格式。按 Nature 概念不视为自主生成研究内容；若竞赛详情文件
  要求完整记录工具用途，仍如实记录“表达整理”。
- **实质性辅助**：AI参与候选模型、形式化表达、代码草拟、数据分析或正文初稿。披露
  具体作用、采纳范围和人工核验，但不得由“使用 AI”直接推出“成果归 AI”。
- **确定性程序图**：图像由真实数据和明确算法可重复计算得到。AI若帮助编写绘图代码，
  记录代码辅助；除非 AI 直接生成或改动图像内容，不标为生成式 AI 图像。
- **生成式图像**：模型直接合成、补绘或实质修改像素。按竞赛明文和适用出版政策在
  对应图件处披露，并检查真实性、版权和可追溯性限制。

例如，人类独立识别题目中的逻辑缺口，AI提出候选后处理规则，人类理解、修改、复现、
验证并决定采用时，应记为“人类发现问题并主导最终建模，AI参与候选方案讨论与形式化
辅助”，而不是把问题发现、模型或全部下游结果笼统归为 AI 生成。

实际交互时间线可以帮助说明AI在哪个环节提供过辅助，但不得据此赋予AI作者身份或
成果主权，也不得用“谁先说出一句话”替代对人类实质控制的判断。

### 深层掌握自检

空白纸推导、反例、变式、纠错和迁移测试可帮助参赛者自查自己是否真正理解并能够
维护模型：

- 不看AI记录重新定义变量、目标、约束和求解逻辑；
- 指出方案失效条件和结论边界；
- 改变参数、信息结构或现实规则后修改模型；
- 主动发现建议中的遗漏、错误或不必要假设；
- 把方法迁移到另一对象并重新解释。

这些测试是人类自检和答辩准备工具，不是AI能够在对话中认证的事实，也不能被AI用于
裁定人的内在思考、原创程度或成果归属。记录时只能写实际完成并有证据的检查。

## 正文标注颗粒度

“AI参与过工作链”与“AI生成内容被实质纳入最终作品”必须分开判断。正文相应位置
优先标注被实质采用的AI输出，可按公式、段落、小节、程序文件或直接生成的图件设置，
不要求把整问、整章或所有下游结果一并贴成AI生成。

建议写法应同时交代人类主导与AI辅助范围，例如：

> 参赛者在审查既有方案时提出该逻辑缺口，并主导问题解释与最终方案选择；AI参与
> 候选形式化方案的讨论。参赛者对假设、推导、边界条件、实现和数值结果完成核验，
> 并对最终模型承担责任。

详情文件再记录关键交互、采纳范围、人工修改和验证证据。若当届官方文件对标注颗粒度
给出更明确要求，以官方文件为准。

## 常见污染信号

- 把一个库函数误称为另一算法；
- 用连续优化器声称求得整数最优解；
- 把搜索结果页当原始文献 URL；
- 只有摘要可读却标记“已阅读全文”；
- 把推荐篇数或版式写成官方硬要求；
- 用通用示例结构覆盖指定 Word/LaTeX 模板的明确章节结构；
- 因现有脚本只覆盖部分任务，就反向解释题目范围并遗漏其余小问；
- 从其他题迁移来的变量、物理对象、作者示例或绝对路径；
- 示例数据、文字结论和代码输出不一致；
- 以随机扰动代替有现实含义的不确定性模型。

## 交付审计

- 内容是否跨项目成立；
- 每条硬性规则是否有更高等级来源；
- 是否明确区分官方要求、团队约定和经验建议；
- 算法名称、数学假设、软件接口是否一致；
- 是否保留来源与适用范围；
- 是否误收项目专用事实或不可验证结论。
- 是否完成唯一内容阅读，并对镜像、归档、缓存和生成产物给出相应核验方式；
- 新增规则是否具有跨项目触发条件、执行动作和可验证的完成标准。

# 证据链、复现与来源规则

## E-01 双向证据链

正向：

`原题与数据 → 题意解释 → 方法规格 → 代码 → 冻结结果 → 图表与正文 → 摘要与结论`

反向：

`论文声明 → 冻结结果 → 代码 → 方法规格 → 题意与原始数据`

每个关键声明记录证据路径、验证状态、适用范围和禁止外推。发现冲突时，修正最早错误
层并重新生成全部下游产物，不能只改论文表面措辞。

论文不是单一权威文件。题面、批准的任务定义、方法规格、公式、实现、冻结输出、图表、
正文、摘要和结论不一致时，不能用其中任一处单独覆盖其余内容；先定位最早的不受支持
层，再把修正传播到全部消费者。

## E-02 数据与代码

- 原始输入只读并保存哈希、工作表或页码、原始行号和原文；
- 结构化字段、派生字段、分析设置和更正记录分开；
- 结论必须冻结在结构化输出中，控制台文字不能作为唯一证据；
- 验证程序不导入主实现的结论逻辑，并直接读取权威输入复算；
- 代码声明的输入输出与真实读写一致；
- 任何数字按其身份和显示精度追溯，不用统一容差掩盖错误。

每个当前有效机器产物登记生产者、输入版本、模式、哈希、直接消费者、支撑声明和当前
状态。消费者可以是下游脚本、图表、正文、验证或交付材料；没有下游脚本读取不等于
孤儿，但没有生产者、用途、消费者或版本状态的文件不得作为当前证据。上游题意、数据、
假设、目标、约束或参数改变后，使直接与传递消费者失效，重跑或证明不受影响后才能
关闭。

程序中的数值按角色区分：题设常量可以集中命名并保留来源；灵敏度范围、显示精度和
安全余量属于分析设置；临界值、最优值、推荐方案和瓶颈对象必须实时计算，禁止把上次
输出写回求解逻辑。展示点若依赖计算结果，先计算再按明确规则生成。论文关键结果在源码
中以裸常量出现时，除带来源的测试期望值外，按严重问题追查。

## E-03 来源

题面、官方文件、学术文献、公开论文、讲座规则和用户决定保持来源身份。公开优秀论文
只能用于观察表达结构，不能复制文字、模型和结果，也不能自动提升其写法为硬规则。

外部资料记录原始 URL 或 DOI、访问日期、来源类型、阅读状态、支撑主张和限制。只有
摘要可读时不得声称阅读全文；搜索结果页、AI回答和往届答案不能作为事实、机理或最优性
依据。论文中的外部主张必须能回到与其身份相符的来源，不能用主题相关文献装饰。

## E-04 一修全修

术语、单位、指标、条件、数字或证明范围改变后，搜索摘要、正文、公式、表头、图注、
结论、审计、复现文档和交付副本的全部关联表达。同步核对完成前不得关闭问题。

# Provenance and delivery quality

Read this rule for every substantive task.

## Evidence chain

Maintain both directions:

```text
input → interpretation → treatment/design → specification → code → frozen output → verification →
figure/table/prose → conclusion

claim → figure/table/frozen output → code → specification → interpretation → original input
```

For every material artifact record producer, inputs, parameters or decision identity, timestamp or
version, dimensions, units, hash where appropriate, and consumers.

## Authority

- Original statements and inputs are immutable evidence.
- Current approved interpretations and specifications have one owner each.
- Frozen outputs are not authoritative beyond their producer and verification identity.
- Handoffs, state files, READMEs, and logs are navigation aids, not completion proof.
- Archives and excellent papers preserve provenance or expression examples; they do not become
  current truth or model authority.

## Change propagation

When an upstream layer changes, identify every direct and transitive consumer. Regenerate it, prove
it remains valid, or mark it provisional/invalid. Synchronization is demonstrated by content and
identity checks, not by a copy command.

## Draft and formal delivery

- Keep drafts isolated and visibly marked in filename plus page or metadata.
- Do not occupy the formal entry point before explicit promotion.
- Do not promote until all required components are verified, evaluator-visible chains are complete,
  rendered pages are inspected, and the user explicitly approves formal status.
- Package only current, traceable, necessary files and verify the package itself.
