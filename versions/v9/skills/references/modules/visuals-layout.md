## 职责与强度

本文件是正式论文排版的唯一建设入口，负责 LaTeX 主稿、官方模板落实、文档类与编译
引擎、页面参数、字体字号、标题层级、公式与图表排布、分页、浮动体、编辑安全、编译
日志和最终 PDF 版面检查。论文写什么由 `03` 决定，图表内容与视觉编码由 `04` 设计，
全文通过判定由 `05` 执行，官方提交边界和交付打包由 `11/12` 核验。

用户确认采用的《数模论文模板（修改版）》正文中明确写出的字体、字号、行距、标题
层级和章节结构为 A/C；唯一主稿、成功编译和最终 PDF 核验为 A。DOCX 文件自身但正文
未明示的页面设置、模板没有规定的宏包实现和浮动调优为 D，不得冒充模板硬规则。
不得用排版规则删减必要内容，也不得用内容修改掩盖字体、分页、浮动或编译缺陷。

## 先服从当届官方规范

以 2026 CUMCM 规范为例：电子论文首页为摘要页，摘要原则上不超过一页，正文不超过 30 页且不设目录；论文与支撑材料分别提交，所有文件不得出现身份、学校或赛区信息。官方未统一规定字号、字体、行距和颜色，因此这些属于版式方案，不得写成竞赛硬规则。每届比赛开始前必须重新核验官网文件。

## LaTeX 主稿硬规则

本数学建模论文工作流以 **LaTeX 作为正式论文的唯一源格式**，不得另建 Word、Markdown
或其他格式作为竞争主稿。只有当官方明确禁止 LaTeX 或强制提交其他可编辑源格式时，
才按官方要求改变；这种例外必须保存依据并同步修改项目入口。

允许在正式组装前使用 LaTeX 内容草稿，但必须同时满足：

- 草稿位于独立目录并使用 `*_draft.tex`、`*_draft.pdf` 等显式草稿名称，不占用
  `paper/paper.tex`、`paper/paper.pdf` 或项目约定的正式入口和正式输出名；
- 草稿源码、首页或页眉以及 PDF 元数据至少使用两种方式标明“草稿/非正式论文”；
- 正式入口不得自动 `\input` 整个草稿。内容只有在完成审核和人工确认后，才能由正式
  组装步骤选择性迁入；文件存在、成功编译或进入协作镜像均不构成内容批准；
- 协作镜像可包含明确标记的草稿以供团队审阅，但正式提交包、最终论文链接和交付清单
  不得把草稿列为正式成果；
- 同一阶段只能有一个当前草稿入口。旧草稿须归档或标明失效，避免多个可编译版本竞争。

Markdown、Word 或其他文件可以作为历史来源、证据笔记或内部说明保留；只要明确停止
作为当前正文维护且不能独立冒充正式论文，就不构成竞争主稿。

## 源文件语法边界

- `.tex` 源文件只使用有效 LaTeX 表达标题、强调、引用、交叉引用、公式、图表和环境；
  不得把 Markdown 的 `#` 标题、`**` 强调、`[文字](链接)`、管道表格或围栏代码块当作
  正文结构。
- `.md` 证据笔记、规划、审计和说明只使用 Markdown。不得为了以后迁入论文而提前嵌入
  `\section`、`\cite`、`\ref`、`\begin...\end` 或 LaTeX/MathJax 数学定界符；短公式
  用文字或 Unicode 表达，长公式放入标记为 `text` 的围栏代码块并紧接符号解释。
- 从 Markdown 迁入 LaTeX 时执行显式格式转换：标题、强调、链接、表格、代码块和公式
  分别改写为对应 LaTeX 结构，并重新核对语义、引用和编号。不得仅修改扩展名或直接
  粘贴后把混合语法留在 `.tex`。
- 本 Skill 文件中的 `latex` 围栏仅用于展示 `.tex` 实现，不属于项目 Markdown 正文。

论文排版固定执行《数模论文模板（修改版）》正文明确写出的字体、字号、行距、标题
层级和章节结构，不得把这些已确认条款降为建议。该模板末尾自述“仅供初学者参考”，
因此没有在正文中明确规定的项目不得从 DOCX 隐藏属性或个人经验反推成硬规则。若当届
官方文件与已确认条款发生明确冲突，必须先向用户提交冲突和影响，未经确认不得自行
更换。

使用 XeLaTeX 编译中文论文。XeLaTeX 是编译引擎，只负责解释 LaTeX 源码、中文字体和
宏包，不自带《数模论文模板（修改版）》的页面参数；模板参数必须在项目模板或
preamble 中显式落实。项目使用模板现有文档类；需要重建入口时使用 `ctexart`。项目
必须有唯一主编译入口，例如 `paper/paper.tex`。短论文可用单文件，长论文或多人协作
可用 `\input`、`\include` 等拆分，但不得形成多个竞争主版本。最终以 LaTeX 源文件的
可维护性、编译日志和实际交付 PDF 为准。

### 正文模块的拆分基线

需要拆分源码时，优先按评审可见、跨小问稳定的论文职责拆分，例如问题重述、问题分析、
模型假设、符号说明、数据预处理、模型建立与求解、评价和参考文献；模型章内部再按原题
任务或共享模型拆分。不得把历史工作阶段、人员分工或“某问曾经先写成一份草稿”直接
固化为跨越多个一级章节的 body 文件。

唯一入口必须按最终阅读顺序显式调用各模块。模块名应反映实际内容职责；一个名为某小问
的文件不得同时混装问题重述、全局假设和其他小问分析。简单短文可保持单文件，不为满足
目录外观机械拆分；只有拆分能降低误放、冲突或协作成本时才使用。

拆分或重命名后不能只验证“仍能编译”。立即执行：

1. 列出每个模块的标题范围和内容职责；
2. 检查跨文件的 LaTeX 环境、命令参数、标签和引用没有被截断；
3. 按 `03` 审计每段是否属于当前章节，并移动同职能重复内容；
4. 搜索旧文件名，更新入口、导航、日志和协作镜像，移除当前目录中的陈旧竞争模块；
5. 重新编译至引用稳定，检查日志、页数、受影响页面和相邻页面；
6. 核对统一入口与协作镜像逐文件一致。

文件拆分只是维护手段，不改变论文目录，也不证明内容已经组织正确。

## 固定采用的模板明示条款

以下内容由模板正文明确写出，并经用户确认在本工作流固定采用：

- 中文正文宋体小四，英文与数字 Times New Roman，单倍行距；
- 题目黑体三号、居中、段前后 18 磅；
- 一级标题黑体四号、居中、段前后 12 磅；
- 二级至四级标题黑体小四、段前后 6 磅；
- 低级标题不得擅自缩成小于正文的字号。二至四级标题同为小四时，通过黑体、编号、
  段前后间距和四级标题缩进建立层级，不把三级、四级降为五号；
- 模型部分按指定模板统一置于“模型建立与求解”一级章下。原题包含多个并列问题或
  独立任务时，极其推荐将其设为二级标题，并采用原题任务标识及具体研究对象，使评审
  能够快速定位；
- 各问完整覆盖模型建立、模型求解、问题结论、检验分析和必要的小结功能；这五项用于
  内容完整性检查，不机械设为五个固定三级标题。

标题层级首先由内容的并列、从属和先后关系决定，其次才由编号与留白呈现；不得通过
修改模板字号制造并不存在的内容层级。多任务论文必须为各项任务提供醒目、无歧义的
标题入口；标题具体措辞服从原题标识和实际内容，不把某一道题的编号句式固化为跨项目
模板。原题小问若只是同一模型链中的从属步骤，可以置于对应任务标题下作为三级或
四级标题；多个任务共享同一模型时，可以先设置共享模型章节，再为各项任务设置清晰
的结果与回答入口。不得仅因原题存在数字或字母编号便机械提升标题层级，也不得以共享
模型或合并章节为由隐藏任何任务入口。

### 符号说明版式

先核验当届官方文件和实际交付模板；若其明确规定符号说明的形式，直接服从，不以优秀
论文或通用惯例覆盖。模板未规定时，优先使用无竖线的全宽三线表，并按“符号—含义—
单位或取值”组织：

- 符号列使用数学模式，含义列只写对象或数学定义，单位、量纲、集合或取值类型单列；
- 一行只承载一个语义一致的符号或符号组；只有定义平行且单位相容时才合并；
- 按索引与集合、核心变量、模型参数与统计量、决策变量的阅读顺序排列；
- 长释义较多时使用三列全宽表，不为节省高度机械改成两组“符号—含义”并排的四列
  表；仅当释义都很短且视觉检查无拥挤、错行或歧义时才使用配对列；
- 使用 `booktabs` 的顶线、表头分隔线和底线，不加竖线或逐行横线；编译后检查列宽、
  数学字体、单位断行、跨页和相邻章节留白。

此规则属于模板未规定时的 B 级可检查版式规则，不是竞赛官方强制格式。公开展示优秀
论文只能用于确认“表格化、紧凑化”是可行惯例，不能证明某一固定列数是唯一规范。

- 模板正文没有规定页边距，不得称上下 `2.54 cm`、左右 `3.175 cm` 为模板要求，也

  `2.54 cm`、左右 `3.175 cm`；这只证明该样例文件当前采用此页面设置。

  主稿规则冲突，因此不迁移为执行规则；只保留为来源材料的工具偏好。
- 模板正文提出插图“不带彩色和背景”。其中“不带彩色”与用户确认采用的 Nature

- 模板末尾允许按需求适当调整，说明它不是官方强制规范。固定采用哪些明示条款来自

## XeLaTeX preamble 基线

以下代码用 XeLaTeX 实现已确认的字体、字号和标题参数。页边距按以下优先级确定：

1. 当届官方文件明确规定页边距，或官方指定的实际交付模板能够可靠核验其页面几何且
   要求沿用该版式时，采用该值并记录来源；普通示例、参考论文和来源不明的隐藏属性
   不属于这一层；
2. 官方或模板未规定而用户已经确认项目页边距时，采用用户确认值；
3. 两者均无明示值时，使用四边 `2.5 cm` 作为中性实现默认值，并在项目版式记录中
   标明它是可调整的工程默认值，不是竞赛官方或模板硬要求。

不得把 DOCX 样例的隐藏节属性直接作为新项目基线，也不得因“实现基线”四字跳过项目
确认。项目用途或模板变化时重新执行上述优先级。

```latex
\documentclass[12pt,a4paper]{ctexart}   % 12pt = 正文小四

\usepackage{amsmath,amssymb,amsthm}
\usepackage{booktabs}                    % 三线表
\usepackage{graphicx}
\usepackage[margin=2.5cm,headheight=15pt]{geometry} % 中性工程默认值；有官方/模板明示值或用户确认值时替换
\usepackage{fancyhdr}
\usepackage{hyperref}
\usepackage{caption}
\usepackage{enumitem}
\usepackage{float}
\usepackage{setspace}
\usepackage{titlesec}
\usepackage[section]{placeins}          % 浮动图禁跨节漂移
\singlespacing                           % 单倍行距

% ---- 字体：中文宋体/黑体，英文数字 Times New Roman ----
% 字体名称依赖运行环境；先用 fc-list 核验，再按赛区模板设置。

% ---- 标题字号 ----
\titleformat{\section}{\centering\heiti\fontsize{14pt}{16pt}\selectfont}{}{0pt}{}
\titlespacing{\section}{0pt}{12pt}{12pt}
\titleformat{\subsection}{\heiti\fontsize{12pt}{14pt}\selectfont}{}{0pt}{}
\titlespacing{\subsection}{0pt}{6pt}{6pt}
\titleformat{\subsubsection}{\heiti\fontsize{12pt}{14pt}\selectfont}{}{0pt}{}
\titlespacing{\subsubsection}{0pt}{6pt}{6pt}
\titleformat{\paragraph}[block]{\heiti\fontsize{12pt}{14pt}\selectfont}{}{0pt}{}
\titlespacing{\paragraph}{1em}{6pt}{6pt}

% ---- Float 调优 ----
\renewcommand{\topfraction}{0.92}
\renewcommand{\bottomfraction}{0.85}
\renewcommand{\textfraction}{0.05}
\renewcommand{\floatpagefraction}{0.85}
```

## 关键排版规则

- **摘要+关键词占一页**，摘要末尾 `\newpage` 隔开正文
- 参考文献是否另起页由版面决定；官方未要求强制分页
- 附录的分页和代码呈现服从官方要求；可使用 `verbatim`、代码清单或独立支撑材料，
  不强制把全部源码印入论文
- 摘要一般不放展示公式；必要符号和缩写按官方规则、首次解释和可读性决定
- `\newpage` 按模板、语义边界和最终浮动结果使用，不设跨项目固定次数
- 图表在 LaTeX 源码中放在首次实质引用段之后，并由紧随其后的正文解释图表中的关系、
  现象及其对本问结论的意义，形成“引用引导—图表—就地解释”的局部闭环。图表不得
  漂到尚未引用的位置，也不得与解释之间插入无关标题、另一幅图表或其他论证。
- `[htbp]` 只在最终 PDF 仍保持上述局部闭环时使用。若浮动使图表与首次引用或解释
  分离，先在不降低可读性的前提下调整图像显示尺寸并复查当前页及相邻页。改变源码
  位置、浮动参数、浮动屏障、`[H]`、非浮动结构或正文顺序均须先提交用户确认。

## 版面冲突的修改权限

摘要超过一页、正文超过规定页数、关键词跨页、标题或句子孤悬、图表漂移、大块留白
以及其他版面冲突出现时，先报告具体页面、冲突原因和受影响内容，不得擅自压缩、删除、
合并或改写任何词句，也不得自行调整字号、字体、行距、字距、页边距、段前后间距、
标题间距、分页命令、图表顺序或浮动参数。

唯一可先行尝试的自动处置是调整图像在论文中的**显示尺寸**，且必须同时满足：

1. 不裁剪、重绘或改变图像内容、数据、比例关系、颜色语义和标注；
2. 最终 PDF 中标题、坐标轴、图例、节点、路线、数字和注释仍清楚可辨；
3. 图像仍完成原有信息职责，并与首次引用及就地解释保持局部闭环；
4. 调整后复查当前页、前后页、缩印和普通打印效果，不产生新的孤悬、空白或漂移。

若仅调整图像显示尺寸不能解决冲突，列出文字删改、图表取舍、浮动调整或版面参数方案
及其影响，等待用户明确确认后实施。

## LaTeX 编辑安全

- 使用能够精确保留反斜杠的编辑方式；每次小范围修改后立即编译。
- 编译前扫描 Markdown 结构残留；若 `.tex` 中出现 Markdown 标题、链接、强调、管道
  表格或围栏代码块，先完成格式转换，不把“仍能编译”视为语法边界通过。
- 禁止无边界的全局替换；修改前后检查公式、引用和环境配对。
- 双编后检查 Error、undefined citation/reference、overfull box 和最终页数。
- 编译后必须查看实际 PDF。源文件中的 `10.5pt`、`12pt` 等数值不能只凭视觉猜测；先确认正文基准字号，再逐级核对标题是否满足指定模板。

# 04 — 论文图像生成与视觉审计

> 用于数学建模论文的网络图、统计图、空间图和多面板图。生成图表前读取，编译终稿后再次逐条审计。

---

## 职责与强度

本文件设计图表的信息职能、视觉语义、可访问性和最终尺寸质量。数据真实性由 `05/10`
检查，模板参数服从 `02`。本工作流经用户确认固定采用 Nature Research Figure Guide；
不误导、可追溯、可读和非颜色唯一编码为 A/B，具体色值和实现路径为 C/D。

## 核心原则

图像必须独立承担一种不可由相邻表格或正文替代的表达任务，例如空间关系、趋势、分布、路径或权衡。颜色用于编码语义，不用于装饰；统一风格不是“全部灰度”，而是同一对象在全篇始终具有同一颜色、符号和线型。

按 Nature 官方规范执行：

- 允许使用具有明确数据语义的彩色；使用色觉友好且对比充分的配色，避免红绿组合与
  彩虹色阶，并同时用形状、线型、明度或标签提供冗余编码；
- 同类图统一字体、字号、线宽、图例顺序和坐标单位；
- 保持简洁背景，避免背景网格、三维效果、渐变、阴影、装饰图标和无意义的大面积填色；
- 线图、结构图、文字、箭头和比例尺优先使用保留可编辑元素的 PDF 或 EPS 矢量格式；
- 照片类位图按最终使用尺寸至少达到 `300 dpi`，不得用插值放大冒充真实分辨率；
- 图中文字在最终缩放尺寸下必须清楚，不以绘图画布上的原始尺寸判断。

正式制图前核验以下 Nature 官方页面并记录访问日期：

- <https://research-figure-guide.nature.com/figures/preparing-figures-our-specifications/>
- <https://research-figure-guide.nature.com/figures/building-and-exporting-figure-panels/>

## 共享视觉语义

把跨图复用的颜色语义、字体、线宽、标记和导出参数集中到一个可复用的样式模块或配置
中，并由相关绘图脚本共同引用；文件路径和实现形式服从项目现有结构。建议语义如下，
具体色值可按任务调整：

| 对象 | 推荐编码 |
|---|---|
| 背景道路、辅助网格 | 浅冷灰细线 |
| 普通需求节点 | 中性灰小圆点 |
| 现有设施 | 蓝色圆点 |
| 推荐或新增设施 | 橙色星号 |
| 出入口、边界控制点 | 紫红色菱形 |
| 事件点 | 朱红色 `X` |
| 普通路径 | 低饱和蓝色 |
| 瓶颈、最弱路径 | 朱红色粗线 |
| 基准方案 | 中性灰 |
| 优化方案 | 蓝绿色 |
| 约束或阈值 | 朱红色虚线 |

可采用 Wong/Okabe–Ito 色板：

```python
COLORS = {
    "blue": "#0072B2",
    "sky": "#56B4E9",
    "green": "#009E73",
    "orange": "#E69F00",
    "vermillion": "#D55E00",
    "purple": "#CC79A7",
    "gray": "#73777D",
    "light_gray": "#D9DDE2",
}
```

禁止仅依赖颜色差异；避免红绿组合与彩虹色阶。必须检查灰度退化后关键对象能否依靠
形状、线型、明度或标签识别。

## 统一格式

- 图中文字使用无衬线字体；英文、数字优先使用 Arial 或 Helvetica，中文使用兼容的
  无衬线字体；
- 除面板标号外，最终输出中的图内文字原则上为 `5--7 pt`；不得为满足该范围而牺牲
  中文可读性，最终仍以实际 PDF 页面检查为准；
- 多面板图使用 `8 pt`、粗体、正体、小写 `a`、`b`、`c` 等面板标号；
- 坐标采用“变量（单位）”，不要在同一论文混用 `/min`、`/(km/h)` 等形式；
- 图例去边框，并按“背景对象→现有设施→新增/特殊设施→关键路径”排序；
- 避免彩色文字；文字优先使用黑色，深色背景上可使用具有充分对比度的白色；
- 图题只写在 LaTeX `\caption{}` 中，不在图内重复；
- 图内避免完整解释句，只保留节点编号、短标签和必要引线；
- 多面板图保持面板高度、字体、比例和边距一致；
- 同一语义不得在不同面板中交换颜色，例如“现有方案”不能一幅图深色、另一幅图浅色。

## 图表选择与版面

- 小规模精确数值优先使用三线表；
- 趋势、空间、路径、分布和权衡使用图；
- 图与表若表达同一结果，必须明确分工：表给精确值，图给空间结构或趋势；
- 不让一个表和一个大图无理由共同占据整页；
- 图像尺寸取“能够清楚表达的最小尺寸”，不得机械使用 `0.9\textwidth`；
- 图表与正文形成“引用引导—图表—就地解释”的局部闭环：源码放在首次实质引用段后，
  图表后紧跟关系、现象和结论解释；中间不插入无关标题、另一图表或其他论证。若浮动
  破坏该闭环，可先在不影响最终 PDF 可读性的条件下调整图像显示尺寸，并复查当前页
  与相邻页；改变源码位置、浮动屏障、固定方式、正文顺序或其他版面参数须经用户确认。
- 自动调整只允许改变论文中的图像显示尺寸，不得裁剪、重绘、删标注、降低清晰度或
  改变数据与视觉语义。若坐标轴、图例、节点、路线、数字或注释变得难以辨认，应回退
  调整并提交其他方案。

## 正文中的图表解读

图注负责标明图中对象、变量和编码，正文负责完成分析，二者不能互相替代。每幅关键图
的正文解读依次覆盖以下功能：

1. 说明这是一张什么图，给出了哪些对象或变量之间的关系；
2. 描述图中可直接观察到的趋势、差异、拐点、聚类或空间现象；
3. 由该现象推出与题目有关的结论，并说明推断边界；
4. 必要时总结该图对方案选择、风险识别或决策实施的作用。

不要求机械凑足四句话，但不得从“图给出了什么”直接跳到结论而省略现象证据，也不得
只重复坐标轴、图例或表中数值。表格同样应先说明比较对象，再解释关键差异和决策含义。

## 图像与表格三组审计

先从全稿检查是否缺少必要图表及载体是否选对，再让每幅图和每张表分别通过“内容”与
“质量”审计。三组独立判定，不能用高清、美观或排版整齐掩盖内容错误，也不能以数值
正确为由接受最终尺寸下不可读或表达形式不合适的载体。

### 0. 完整性与载体选择

- 从题目任务、关键模型结构、主要结果、方案清单、空间关系、趋势、分布、阈值和权衡
  反向建立“需要被读者看见的信息”清单，检查是否存在应该图示或列表却只藏在正文、
  公式、代码或内部文件中的关键信息；
- 检查每项主要结论是否至少有一种合适的可见证据载体，但不要求每条结论机械配图；
- 小规模精确数值、完整方案、逐项查询和多字段对照优先用表；空间拓扑、路径、趋势、
  分布、阈值、聚类和多变量权衡优先用图；单一数字或简单结论优先用正文；
- 已有表格若主要任务是让读者发现趋势、空间结构或权衡，应评估改图或增加非重复图；
  已有图像若读者需要精确查询完整数值或执行清单，应评估改表或增加非重复表；
- 若图和表同时保留，分别写明不可替代职责；不得用同一数据的完整重复展示制造
  “证据更多”的假象；
- 记录决定不增加图表的理由，例如关系足够简单、正文一句即可说明、数据不足以支持
  可视化，或新增载体只会重复现有证据。

### A. 内容与证据功能

- 明确它回答哪个问题、支持哪条正文声明，以及为什么需要用图或表表达；
- 数据、对象集合、筛选条件、方案版本、单位、舍入和排序与冻结结果一致；
- 图中的点、线、颜色、形状、阈值和面板，或表中的行、列、合计、最优标记和缺失值，
  均有定义且没有漏画、漏列、错配、重复统计或把未选对象画成已选对象；
- 图题、表题、图注、表注和正文对对象、情景、基准、条件、符号及例外的描述一致；
- 可从载体直接观察到的现象确实支持正文结论；相关性、局部案例或单一情景不得被
  外推为因果、整体规律或无条件结论；
- 与相邻正文及其他图表执行双向删除检验：删除该图表会损失必要证据，删除相邻载体
  也不会发现二者只是完整重复；
- 表格用于精确查询或完整清单时，检查是否真的完整；图像用于空间、趋势、分布、
  阈值或机制时，检查其编码是否足以显现该结构。

### B. 呈现与技术质量

- 图像文件未模糊、拉伸、裁切或压缩失真；线图优先矢量，位图分辨率与最终印刷尺寸
  匹配；
- 最终PDF尺寸下文字、线宽、标记和注释清晰，标签、引线、图例和数据不碰撞、不遮挡；
- 表格列宽、对齐、小数位、单位、换行和表注可读，无越界、截断、过密、跨页断裂或
  难以追踪的超长行；
- 图表标题、编号、引用、浮动顺序和首次提及位置一致，不造成无意义整页占用、大块
  空白、孤行或标题被挤出；
- 全篇颜色、形状、线型、字体、字号、单位、面板编号和小数精度语义一致；
- 灰度、低对比显示和普通打印下仍能依靠形状、线型、明度、标签或表格结构识别重点。

## 三轮视觉审计

### 第一轮：独立图件

逐图查看 PDF/PNG：

- 标签、节点编号、引线是否重叠；
- 图例是否遮挡数据；
- 线条是否被节点完全覆盖；
- 坐标、单位、面板标号是否一致；
- 背景信息是否压过关键结果；
- 关键结论能否在数秒内定位。

### 第二轮：最终 PDF 页内尺寸

编译论文并把含图页面渲染为 PNG，逐页检查：

- 缩印后最小文字和细线是否仍可见；
- 图题、图注、首次实质引用和图后解释是否形成连续局部闭环；
- 图表组合是否造成整页压迫或大块空白；
- 浮动顺序是否与正文叙事一致；
- 页面底部是否出现孤行、孤字或被挤出的标题。

### 第三轮：退化与可访问性

- 转为灰度查看关键系列是否仍可辨认；
- 检查低对比显示器和普通打印条件；
- 颜色相近时增加标记形状、实虚线或空心/实心差异；
- 彩色文字尽量避免，标签优先用黑色或深灰。

发现问题后必须重新生成图、重新编译并再次查看最终页面，不能以“脚本无报错”代替视觉验收。

表格不因没有独立图像文件而跳过三轮检查：先核对表格源数据和内容，再在最终PDF中
检查列宽、换行、对齐、分页、表注和邻接正文。若表格由LaTeX直接生成，以最终PDF页
为质量验收对象。

## 可追溯性

每幅图在生成脚本或图像清单中记录：

- 支持的论文主张；
- 来源 JSON/NPZ；
- 生成脚本；
- PDF 与 PNG 路径。

共享绘图样式属于运行依赖；若论文附录要求提供完整源码，必须同时嵌入该样式文件。

# 图表、LaTeX 与页面专项规则

## V-01 模板

服从当届官方规范和用户确认模板。当前基线为中文正文宋体小四、英文数字 Times New
Roman、单倍行距；题目黑体三号居中；一级标题黑体四号居中；二至四级标题黑体小四。
不得靠缩字号、行距、页边距或标题间距掩盖内容和分页问题。

结构性重写先列无标题的逻辑提纲，再把真实的并列、从属和依赖关系映射为标题；不得先
套“模型建立—模型求解—结果分析”模板再塞内容。标题既导航也预告本节实质机制，但
不得写成宣传语、完整结论或术语清单。隐藏正文只读标题时，应能辨认原题各项任务入口
和推进顺序。

建立“摘要主要方法或亮点—正文标题或首句—公式、结果或检验证据”映射。只有本节确有
独特机制、约束、证明、反事实、阈值或权衡时才在标题预告；普通组织性章节可保留普通
标题，不为显得创新把所有标题改成宣传语，也不增加只有一个子项的空层级。

## V-02 字体可用性与验证门禁

字体要求描述的是排版角色，不等于任意运行环境都安装了同名字体。首次编译、迁移机器、
切换操作系统或更换 TeX 环境后，必须先查询编译器实际运行环境可见的中文衬线、中文
无衬线和西文衬线字体，再显式设置正文、标题与英文数字字体；不得依赖文档类按操作系统
名称自动猜测字体，也不得把宿主系统“看得见”误当成 WSL、容器或远程编译器可调用。

- 精确模板字体可用时，使用经查询确认的字体族名；
- 精确字体不可用但当前成果允许工程替代时，中文正文采用字形完整的宋体类衬线字体，
  标题采用黑体类无衬线字体，英文数字采用 Times 兼容衬线字体；记录“要求字体—
  实际字体—替代理由—适用范围”，并明确该结果不等于精确模板合规；
- 精确字体是交付硬条件时，不得静默替代，必须停止正式交付并报告缺失字体；
- 全文编译前先用包含中文标题、中文正文、英文、数字、标点和数学公式的最小样张检查
  字形。字体加载错误、中文缺字警告、中文被西文字体代打或不可见均视为编译失败；
- 生成 PDF 后使用 `pdffonts` 或等价工具核对预期字体已嵌入或子集嵌入，并目视检查
  代表页面。源码中的字体声明、编译退出码和“生成了 PDF”都不能单独证明字体正确。

### V-03 环境探测

第一次编译或环境变化后，先确认实际 `xelatex` 的路径与版本，再按该程序所在环境检查
字体。Linux 原生环境可用 `fc-list`、`fc-match`，TeX 随附字体可用 `kpsewhich`；
Windows 环境检查系统字体目录和字体注册情况。用查询或文件检查证实的字体族名，不凭
经验拼写。

若 WSL 调用的实际是 Windows 版 XeLaTeX，Linux `fc-list` 不能完整代表它能使用的
字体。此时同时检查 `/mnt/c/Windows/Fonts/` 中的文件，并可通过
`Path=C:/Windows/Fonts/` 与具体文件名显式加载。显式路径优先于依赖 `ctex` 自动发现
Windows 字体，因为后者可能受注册名称和启动环境影响。

### V-04 XeLaTeX 显式设置

重建入口时优先使用 `fontset=none`，通过 `fontspec`/`xeCJK` 显式设置。Windows 字体
文件存在且项目要求精确采用宋体、黑体和 Times New Roman 时，可使用下列结构；具体
文件名必须在当前机器检查，不能未经核验照抄：

```latex
\documentclass[UTF8,fontset=none,12pt,a4paper]{ctexart}
\usepackage{fontspec,xeCJK}
\setmainfont[
  Path=C:/Windows/Fonts/,
  UprightFont=times.ttf,
  BoldFont=timesbd.ttf,
  ItalicFont=timesi.ttf,
  BoldItalicFont=timesbi.ttf
]{Times New Roman}
\setCJKmainfont[
  Path=C:/Windows/Fonts/,
  UprightFont=simsun.ttc,
  BoldFont=simhei.ttf
]{SimSun}
\setCJKsansfont[
  Path=C:/Windows/Fonts/,
  UprightFont=simhei.ttf,
  BoldFont=simhei.ttf
]{SimHei}
```

使用 `fontset=none` 后，若正文或标题调用 `\songti`、`\heiti` 等 `ctex` 字体族命令，
还必须用 `\setCJKfamilyfont` 为相应 family 建立显式映射，并以 `\newcommand` 或适合
当前文档类的方式定义命令；不得只设置 main/sans font 后假定这些命令自然有效。

### V-05 替代层级与记录

1. 精确模板字体可用时采用精确字体；
2. 精确字体不可用但当前草稿允许工程替代时，采用字形完整、角色相符且实测可用的
   宋体类、黑体类和 Times 兼容字体，并记录“要求字体—实际字体—替代理由—影响与
   适用范围”；Fandol 或 Noto 只能作为候选，不能未经实测自动选用；
3. 精确字体属于正式交付硬条件且不可用时，停止正式交付并报告安装需求。

### V-06 最小样张与 PDF 验收

全文编译前先编译一页样张，至少包含中文题目、各级标题、正文、全角/半角标点、英文、
数字、单位、行内与展示公式、粗体、斜体和题注。`fontspec`/`xeCJK` 加载错误、
`Missing character`、中文被西文字体代打、空白方框或不可见字符均为硬失败。

全文双编后必须同时：

1. 检查完整日志中的字体错误、缺字、未定义引用和越界盒；
2. 用 `pdffonts` 或等价工具核对中文正文、中文标题、英文和数字字体已实际嵌入或
   子集嵌入；
3. 逐页目视检查，并重点放大首页、正文密集页、公式页、图表题注和参考文献页；
4. 保存字体映射、检查命令、结果和未满足的精确合规边界。

只有字体可加载、无缺字、PDF 实际嵌入且页面显示正确同时成立，字体门禁才通过。

## V-07 图表选择

- 精确查询和完整比较优先表格；
- 趋势、分布、结构和权衡优先图；
- 一两项简单数字直接写正文；
- 每张图表只承担一个主要信息职责；
- 图题说明对象、条件和单位，图后正文解释发现及题目作用。

图像使用色觉友好配色，并以形状、线型或标签提供冗余编码；最终尺寸下文字、坐标和
图例清晰。禁止装饰性背景和无意义三维效果。

同一主张原则上只有一个主载体。表用于完整查询，图用于趋势、分布、例外和权衡；若
正文声称覆盖全部配方、条件或方案，主载体必须让读者实际看见这一覆盖，不能只展示
少数代表案例并把完整证据藏在内部文件。多面板图在最终页尺寸下任一面板无法快速读取
时，必须拆分、改用表格或重新设计，不能以源图高清为由放行。

图表必须通过三层检查：

1. 全文层：题目要求和关键主张是否都有合适载体，图、表和正文的分工是否必要；
2. 单件层：数据、单位、比较对象、视觉编码和图题是否正确，是否承担唯一信息职责；
3. 渲染层：最终 PDF 中字号、线宽、颜色、图例、裁切、留白和灰度可辨性是否合格。

任一层通过都不能替代另外两层。

### V-08 图表内容闭环

每幅关键图表在正文中依次完成：

`首次实质引用 → 图表 → 可直接观察的关系或现象 → 本问结论 → 必要决策作用与边界`

图注只说明对象、变量、条件和编码，不能代替正文分析。不得从坐标轴或图例直接跳到
结论，也不得把相关、局部案例或单一情景外推为因果或整体规律。图与表同时保留时，正文
明确表负责精确查询、图负责趋势、分布、例外或权衡；双向删除后若信息无损，视为重复。

### V-09 Nature 图件与退化检查

正式图件遵守已经确认采用的 Nature Research Figure Guide：

- 线图、结构图和文字优先矢量 PDF/EPS；照片类位图在最终尺寸至少 300 dpi，不用插值
  放大冒充分辨率；
- 图内英文和数字优先 Arial/Helvetica，普通图中文字原则上为最终尺寸 5--7 pt；
  多面板标号使用 8 pt、粗体、正体、小写字母；
- 坐标写明变量和单位，图例无装饰边框，图题只放 LaTeX 题注；
- 颜色具有数据语义，并同时使用形状、线型、明度或标签，不使用彩虹色阶、红绿唯一
  对照、三维效果、渐变、阴影和装饰背景；
- 同一对象在全文保持相同颜色、符号、线型、单位和图例顺序。

逐图、逐表执行三轮验收：

1. 独立检查数据、标签、图例、遮挡、裁切、单位、表格列宽与小数位；
2. 在最终 PDF 实际尺寸逐页检查最小文字、细线、表格换行、引用—载体—解释的邻接、
   留白、孤题和浮动；
3. 检查灰度、低对比和普通打印下是否仍可凭冗余编码辨认。

修复后必须重新生成、编译并复查当前页与相邻页；源图高清或脚本无报错不能替代验收。

每幅图表登记所回答任务、支持声明、数据或模型来源、生成方式、正文引用位置和当前
版本。数据图追溯到冻结数据与脚本；流程图、机制图和结构图追溯到明确公式、拓扑或
设计定义。手工绘制不免除来源与版本登记。

## V-10 LaTeX 源边界

正式论文只保留一个 LaTeX 主入口；不得建立 Word、Markdown 或另一份 LaTeX 作为竞争
主稿。`.tex` 不得残留 Markdown 标题、强调、链接、管道表格或围栏代码；项目 Markdown
不得混入用作正文结构的 LaTeX 命令和数学定界符。编译成功不能证明源格式边界正确。

草稿的非正式标识、正式入口隔离与人工升级门禁只执行
`29-governance-acceptance.md`，本文件不重复规定。

## V-11 浮动与分页

图表放在首次实质引用之后，并与解释保持局部闭环。出现大块留白、标题孤行、图表漂移、
图表或单条文献无意义独占页时，先定位原因。未经用户确认，不得擅自删改必要文字、
调整字体、行距、页边距、标题间距、图表顺序或浮动规则；可先尝试在保持清晰度前提下
调整图像显示尺寸。

## V-12 编译检查

使用唯一草稿入口双编至引用稳定。检查错误、未定义引用、越界盒、页数和输出文件，并
逐页目视检查字体、标题、表格、公式、图像、留白、分页和参考文献。日志通过不能替代
视觉检查。

出现摘要超页、关键词跨页、正文超限、标题或句子孤悬、半页留白和图表漂移时，先报告
具体页面、原因和受影响内容。除保持图件完整且仍清晰的显示尺寸调整外，删除、压缩、
合并或改写文字，以及改变字号、字体、行距、字距、页边距、段距、标题间距、分页、
图表顺序和浮动参数，均须取得用户对具体方案的确认。

# Visuals, LaTeX, and layout quality

Apply this file only when the controller permits figure or delivery work.

## Visual evidence

- Give every figure or table a named task, supported claim, source, producer, manuscript location,
  and current status.
- Choose a visual only when it communicates a relationship better than concise prose or a table.
- Show the comparison object, metric, baseline, units, direction, uncertainty or boundary needed to
  interpret the claim.
- Explain the visual in the body; do not use “as shown” as the argument.
- Avoid redundant figures competing for the same conclusion.

## Technical quality

- Use consistent fonts, sizes, colors, symbols, units, precision, terminology, and panel labels.
- Test legibility at final page size, not only as a standalone image.
- Check grayscale, color-vision robustness, marker or line redundancy, and dense-label collisions.
- Prefer vector output for line work and adequate-resolution raster output where appropriate.

## LaTeX and PDF

- Follow the current official template first.
- Probe font availability and compile a minimal sample before committing to a font configuration.
- Keep LaTeX commands outside prose and preserve source syntax boundaries.
- Compile from a clean-enough state and inspect warnings, missing references, fonts, metadata, page
  count, and file size.
- Visually inspect every affected PDF page for clipping, blank pages, overflow, tiny figures,
  broken formulas, bad float placement, inconsistent headers, and excessive whitespace.
- Never repair pagination by silently deleting necessary evidence or shrinking text below acceptable
  readability.

# 数学建模论文科研绘图与工程制图规则

本规则只规定控制器已经授权的图件工作如何实施和验收，不能自行批准模型、公式、结果、
论文改稿或正式发布。它补充 `04-figure-generator.md`、`27-visual-layout-acceptance.md` 和
`34-visuals-minimum.md`，不削弱其中任何内容。

## 1. 先确定图件的信息职责

绘图前建立图件任务卡，至少记录：

- 原题中的对应任务；
- 图要帮助评委看见的关系、机制、趋势、分布、空间结构、权衡或例外；
- 支持的正文声明及其成立条件；
- 数据、公式、拓扑、方案或设计定义的权威来源；
- 为什么图优于一句正文或一张表；
- 与相邻图表不可替代的职责；
- 预期正文位置、最终栏宽和输出格式。

若删除该图不损失必要信息，或图只能重复正文与表格，默认不画。不得用增加图数代替增加
证据密度；也不得把关键结构、完整方案、阈值或权衡长期藏在文字、代码和内部文件中。

## 2. 真实性映射门

结构图、机构图、受力图、机理图和流程图在出图前必须建立：

`题面对象 → 几何/拓扑关系 → 数学变量 → 作用或信息流 → 图中元素`

映射表逐项记录来源页、原题图、附件、冻结公式或设计定义。必须先核对原题原图及文字，
再用公式检查作用方向和符号。公式可以约束动力学关系，但不能唯一确定题面未写明的外壳、
安装、铰接、支承和连接几何；不得用领域常见装置或生成模型先验补全这些事实。

受力图另行检查：

- 分离体、坐标系、正方向和参考状态明确；
- 每个力或力矩都有施力者、受力者、作用方向和符号约定；
- 内力在不同分离体上等大反向；
- 重力、静浮力等若因静平衡消去，应明确采用动态平衡坐标，不能一面省略一面保留；
- 图中箭头与最终方程逐项双向核对，不靠“看起来合理”放行。

真实性映射未闭合时，只能制作标有待核项的内部草图，不能美化、准入论文或据图怀疑已经
冻结的公式。发现结构图与公式不一致时，先判断是几何解释错误、符号约定错误还是模型层
错误，并按控制器回退到最早受影响状态。

## 3. 按图类选择表达范式

### 3.1 工程结构、剖面与受力图

- 默认白底、黑线或深灰线，采用工程制图的线宽层级；
- 可见轮廓用粗实线，内部构件和引线用细实线，轴线用细点画线，剖切实体用一致斜线；
- 不使用卡片、渐变、阴影、拟物高光、装饰性海水填充或儿童插画式配色；
- 保持轴对称、共轴、铰接、固定、接触和穿设关系在几何上可读；
- 引出线先留水平着陆段，再指向唯一对象；标签不压线、不跨对象；
- 受力箭头与其标签形成一一对应，避免用颜色承担方向语义；
- 若不是按比例工程图，应写明“示意”或通过图注限制几何推断。

### 3.2 模型机理、流程和算法图

- 节点只写短标签，长解释放图注或正文；
- 箭头只表示明确的因果、依赖、数据流或迭代方向，不用无语义连接线装饰；
- 分支条件、循环停止条件、输入和输出必须可回放；
- 结构忠实于实际求解流程，不把普通流水线包装成虚构的新算法。

### 3.3 数据、结果与优化图

- 先选比较对象、基准、度量、单位、方向和不确定性，再选图形；
- 时间响应优先折线或相图，分布优先箱线/小提琴/经验分布，参数扫描优先曲线或等值图，
  多目标权衡优先帕累托图，空间关系优先坐标或拓扑图；
- 不使用无意义三维柱图、饼图堆叠、双纵轴或彩虹色阶；确有必要时记录不可替代理由；
- 误差带、置信区间、可行域、阈值和基准线必须说明来源与含义；
- 不用平滑、截轴、面积、颜色饱和度或透视制造超过数据证据的差异。

## 4. 视觉系统

同一论文先建立共享样式，再画单图。至少冻结：字体角色、最终字号、线宽层级、标记大小、
面板编号、颜色语义、线型、单位格式、有效数字和图例顺序。

- 普通科研图优先简洁二维表达；网格线只在帮助读数时保留并明显弱于数据；
- 黑色正文标签优先，颜色只编码数据语义；同一对象跨图保持相同编码；
- 颜色必须有形状、线型、明度、标签或位置冗余，灰度打印仍可辨；
- 图内不放论文式大标题和完整结论句，标题交给 LaTeX `caption`；
- 数学变量使用真正的上下标、希腊字母和点号，不以 `m_f` 等代码字符串冒充排版；
- 多面板共享尺度、边距、字体和面板字母位置；面板之间只保留必要分隔；
- 最终栏宽下确定字号和线宽，不以放大查看源图清晰作为验收依据。

参考优秀论文或外部规范时，提取的是信息层级、比较设计、标注密度和视觉系统，不照搬其
数据、结论或装饰。外部样式不能覆盖题面事实、官方模板和当前项目术语。

## 5. 工具选择与可复现性

- 数值曲线、统计图和参数图优先 Python/Matplotlib；
- 精确节点布局、工程剖面和复杂标注优先可编程 SVG，必要时使用 CAD 或矢量编辑器；
- LaTeX/TikZ 只在字体一致性和构图复杂度适合时使用；
- 生成式位图只用于不承载精确几何、数值或拓扑的装饰性素材，不能生成受力图、工程图、
  数据图或需要逐项核验的科学证据；
- 手工软件可作末端微调，但必须保存源文件并记录不可由代码重现的操作。

每幅正式图至少保存可复现源码或可编辑源文件、矢量 PDF/SVG 和审阅用 PNG。照片、遥感
影像等天然位图例外，但要保留原始分辨率和处理链。生成脚本从项目根解析路径，不依赖
个人桌面、临时目录或隐含工作目录。

## 6. 样板门与准入门

新图类或新视觉系统先制作一张高风险代表性样板。样板顺序固定为：

1. 核对内容与真实性映射；
2. 核对图类和信息职责；
3. 核对视觉层级与最终尺寸；
4. 核对灰度、低对比和普通打印；
5. 获得用户对技术含义和审美的明确批准；
6. 才能批量扩展或准入项目。

“好看”不能批准内容错误，“正确”也不能批准最终尺寸下难读的图。候选图在外部目录通过
后，准入项目仍是一次独立变更：保留不同文件名，重新由项目内源码生成，验证后再决定
是否替换论文引用。不得把“准入项目目录”默认为“替换正文现图”。

## 7. 自动检查与人工检查边界

项目提供 `scripts/validate_figure_assets.py` 检查文件配套、SVG 基础结构、PNG 像素、PDF
页面与字体等机械条件。自动检查不能判断拓扑是否忠于原题、力是否正确、数据是否支持
结论、标签是否真正拥挤或图是否美观。

每次图件变更仍须人工完成：独立图件目视检查、最终 PDF 页内检查、灰度/低对比退化检查，
并记录发现的问题、修复和复检结果。自动通过与脚本无报错都不能替代这三轮验收。

## 8. 图件登记与论文闭环

每幅准入图登记：图件 ID、信息职责、支持声明、来源、映射表、生成器、输出文件、版本、
正文位置、题注状态、人工验收状态和未决问题。

论文中形成：

`首次实质引用 → 图件 → 可直接观察的关系 → 本问结论 → 条件或边界`

图注说明对象、条件、变量和编码；正文解释现象及其意义。外部规范给出的论文结构和信息
组织也要经过当前任务、数据与冻结模型核对，不能只模仿单图样式。

## 9. 题面工程图复原与像素验收

涉及题面装置、安装关系、运动自由度或局部机构时，必须先从原题 PDF 原生提取对应图片，
分别核对总体图、正反视图、侧视图和局部放大图。不得只凭题面缩略图、论文转述、领域常识
或上一版草图决定视角。若一个投影面不能同时说明两组正交安装关系，拆成“主几何图＋局部
结构图”，不要把全部构件、箭头和说明压进一张图。

绘图前冻结符号合同：每个图中变量直接采用当前论文正文的权威符号、下标和角度定义；同一
符号不得在图和正文中表示不同物理量，也不得用一段映射文字补救两套符号。角度圆弧必须以
真实转角顶点为圆心，位于两条对应参考线之间，并与刚体姿态方向一致。质心、铰点和连接点
的字母、点位、引线终点及正文定义逐项核对。

主图只承担一个主要职责。几何主图优先保留外轮廓、关键点、参考轴和自由度；弹簧、阻尼器、
转轴架等内部结构若在最终尺寸下互相遮挡，转移到与题面一致的局部视图。图内只保留短标签
和符号，公式、长解释和符号换算放正文。引线必须指向唯一对象；组合标签若包含多个元件，
必须分别指向各元件，或改由局部图完整表达。

箭头大小按所附短线和圆弧长度确定，不能使用统一的大箭头头部遮住大部分运动线。完成 SVG
后必须渲染最终交付尺寸的 PNG，并以该 PNG 而非源坐标或放大视图验收。至少记录并检查：

- 画布像素尺寸及 SVG 到 PNG 的横纵缩放比例；
- 角度圆弧端点到对应参考轴同高或同半径位置的像素偏差；
- 标签锚点到目标、引线终点到目标边界的像素距离；
- 关键元件在最终 PNG 中的可见包围盒；
- 文字、箭头头部、短线、轮廓、虚线和引线是否发生实际像素相交或形成伪符号。
