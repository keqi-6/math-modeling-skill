# V9 恢复、接手与闭合治理

## 权威边界

`.modeling/state.json` 是项目状态的唯一机器事实源。聊天摘要、旧回执、文件修改时间和任务标题只能提供线索，不能单独证明状态。只读咨询没有项目状态要求，也不得为恢复而创建文件。

## R0：直接继续

满足以下全部条件时使用：状态结构有效；当前组件和下一动作明确；登记的正式产物存在且身份一致；没有未解释的外部变化；当前请求未要求里程碑或完整审计。

R0 读取状态、当前目标、下一动作、开放决定和直接输入即可。不得全文复读，不生成恢复清单文件。

## R1：定向恢复

状态有效但存在可定位变化时使用。计算变化集合，沿显式消费者关系向前扩展一层，重读变化文件、对应组件证据和直接消费者。更新状态前记录哪些事实被确认、哪些状态回退、哪些产物需要重算。

不得因为一个局部文件变化而默认审计整个项目。只有依赖关系无法定位时升级 R2。

## R2：完整恢复

以下任一条件触发：权威状态缺失或无效；项目或数据身份冲突；核心产物变化无法定位；用户明确要求完整恢复；里程碑或最终闭合需要全局证明。

R2 顺序：确认授权与根目录；盘点题目、数据、状态、代码、结果、论文和交付物；重建组件与消费者关系；核对冻结决策；运行相关验证；生成恢复结论；只在用户授权的写任务中更新状态。

R2 是证据恢复，不是机械地把所有文本塞入同一上下文。可分批读取，但最终必须覆盖所有必需对象并留下覆盖证据。

## 暂停与收尾

普通暂停只更新权威状态中的实际变化、开放问题、下一合法动作和已登记产物身份。里程碑或最终闭合还要执行全局消费者复核。自然语言总结不得夸大未完成验证。

状态一致性由 `scripts/assess_recovery.py` 检查；恢复级别的机器条件由 `references/state-contract.json` 唯一定义。
