# 建模方法提示（非规范性）

本文件帮助形成候选和实现细节，不拥有方法选择权。选择仍需满足当前原子的比较、规格和证据要求。

## 候选族快速索引

| 问题结构 | 常见基线 | 可扩展候选 | 主要失效风险 |
|---|---|---|---|
| 预测与时间序列 | 季节朴素、线性趋势 | ARIMA、状态空间、树模型、序列网络 | 时间泄漏、结构突变、区间失真 |
| 分类或回归 | 线性/逻辑回归 | 树集成、核方法、神经网络 | 分布漂移、类别不平衡、校准不足 |
| 离散优化 | 贪心、线性松弛 | MILP、动态规划、局部搜索、元启发式 | 不可行、最优性缺口、尺度爆炸 |
| 连续优化 | 可行常数方案、梯度法 | SQP、内点法、全局搜索 | 局部最优、病态尺度、约束残差 |
| 网络与路径 | BFS/Dijkstra、中心性 | 流、匹配、多层网络、时变图 | 边权含义错误、连通假设失效 |
| 动力系统 | 平衡态、线性化 | ODE/PDE、差分方程、状态估计 | 参数不可识别、刚性、边界条件错误 |
| 排队与随机过程 | 均值近似 | 马尔可夫链、排队网络、离散事件仿真 | 稳态未到达、随机误差、相关到达 |
| 空间问题 | 最近邻、网格统计 | 选址、空间回归、点过程、元胞模型 | 坐标系、边界效应、空间泄漏 |
| 多指标决策 | 等权评分 | AHP/熵权、TOPSIS、Pareto、多属性效用 | 权重脆弱、尺度重复、补偿性假设 |

候选表不是方法菜单。先用数据、机制、目标和计算预算淘汰不适用项，再在同一证据条件下比较保留下来的方案。

## restatement-and-redesign

题意重述至少区分对象、变量、约束、目标和要求输出。对象说明符号属于哪个实体或系统；输出说明最终量、格式、单位和验收含义。这样可避免用现成算法反向定义问题。

S4 之后的重新设计不是普通措辞修订。它涉及冻结规格及其消费者，应由共享状态机定义合法重开：变更获授权、依赖消费者失效、组件回到候选比较阶段，再重新形成问题定义和规格。规则原子表达这项义务；合法迁移仍由 state-machine contract 拥有。

## specification

一份可实现规格通常能逐项回答：变量和集合是什么；目标或状态方程是什么；硬约束是什么；参数从哪里来；初始与边界条件是什么；算法如何初始化、停止、报告失败；输出指标和单位是什么。随机方法还要给出种子策略和重复次数依据。

假设需要绑定版本化规格身份，而不只是列在候选比较表里。输入/输出接口还应区分含义、形状、类型、单位和失败信号；实施门禁核销的是整份无歧义冻结规格，不是“存在一个规格文件”。

## implementation

实现可按“输入解析—规格实例化—求解—结果校验—输出登记”分层，使 E1/E2 能独立触达。小规模可解析实例、固定种子用例和已知不可行实例常比单纯增加代码覆盖率更能发现建模错误。

运行应明确属于确定性执行，或属于已声明的随机执行。后者保留种子、重复策略和波动摘要。正式输出应有可打开的载体、schema、单位、哈希和运行身份；终端中短暂出现的数字不构成 inspectable output。

## results

结果解释可分三层：直接计算事实、模型内部含义、现实外推。每上升一层都需要额外证据。汇总时保留失败运行、容差、稳定范围和与基线的差异，避免只展示最优一次运行。

一项解释的最小 trace 可以写成 `result_id -> question_id -> baseline comparison -> material limitations`。这条 trace 约束解释与主张；尚未解释的原始输出仍可登记，但不能用数字列表代替回答。
