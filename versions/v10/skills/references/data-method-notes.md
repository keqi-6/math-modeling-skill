# 数据方法提示（非规范性）

这里只列出诊断和处理选项；当前规则原子决定哪些检查适用、哪些证据能通过状态门。

## 审计视角

| 风险 | 可观察信号 | 常见检查 |
|---|---|---|
| 身份错误 | 文件同名、版本混用 | 哈希、行列数、模式签名 |
| 结构错误 | 类型漂移、键不唯一 | schema、主键重复、枚举范围 |
| 缺失偏差 | 缺失集中于特定群体或时间 | 分组缺失率、缺失相关性 |
| 异常值 | 极端量级、物理边界违反 | 稳健统计、领域阈值、轨迹检查 |
| 口径冲突 | 单位、时区、行政区划不同 | 元数据核对、单位换算验证 |
| 泄漏 | 未来信息或同一实体跨划分 | 时间截断、group split、特征审计 |
| 抽样偏差 | 覆盖不足或选择机制变化 | 总体对比、时间覆盖、权重检查 |

## identity-before-use

“身份就绪”与“已经读到文件”不是一回事。前者把实际输入绑定到来源、schema、单位、时空口径和不可变原始身份；只有在路由真实消费数据时才有意义。纯符号推导或不读取数据的写作动作可以形成明确的 not-applicable 判定，但不能因文件名熟悉而省略身份核对。

该门禁的 enforcement 是 `agent_obligation / selection_verified`：路由器能证明原子被选中，不能单独证明六项证据真实存在或发生在首次数据读取之前。项目状态和证据记录仍需给出可核验的身份与时间顺序。

## completeness-and-semantics

完整性、缺失性和结构合法性是三个不同问题：完整性比较“应有总体/时期/对象/字段”与实际覆盖；缺失性分析已存在记录中的空值；schema 检查形状、类型、键和范围。语义一致性再核对同名字段、单位、编码、业务键和时空含义是否一致。某一层通过不能替代另一层。

## treatment

缺失处理可比较完整案例、规则插补、统计插补、模型插补和显式缺失指示；异常处理可比较保留、截尾、稳健损失、分层模型和基于领域规则的修正。选择依据应包括对目标指标、偏差、方差、可解释性和后续消费者的影响。

处理流程宜从不可变原始输入生成新候选。转换记录至少能回答：用了哪个输入、执行了什么、参数是什么、产生了哪个输出。

审计证据应绑定处理前的输入身份。若先删除、插补或转换，再用处理后数据回填“原始审计”，就无法观察处理所针对的问题，也无法证明审计先于 treatment。

## freeze

冻结前可复算模式签名、关键统计、约束、泄漏检查和处理决定。冻结身份改变时，模型运行、图表和稿件数值可能都成为消费者，应通过依赖图传播失效。
