# 17 — 读者优先的论文结构与逐句审计

## 职责与强度

本文件把论文中的章节完整性、首次术语解释、白话可复述性、数据解释和失败回退转化为
不可跳过的执行门。它不替代 `03-paper-content-rules.md` 的写作规范，也不替代
`05-audit-protocol.md` 的证据审计；它负责阻止“规则已经写到但实际没有执行”的情况。

以下均为 B 级质量硬门；涉及题意真实性、数值身份、正式稿批准边界的条款为 A 级：

- 结构门通过前不得进入逐句润色；
- 任何未就近解释的必要术语都会使当前段落失败；
- 机器复算、编译成功和版面正常不能替代表达通过；
- 结构性失败必须使受影响的下游通过状态失效；
- 未经负责人完成人工审计，不得把草稿升级为正式论文。

## 1. 完整阅读证明

声称“完整阅读 Skill”前，必须为全部适用文件记录：

| 字段 | 要求 |
|---|---|
| 文件 | 实际读取的规范文件路径 |
| SHA-256 | 当前文件内容哈希 |
| 总行数 | 机器统计的精确行数 |
| 已读范围 | 无遗漏、无重叠地覆盖第1行至末行 |
| 完成状态 | `complete` 或 `incomplete` |

工具输出出现 `truncated` 时，该次读取不得用于证明被截掉的行已经阅读。必须缩小行段并
继续读取，直至每段输出完整。导航摘要、聊天总结、搜索命中和旧审计记录不能替代原文
阅读。任一适用文件仍为 `incomplete` 时，不得对外声称完整阅读或完整 Skill 审计。

## 2. 全文结构硬门

逐段、逐句审计前，先隐藏现有文件拆分和历史标题，仅根据题目、官方或已确认模板检查
论文是否具备以下职责：

1. 题目；
2. 摘要；
3. 问题背景；
4. 问题重述；
5. 问题分析；
6. 模型假设；
7. 符号说明；
8. 数据预处理；
9. 每项任务的模型建立、求解、结果解释、验证和直接回答；
10. 模型评价、局限与改进；
11. 结论；
12. 参考文献及适用的附录或声明。

标题不必机械照抄本清单，但每项职责必须能由评审直接定位。尤其区分：

- **问题背景**说明现实对象、研究价值和为什么需要题目中的分析或决策；
- **问题重述**准确整理已知信息、数据结构和待回答任务；
- **问题分析**解释每问的困难、可用信息、方法方向和选择理由；
- **模型章节**才展开变量、公式、参数、求解、结果和检验。

任一必要职责缺失、错位或被其他章节替代时，状态必须为`结构审计失败`。此时禁止沿原
结构继续逐句润色；先重建结构并重新检查摘要、标题、章节衔接和首次术语落点。

## 3. 问题背景最低要求

问题背景至少用普通语言回答：

1. 研究的现实对象是什么；
2. 该对象为什么值得研究；
3. 哪些可控条件会影响题目关心的结果；
4. 题目最终要支持什么分析、选择或实验安排。

背景不得写成行业套话，也不得提前出现本文模型、求解步骤或结果。只定义名词而没有
说明现实意义，不构成问题背景；摘要中出现背景也不能替代正文的背景职责。

## 4. 段落与句组强制审计表

每个自然段或不可拆分的句组必须形成内部记录：

| 字段 | 必答问题 |
|---|---|
| 原句或句组 | 当前实际文本是什么 |
| 章节职责 | 为什么必须出现在这里 |
| 现实对象 | 谁或什么在什么条件下发生变化 |
| 必要术语 | 哪些专业名称确实不能删除 |
| 邻近白话解释 | 不使用该术语时，具体在做什么 |
| 数据身份 | 数字是观测、估计、误差、比例、阈值还是候选值 |
| 数据含义 | 这些数字共同说明什么，并怎样回答题目 |
| 边界 | 该句不能推出什么 |
| 判定 | `pass`、`revise` 或 `fail` |

不得用“其余同理”“后文有定义”“符号表已列出”代替首次实质使用处的解释。局部审计
完成后，必须对修改后的整段重新填写，而不能把数次局部修改的旧记录拼成通过证明。

## 5. 术语首用硬门

术语第一次实质出现时，按以下顺序表达：

`本题对象 → 具体动作 → 怎样判断结果 → 必要时给出规范术语`

逐项执行：

1. 该术语是否影响决策、模型复现或准确引用；若否，改用普通语言；
2. 若必须保留，先说明处理什么对象、怎样处理、输出表示什么；
3. 解释中出现的新术语也必须在同句或紧邻句解释，不能形成术语递归；
4. 遮去术语名称、公式和数字后，剩余文字仍须让普通读者复述做法和结论；
5. 不能通过时，当前段落判为`fail`，不得因数学正确或后文存在定义而放行。

“分层、重采样、非加和、有效自由度、敏感范围、稳健、显著、优化、验证”等词不得
默认视为常识。若保留，必须落到本题对象和实际操作。

## 6. 普通读者复述门

每段修改后，内部补全：

> 这一段实际上是在说：________。

复述句不得依赖原段中的专业名称。它至少应包含：

- 为什么要做；
- 对什么数据或对象怎样做；
- 得到什么判断；
- 该判断对本问有什么作用；
- 不能据此推出什么重要结论。

复述仍含未解释术语、只能说“指标更好”或无法说明题目作用时，原段不得通过。复述是
审计工具，不机械写入论文；论文正文应吸收其中必要的白话解释。

## 7. 数据—解释硬门

关键数字按“结论数据组”而非孤立数字检查：

`身份与条件 → 比较对象或阈值 → 实质判断 → 对题目的作用 → 必要边界`

以下均判为失败：

- 只报数，不回答“这些数据说明什么”；
- 把模型估计写成实验事实；
- 把预测误差写成实验测量误差；
- 把描述比例写成因果贡献率；
- 把当前候选域最大值写成连续域或现实全局最优；
- 用“结果较好、模型有效、较为稳定”代替具体判断。

## 8. 状态机与禁止越级

每个模块只允许使用以下状态：

1. `未读取`；
2. `已读取但未审计`；
3. `结构审计失败`；
4. `逐句审计失败`；
5. `机器核对通过但表达未通过`；
6. `表达与证据均通过，待人工审计`；
7. `人工审计通过`。

禁止使用含糊的“通过”“已完成”“基本合格”。只有第6级可以提交负责人审阅，只有
负责人明确确认后才能进入第7级。代码核对、公式复算、编译、页数、图表清晰度分别只是
证据的一部分，不能单独把状态提升到第6级。

## 9. 失败传播与回退

发现以下任一问题时，撤销受影响模块及其下游的既有通过状态：

- 问题背景、任务或必要章节缺失；
- 核心术语普遍无法由普通读者理解；
- 题意、数据身份、模型口径或结论边界改变；
- 摘要、正文、图表、结论或冻结结果不一致；
- 用户指出的是可泛化缺陷，而非孤立错字。

回退后先修最早出错层，再依次重审结构、章节、段落、证据、版面和摘要双向映射。禁止
只修用户指出的句子后恢复原通过状态。

## 10. 重复错误回归表

项目审计记录必须维护至少以下回归项，并在每次重新编译后复查：

- 问题背景没有缺失或被名词定义替代；
- 问题分析没有塞入公式、参数和具体求解步骤；
- 首次必要术语均有邻近白话解释；
- 每组关键数据均解释其判断与题目作用；
- 摘要保留正文已证实的主要结构性亮点；
- 图表、标题、公式和参考文献没有无意义独占一页；
- 字体、字号、行距和标题层级符合已确认模板；
- 草稿仍明确标记为草稿，且未建立正式论文入口。

用户再次指出已登记的问题时，当前审计自动失败。先说明旧门禁为何没有拦截，再修订
Skill 或检查流程；不得把重复错误仅登记为新的论文错字。

## 11. 交付前最小证据

声称某模块“表达与证据均通过，待人工审计”时，必须同时提供：

- 完整阅读证明；
- 全文结构门结果；
- 当前模块逐段审计表；
- 术语首用清单及白话解释；
- 数字—结论数据组追踪；
- 公式、代码和冻结结果核对；
- 编译日志与受影响页面视觉检查；
- 重复错误回归表；
- 仍待负责人决定的事项。

缺少任一项，只能报告实际完成的较低状态。
