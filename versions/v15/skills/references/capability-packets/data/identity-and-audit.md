# 数据身份、结构与证据能力审计

适用于首次读取数据、接手既有数据接口、检查原始附件或决定数据能支持哪些建模主张。完整读取本包后再消费数据；`rules/data.json` 仍拥有规范效果和通过条件。

来源保留：V8 `16-data-audit-methodology.md`、`30-data-minimum.md`，结合 V10–V14 的 identity、类型化证据和精确失效边界重新组织。

## 身份先于分析

“已经打开文件”不等于“数据身份就绪”。消费数据前至少建立：

- 来源、版本、文件哈希、工作表或页面身份；
- 行列、隐藏/合并结构、编码、时区和区域口径；
- 字段名称、类型、单位、合法域、缺失语义和任务用途；
- 主键、重复键、时间/空间粒度、排序和覆盖范围；
- 原始、结构化、派生、纠正记录和分析设置之间的边界。

原始文件保持只读，保留原始行号、单元格或文字定位。分析设置不能伪装成观测；解析器遇到无法由文件结构唯一判断的内容应显式失败，不静默猜测。

## 先确定统计单位

列出实体、观测、实验单位、重复测量、时间点、空间单元、批次、场景和网络层次，再计算统计量。常见错误包括：

- 把同一实体在多个条件下的记录当作多份独立实体；
- 把一次实验的多个时间点当作独立重复实验；
- 把不平衡组的总体均值写成因素效应；
- 比较没有共同条件或共同支持域的群体；
- 聚合后丢失权重、样本组成和缺测结构。

同一数据需要多个层次时，分别明确主键、消费者和允许支持的主张，不能让一个聚合表承担所有分析。

## 分开六种异常状态

至少区分：真正缺失、结构性不存在、审查/截尾值、合法零值、合理极端值和解析错误。还要区分数据错误、设计边界和未知原因异常。

异常算法只产生候选：记录比较总体、分组依据、样本量、阈值、被标记录和失败条件。高价值、边界或稀有观测不能仅因极端而删除；小组、零方差、单点层次和无重复设计不能包装成可靠异常判定。

## 对账顺序

根据实际风险执行并冻结可复核结果：

1. 文件、工作表、行列、合并/隐藏结构和输入哈希；
2. 类型、单位、范围、合法域和违规数；
3. 主键、重复键、排序、时间间隔、覆盖和采样粒度；
4. 原始与结构化表中保留字段的逐字段不一致数和最大差异；
5. 解析实体的原文定位与充分人工核验；
6. 守恒、闭合、合计、题面公式和至少一个手算样例；
7. 处理前后记录数及每类增删改原因。

摘要统计相等不能替代逐字段对账；主脚本再次读取自己的输出也不是独立证明。

## 数据能支持什么

审计覆盖矩阵、共同条件、重复、因素水平、批次、时间间隔、空间支持和可观测域，并把主张分为关联、受控局部比较、预测、因果效应和机制解释。

- 相关不等于独立效应或因果。
- 不平衡组均值不等于控制其他因素后的差异。
- 最近邻不等于身份。
- 已测最大值不等于连续域或未测条件的最优值。
- 单条纵向序列不等于总体稳定性分布。

明确可识别量、不可识别量、外推边界，以及需要额外实验才能回答的问题。复杂方法之前先建立一个可手检的简单基线。

## 身份线索与相似性

身份未知时，相似性只能提供线索。记录特征集、缩放、距离、候选域、排名间隔和时间/场景差异。确认身份通常还需要直接编号或批次证据、多种合理度量下的稳定唯一候选、相对次优候选的清晰间隔，以及与测量误差和漂移相容。否则只报告“在指定度量下最相似”。

## 审计图

每幅审计图登记：

`数据层次 → 原始/结构化/派生字段 → 质量问题 → 视觉编码 → 精确值载体 → 禁止推断`

覆盖矩阵适合揭示缺测与不平衡，小倍图适合实体内趋势，原始点和分布图展示范围，匹配差异图优于无控制组均值比较。空白、零值和结构性不存在必须使用不同编码。

若清洁过程未改变响应值，不制造完全重合的“前后图”；用对账证明一致，让图展示真正新增的信息。诊断图容易被误读时应加显著边界或仅留作内部审计。

## 输出

根据项目需要保存：数据字典、identity 记录、审计摘要、异常候选、设计/证据能力结论、对账结果和未决处理决定。文件数量不是完成标准；每项输出都应有明确消费者。
