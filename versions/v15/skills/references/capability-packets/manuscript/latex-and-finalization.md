# LaTeX、渲染与终稿收口

适用于当前项目已经选择或要求 LaTeX 时的源稿建设、编译、字体与页面验证、局部版面修复，以及从完整候选 PDF 向正式交付审计的收口。LaTeX 不是所有项目的全局强制格式；当前官方要求或用户指定其他源格式时，服从当前项目合同，只迁移本包中与最终渲染有关的方法。

来源保留：V1 `02-latex-setup.md`、`11-paper-finalizer.md`，V3 V-02–V-06/V-10–V-12 及 V4–V5 render/final 原子。删除陈旧年份、固定字体/页边距/目录断言、固定双编次数、每次排版微调都审批和日常逐页全文检查；保留官方优先、唯一当前源、真实字体探测、编译—渲染分离、局部页面闭包与正式人工发布。

## 何时读取本包

以下情形读取：

- 新建或重构 LaTeX 入口、文档类、preamble 或源码模块；
- 首次编译、迁移机器/容器/操作系统、切换 TeX 环境或更换字体；
- 出现编译错误、引用不稳定、缺字、字体代打、越界盒、浮动漂移或分页异常；
- 修改公式、表格、图件、题注、标题或其他会改变实际页面的内容；
- 进行章节候选、整稿候选或正式交付前的渲染检查。

不改变页面的普通文本读审不要求探测字体环境；修一个局部段落也不自动触发逐页全文目检。审计范围按 V14 的实际修改闭包和候选层级确定。

## 一、先确定排版权威与当前入口

### 1. 权威优先级

建立或改变版式前按以下顺序取值：

1. 当前适用的官方、机构、期刊或赛事明文要求；
2. 用户为本项目明确选择的模板与写作/版式 profile；
3. 项目已经批准且仍兼容前两者的实现；
4. 前三者未规定时，才选择中性、可维护的工程默认值，并明确其不是官方规则。

页数、匿名、文件格式、页面尺寸、字体、字号、行距、页边距、标题层级、参考文献和支撑材料都分别核对，不从样例 DOCX 的隐藏属性、往届论文或个人经验反推硬要求。正式交付时由 [正式交付、提交合规与人类责任](../evidence/final-delivery-and-compliance.md) 重新核验时效性要求；本包不复制会过期的政策和 AI 披露条款。

### 2. 一个当前源入口

当前稿件应有一个可识别的主源入口及其对应构建命令，避免平行 Word、Markdown、旧 LaTeX 或多个可编译入口竞争“哪份是当前稿”。历史来源、草稿和审阅副本可以保留，但必须明确不作为当前正式源消费。

草稿、候选、已批准和已发布身份由 V14 的产物状态与发布机制管理。本包不通过文件名自动批准内容，也不允许因为“编译成功”覆盖已发布版本；修改已发布稿应走合法重开并生成新的工作修订。

### 3. 按稳定职责拆源

短稿保持单文件即可。长稿或多人协作时，只有拆分能降低误放、冲突或维护成本才使用 `\input`、`\include` 或项目等价机制，并按稳定的评审可见职责拆分，而不是按工作阶段、人员或脚本顺序拆分。

唯一入口按最终阅读顺序显式组装。拆分、移动或重命名后检查：

- LaTeX 环境、命令参数和分组没有跨文件断裂；
- 标签、引用、文献、图片和表格路径仍解析到当前对象；
- 章节内容仍属于文件声明的职责；
- 旧入口和旧模块不会被构建脚本或交付白名单误选；
- 受影响章节与相邻交界连续可读。

文件拆分只是维护手段，不能证明论文结构或内容已经通过。

## 二、源格式与编辑安全

`.tex` 中用有效 LaTeX 表达标题、强调、链接、引用、公式、表格和环境。来自 Markdown、Word 或其他格式的内容应显式转换相应结构，并重新核对语义、标签、编号和引用；不得只改扩展名或把 Markdown 标题、围栏代码、管道表格和链接语法留在正文源中。

> 编译成功不能证明源格式边界正确。

编辑时：

- 使用能精确保留反斜杠、花括号和 Unicode 的方式；
- 小范围修改优先使用有上下文的精确补丁，避免无边界全局替换；
- 修改公式、环境、命令定义或引用后检查配对和直接消费者；
- 标签采用稳定的语义命名，不因页码或暂时顺序变化而改义；
- 生成文件、中间文件与作者源分开，不把编译产物当成可维护源；
- 构建命令从明确项目根或稿件目录解析路径，避免依赖调用者当前目录。

搜索 Markdown 残留、未定义命令或可疑字符只能定位候选问题；命中后要按上下文判断，未命中也不能代替编译和渲染检查。

## 三、字体：从实际编译环境验证

字体工作流只在首次建设、环境变化、模板/字体变化或出现字体异常时执行，不在每次正文小改后重复。

### 1. 探测实际环境

先确认实际被调用的编译器路径、版本和运行环境，再在同一环境查询字体。宿主系统看得到某字体，不代表 WSL、容器、远程构建器或另一套 TeX 可以调用；Linux 字体查询也不能自动代表 Windows 编译器的注册与路径。

根据环境使用可验证的字体查询或文件检查，取得真实字体族名和样式，不凭经验拼写。中文论文至少区分正文衬线、标题无衬线和西文/数字衬线等排版角色；具体角色服从当前项目要求。

### 2. 选择精确、替代或停止

- 当前要求的精确字体可用：显式采用并验证；
- 精确字体不可用，但当前草稿或项目允许工程替代：选择字形完整、角色相符且实测可用的字体，说明要求字体、实际字体、替代理由和适用范围；不能把替代稿称为精确合规；
- 精确字体是正式交付硬条件且不可用：停止正式完成声称，报告缺失条件，不静默替代。

字体 fallback 的决定依据当前项目与候选层级，不由某个历史字体清单全局决定。

### 3. 最小样张

在大稿首次使用新字体配置前，编译一页代表性样张，覆盖项目实际需要的中文标题与正文、英文、数字、标点、单位、行内/展示公式、粗斜体和题注。检查：

- 字体加载错误与缺字警告；
- 中文是否被西文字体代打；
- 粗体、斜体和标题角色是否真实生效；
- 数学字体与正文搭配；
- 空白方框、不可见字符和异常字距。

样张失败先修字体配置，不用完整稿反复试错掩盖根因。

### 4. PDF 证据

生成 PDF 后用 `pdffonts` 或等价工具核对预期字体实际嵌入或子集嵌入，并目视代表页面。

> 源码中的字体声明、编译退出码和“生成了 PDF”都不能单独证明字体正确。

字体验收同时需要：可加载、无材料性缺字、PDF 实际嵌入、最终页面显示正确。局部正文修改若未改变字体配置且没有新字符异常，只检查受影响页，不重新执行完整探测。

## 四、构建与日志检查

### 1. 使用项目真实构建方式

从当前唯一入口执行项目规定的引擎或构建器。中文 LaTeX 常使用 XeLaTeX，但具体引擎由文档类、模板和当前要求决定，不把历史实现写成全局强制。

运行足够的轮次使目录、文献和交叉引用稳定；可由 `latexmk` 等构建器管理依赖，也可显式重复编译。不要把固定“两遍”当作所有项目的完成条件：文献工具、索引或复杂引用可能需要更多步骤，纯局部源检查也可能由构建器增量完成。

### 2. 同时检查四类事实

- **过程**：命令退出状态、实际入口、引擎与构建路径；
- **日志**：致命错误、缺失文件/字符、未定义引用/文献、重复标签、越界盒和材料性警告；
- **产物**：PDF 确实来自当前入口，能够打开，页面尺寸与基本元数据合理；
- **稳定性**：再次构建后引用、目录、文献与页面没有继续漂移。

日志搜索只是定位器。警告不能机械按数量判错：区分无害提示、可接受妥协和影响内容/页面的真实缺陷，并记录尚未解决的材料性边界。

## 五、最终页面怎样检查

### 局部修改

查看受影响页面，并在分页、浮动、标题、脚注或跨页表格可能传播时查看必要相邻页。重点确认：

- 改动完整出现，没有乱码、裁切或意外丢字；
- 标题与正文、图表与引用、公式与解释没有被分页切断；
- 字号、行距、缩进、编号和对齐没有局部异常；
- 公式、表格、图例、注释和参考文献在真实页尺寸可读；
- 局部修复没有制造新的空白、孤题、漂移或越界盒。

没有传播迹象时到此结束，不升级为逐页全文审计。

### 章节或整稿候选

章节候选查看该节全部页面及与前后节的交界。整稿、里程碑或发布候选逐页检查：首页/摘要、正文密集页、公式页、图表页、跨页表格、结论、参考文献、附录与最后一页，并确认页码、页眉页脚、匿名信息、页面尺寸和当前要求一致。

检查实际 PDF，而不是编辑器预览的局部截图。独立大图清晰不代表嵌入真实栏宽后可读；源表格正确不代表跨页后表头、单位和行对应关系仍清楚。

## 六、图表、浮动与局部解释闭环

图表内容和视觉语义由 visual 能力包决定；LaTeX 层负责保持它在最终页面中的阅读关系：

`首次实质引用 → 图表 → 可观察现象 → 正文解释与本问落点`

图注说明对象、条件、变量、单位和编码，不能替代正文论证。表格适合精确查询，图适合趋势、结构、分布和权衡；两者并存时在正文说明分工。

浮动体原则：

- 不让图表漂到首次引用之前；
- 不让无关标题或另一图表切断引用—载体—解释；
- 不为固定“图必须原地”而制造大块空白或不可维护结构；
- 优先用语义合理的源码位置、尺寸、浮动参数和屏障解决；
- 每次修复后重新编译，并查看当前页与真实受影响相邻页。

图像显示尺寸可以在保持内容、比例、标注与最终可读性的前提下调整。不能以“源图高清”为由把文字缩到实际页面不可读，也不能裁剪、变形或隐藏证据来解决分页。

## 七、版面冲突的诊断与局部修复

遇到超页、标题孤行、图表漂移、大块留白、表格越界、公式溢出或参考文献异常时，先定位根因，不直接压缩整稿。

按风险从低到高选择最小修复：

1. 修正源语法、错误路径、重复标签、未定义引用和意外空白；
2. 在已批准版式内调整局部断行、表格列宽、公式换行、题注宽度或图像显示尺寸；
3. 调整语义合理的浮动位置、屏障或分页点，并检查引用—载体—解释关系；
4. 调整章节/段落顺序，前提是论证依赖不变；
5. 只有内容确有重复或版面硬限制时，提出删改正文、删图/表或改变官方/profile 参数的候选方案。

前四类若在当前授权和已批准 profile 内、可逆且不改变语义，可直接实施并按局部页面闭包验收，不需要逐项人工门。第五类，或任何会改变证据、主张、官方格式、图表解释和正式身份的动作，必须先由人工确认具体取舍。

不要通过缩小正文字号、行距、页边距或图内文字静默掩盖内容问题；也不要把保持旧页数置于语义正确之上。修复后重新构建和查看受影响页面，不能只看源差异。

## 八、终稿收口

只有当前任务明确进入整稿候选、里程碑或正式交付时执行本节。

1. **确认当前要求**：从现行官方/项目材料核对格式、页数、匿名、引用、文件名、附件与披露；时效规则交 evidence/final-delivery 包处理。
2. **绑定唯一源与 PDF**：确认候选 PDF 来自当前唯一入口和当前图表/文献，不从旧副本或并行格式拼装。
3. **清除未完成项**：查找真实占位符、未定义引用/文献、草稿标记、内部审计语言、错误链接和失效图表；搜索命中必须人工判定上下文。
4. **核对跨载体身份**：摘要、正文、公式、表头图注、结论和支撑材料使用同一结果、单位、舍入和证明强度。
5. **完成最终渲染审计**：逐页检查内容与版面，并记录材料性未决项；日志通过不能替代页面检查。
6. **形成交付候选而非自动发布**：把最终 PDF、源入口、构建方式、适用要求、限制和检查结果交给正式交付包。
7. **人工批准发布**：只有 V14 的相应人工确认与状态迁移完成后才成为正式稿；候选通过编译或审计不自动覆盖正式版本。

当前 AI 政策、赛事年份、期刊声明格式和提交链接具有时效性，不从历史论文规则继承；正式阶段重新取证。

## 九、分层完成标准

不要把以下四个结论混为一谈：

- **源完整**：唯一入口、语法边界、依赖和当前文件身份清楚；
- **构建成功**：真实构建完成，致命错误与未定义引用已处理，产物稳定；
- **渲染通过**：实际范围内页面可读，字体、公式、图表、浮动和分页满足当前要求；
- **正式就绪**：内容、证据、合规、交付白名单和人工发布决定均完成。

前一层是后一层的必要条件之一，但不能替代后一层。局部渲染通过只能支持局部结论；正式就绪必须由完整候选与当前规范共同判断。

## 十、常见失败与修复

| 失败 | 原因 | 修复 |
|---|---|---|
| 宿主机有字体，编译器仍报缺失 | 探测环境错位 | 确认实际引擎，在其运行环境查询/显式加载并重做样张 |
| 自动 fallback 后宣称模板合规 | 精确与工程替代混淆 | 标明替代边界；正式硬条件缺失时停止完成声称 |
| 生成 PDF 就判定通过 | 构建、字体和渲染混淆 | 查日志、嵌入字体、实际页面和产物身份 |
| `.tex` 残留 Markdown 但仍能编译 | 源格式转换不完整 | 显式转换结构并核对语义、引用和编号 |
| 图表离引用很远 | 浮动与源码语义位置冲突 | 调整合理位置/尺寸/参数，重编并检查邻页 |
| 表格/公式靠缩字塞入 | 局部排版掩盖信息设计问题 | 优先重排、换行、拆表或改载体；保证最终尺寸可读 |
| 局部修改后逐页全文检查 | 审计范围过度 | 查看受影响页及有传播迹象的相邻页即可 |
| 为恢复页数静默删句 | 版面越权改变内容 | 恢复语义，提出具体候选及影响，取得人工取舍 |
| 直接覆盖已发布 PDF | 状态与源身份混淆 | 合法重开新工作修订，重新构建、审计和批准 |

## 十一、必要人工确认点

本包不对普通编译、日志检查、局部换行、可逆浮动修复或受影响页面查看增加门禁。以下真实取舍在当前授权未覆盖时需要人工确认：

- 当前官方要求、用户模板与既有 LaTeX 实现发生冲突；
- 精确交付字体不可用，需要选择替代、安装或更换环境；
- 为满足硬版面限制必须删除/实质改写内容、移除证据或改变图表解释关系；
- 需要改变官方/profile 的字号、字体、页边距、行距、页面尺寸或提交格式；
- 要用候选 PDF 覆盖已批准/已发布稿，或正式提交交付包。

确认针对实际语义或发布取舍，不针对每个技术命令。批准后的实现与局部修复按一个连贯 ChangeSet 执行、构建和验收即可。
