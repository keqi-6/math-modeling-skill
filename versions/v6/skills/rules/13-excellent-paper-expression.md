# 13 — 优秀论文表达与证据闭环规则组合

> 用途：参考公开展示的优秀数学建模论文，学习其信息组织和论证表达；不得复制原句、
> 套用与本题不符的叙述，亦不得因论文获奖而照收其中的表达缺陷。
>
> **职责：**保存并分类从优秀论文及写作指南中提炼的表达、内容、证据链、模型解释、
> 验证和声明强度规则。来源不决定强制程度：A/B/C 项必须由对应职责 Skill 采用，
> D 项是建议或诊断，E 项保留等待人工确认。

## 强度与职责索引

| 规则群 | 强度 | 规范归属 |
|---|---|---|
| 来源使用与防抄袭 | A/B/C | `12` 管来源，`03` 管正文采用 |
| 摘要准入、术语解释、问题分析、模型与结果叙述 | B/C/D，少量 E | `03` |
| 公式—算法—验证—声明强度 | A/B/C | `03` 建设，`05` 审计，`09` 设计验证 |
| 摘要—正文—代码—结果—镜像同步 | A/B | `15` 传播方法，`14` 收尾同步，`05` 判定 |
| 六类句子、遮词检查、三列表改写 | D/B | `13` 保留为表达与诊断工具 |
| 外部研究依据 | B/C/E | `12` 核验来源与适用范围 |

执行时不得因本文件含“优秀论文”字样而整体降为建议。具体内容同时具有规则与建议成分
时，以其中可检查的事实、范围和证据要求为 B/C，以固定句序、固定数量和偏好形式为 D。

已识别为其他职责的规则仍保留在本文件以维持来源可追溯，并由对应 Skill 建立执行
入口；是否迁移或删除重复正文仍须用户确认。

## 使用原则

1. 先核实来源确为竞赛组委会、教育主管部门或主办方公开展示的论文，再分析表达。
2. 首次正文起草或结构性重写前，若存在可取得的同届、同题或同题型公开样本，至少
   逐页检查一篇，并把“来源身份—检查页码—观察到的结构—不可迁移内容”写入项目
   审计；只看搜索摘要、目录截图或他人转述不算完成。
3. 学习“句子的功能和信息次序”，不保存可直接拼接的原文句库。
4. 每条借鉴必须回答“它弥补了当前论文的哪项不足”；已有表达更准确时不强行改写。
5. 获奖身份只证明论文具有参考价值，不证明每句话都是规范。软件代替算法、结果堆叠、
   空泛自评、术语不解释、证明强度夸大等写法仍按本项目规范否决。
6. 改写必须重新绑定本题真实对象、模型、约束、数据、证据和适用边界，禁止改变数学含义。

### 符号说明的可迁移观察

组委会或教育主管部门公开展示的优秀论文中，符号说明既有连续列表，也有“符号—说明”
表格，说明优秀论文并不存在唯一固定样式。可迁移的 B 级规则是：当模板未规定形式且
主要符号较多时，用无竖线的三线表建立符号、含义、单位或取值之间的显式对应；释义较
长时采用全宽三列，避免为压缩篇幅使用拥挤的四列配对表。具体建设规则归 `02`，符号
准入与定义一致性归 `03`，不得把公开样本的固定列宽、字号或符号内容直接复制到新题。

本文件中的“删除、重写、合并、移动、补写”等表述只描述候选处理方向，不构成修改
授权。建设或已授权修订阶段可以实施；只读审计、老师审计或用户仅要求评价时，只记录
原句、缺陷、影响和候选方案。

## 逐句功能链

建模论文的基本表达单元不是“显得专业的长句”，而是下面六种可核查功能：

1. **来意句**：指出本段要解决的现实矛盾或承接关系。
2. **定义句**：把现实对象映射为数学对象，并限定术语在本文中的唯一含义。
3. **动作句**：说明对哪些对象执行何种计算、筛选、固定或比较。
4. **理由句**：说明为何需要该动作，以及不用它会产生什么错误或困难。
5. **证据句**：给出结果、界、对照、图表或独立检验。
6. **落点句**：解释证据回答了题目什么问题，并为下一步提供什么输入。

同一句可以承担相邻功能；当多个新模型名、成立条件、动作和结论使先行对象不唯一或
因果关系难以一次辨认时，应拆句或重排，不用固定数量判错。深度逐句审校时可给每句
标注功能；无法标注，或删除后不损害推理的句子，判为删除或重写候选，并按当前阶段
授权决定只报告还是实施。

## 各部分的优先表达次序

### 摘要

摘要不是论文目录，也不是“所有做过的工作”的压缩清单。先确定各问直接回答题目的
主结论，再提炼贯穿全文的共同对象、口径或决策主线；多问论文不强行压成唯一结论。
各问可采用“题目要求—关键建模动作—核心结果—决策含义或必要边界”的次序：

- 先说明本小问相较前问新增了什么决策、约束或情景；
- 仅保留能够标识主要技术路线的规范模型名，并在同一句说明它在本题中比较什么、
  限制什么或输出什么；
- 同段出现多个模型时，逐一说明各模型在本题中的不同职能；若新增模型名破坏原有
  信息次序，重排整段，不把名称直接插入既有结果句；
- 后一小问复用前文已经解释的多级目标时，只重述影响方案排序的目标顺序差异，不重复
  完整目标清单；
- 报告直接回答题目的方案、关键指标和相对基准；
- 仅当假设、边界或检验会改变读者对推荐结论的理解时，才把它写入摘要。

摘要中的句子应形成因果链，而非“模型名清单 + 数字清单”。需要形成摘要压缩候选方案
时，优先标记背景套话、实现级算法名、局部诊断、重复验证和次要数字；本顺序只用于
生成待审计候选项，不构成删除、合并或改写授权，任何文字修改必须逐项取得用户确认。
不得先压缩标题间距、字号或行距。

#### 内容准入三级表

先把候选信息分为三级，再动笔：

| 级别 | 判定标准 | 摘要处理 |
|---|---|---|
| A 必须项 | 直接回答题目；改变推荐方案、可行域或目标优先级；构成论文最主要的结构性贡献；限定结论成立条件 | 必须写，并交代对象、动作和结论 |
| B 条件项 | 提供关键数量下界、稳健性范围或独立证据，且没有它会误解最优性、可靠性或适用范围 | 有足够篇幅且能解释清楚时写；否则把必要边界并入结果句 |
| C 正文项 | 求解器、变量规模、单商品流等实现构造、广度优先搜索等检查名称、局部必要连接、全部节点表、重复验证和次要备选数值 | 移入正文；不得为展示技术量而塞入摘要 |

以最小可独立判断的信息单元分级，不按整句或整段“一刀切”。同一句中的主模型、核心
结果、试验配置和证明边界可以属于不同级别。检验或适用边界原则上继承其所限定主张的
级别：主张移回正文时，附属边界同时移回；主张保留时，把必要边界并入结果句，避免
留下只有“不能证明什么”而没有检验对象的孤立限制。

当题目要求评价合理性、识别问题或比较方案时，决定评价结论的核心指标、比较基准和
原因诊断规则属于 A 级。摘要不能只写“进行评价”“分析现状”或列出模型名称；应说明
按什么指标评价、比较哪两个条件，以及什么比较结果对应何种判断。实现这些判断的
求解器、变量规模和重复检查仍属于 C 级。

“关键工作”须按摘要功能判断，不按完成成本判断。代码很复杂、运行很久或使用了规范
算法名，不自动取得摘要席位。反之，一个简短的补充条件若改变结论含义，属于 A 级。

#### 自足解释门

摘要中的每个信息单元应按其功能回答下列相关问题，并形成自足语义闭环；不以回答
数量作为合格阈值：

1. 对什么对象？
2. 做了什么比较、限制或计算？
3. 得到什么结论？
4. 该结论为什么影响题目答案？

模型名、检验名或指标名不能单独承担一句话。出现规范术语时采用
“术语 + 本题动作或作用”，例如“建立词典序模型，前一级最优值固定后再求下一级”，
而不能只写“采用词典序优化”。若解释该术语需要展开变量、网络构造或算法步骤，且该
术语不是区分论文主路线所必需的，应从摘要删除，在正文保留规范名称和完整解释。

禁止“复核两个阶段最优值”“验证结果可靠”“进行了敏感性分析”等无对象、无操作、
无判据的悬空声明。按以下优先级处理：

1. 说明具体排除了什么反例或得到什么范围；
2. 合并进相邻结果句，写成结论边界；
3. 若不影响摘要主结论，则移回正文。

#### 正文首次使用的就地解释门

正文按阅读顺序审计，不得用后文信息倒推前文合格。模型名、指标、变量或判断规则首次
实质参与推理时，当前句或紧邻上文必须已经说明它针对什么对象、执行什么动作、按什么
方向或判据工作。后文可以补充符号、公式和严格定义，但不能补救读者此前被迫猜测的含义。

章节总括段允许先出现规范名称，但须立即给出白话机制；若当前表达已经自足，后文只是
形式化，则属于合理的“先解释、后定义”。审计报告不得仅以“后文有定义”判定通过，
而应记录当前句和邻近上文具体提供了哪些信息。审计可以读取后文以核对一致性，但不得
用非直接承接的后文解释免除当前概念的解释责任。

#### 版面不足时的删减顺序

只有用户明确要求处理版面并确认具体删减方案后，才执行本节顺序。编译发现页数增加、
跨页、标题孤行或浮动变化时，只报告现象及来源；不得自行启动压缩，也不得通过字号、
行距、段间距、标题间距或浮动位置调整来恢复旧版面。任何内容压缩与版式调整都必须
分别提交用户审计并取得明确确认。

先完成内容排序，再处理版面。关键词跨页或摘要过密时，依次删除或合并：

1. 背景套话、重复题意和重复主语；
2. C级实现名称、软件名、求解规模和验证工具名；
3. 局部节点、局部连接、完整备选清单及其他正文级诊断；
4. 不改变决策的次要指标和重复小数；
5. 与主模型重复的验证过程，将其改写为必要的结论边界；
6. B级内容中对结论理解增益最小者。

A 级内容最后才允许压缩，而且只能改写，不能无解释删除。获准完成内容删减后，恢复
标题、摘要标题、段间距、关键词间距、正文行距和字号的规范值。若仍存在版面冲突，
只报告冲突及备选方案；包括字号、行距、段间距、标题间距、页边距、分页和浮动在内
的任何版面参数调整，仍须另行取得用户明确确认。模板允许调整只说明方案具有可选性，
不构成自动修改授权。

每轮删除或合并后执行一次“删后语义闭合检查”：脱离删减前的上下文重读剩余摘要，
逐问确认所有“评价、分析、优化、验证、诊断、比较”等动作仍有明确对象和判据，每个
原因判断仍保留评价口径或对照关系，每项结论仍能追溯到相邻的动作或证据。若删去 C 级
细节后只剩抽象动作，不得把空泛句视为已保留 A 级信息；应补回最小必要机制。

#### 摘要—正文—结果双向追踪

双向追踪不是选定摘要、正文、表格、代码或结果文件中的某一处作为标准答案，再让其他
位置机械迁就它。题意与已确认任务、方法定义、数学表达、代码实现、冻结结果、图表、
正文、摘要和结论共同组成证据链；任何两处不一致时，先判断最早的无证据或错误层，
再从该层修正，并将修正传播到全部依赖项。不得按表述出现次数、文档新旧或当前位置
是否“终稿”决定正确口径。

执行“一修全修”：任一术语、指标口径、比较对象、成立条件、结果数字或证明强度改动
后，搜索其全称、简称、同义表达、关联条件和相关数字在全项目中的全部出现位置，逐项
复核摘要、正文首次定义、公式解释、表头图注、结果讨论、结论、双向映射、当前审计、
复现文档和交付副本。局部句子改对但其他位置仍保留旧口径时，不得宣称问题已关闭。
同步完成后重新执行摘要盲读、正文到摘要检查和摘要到证据链检查。

### 问题分析

先完成内部概念审计，再写“为什么不能直接算”和“如何转化为可解问题”：

`对象与职能边界 → 任务量词与情景 → 数据能够表达的能力 → 评价词的操作化定义
→ 现实困难 → 可利用的结构或数据特征 → 数学转化 → 所选方法 → 预期输出`

后续小问必须显式说明继承和变化。例如：保留前问的距离口径，但新增容量约束；因此
不能直接沿用前问方案，需要在原分配模型上增加负荷变量并重新优化。不得重复题意后
直接跳到算法名称。指定节点、指定时刻或指定事件不得因“现实中也可能发生”而扩展为
任意节点、任意时刻或所有事件；边界反例应先判断是在否定题面命题，还是只是否定建模者
额外提出的更强命题。

### 模型建立

按“对象—关系—公式—作用”展开：

- 公式前说明为什么建立这条关系；
- 在公式前或符号首次出现时说明其含义、单位和取值来源；
- 按“原始关系—已知参数代入—等价变形—可直接计算形式”逐步展开关键公式。题目
  常量、集合规模和已统计总量的代入只有在帮助理解来源、判断等价性或复核关键结果
  时才展示；机械代入与简单换算可以省略；
  使用绝对值线性化、最大值
  上界化等变形时，同时写出变形前指标、辅助变量关系和变形后的目标—约束，不得只
  丢出最终公式；
- 公式后解释它排除了什么错误方案，或把哪个现实要求转化成了什么数学条件；
- 多个公式结束后，用一段白话说明它们如何共同把输入变为输出。

辅助约束宜按“现实理由—若不约束会出现的实际错误—最小数学表达—约束效果”叙述。
先检查该性质是否已被前述规则自然保证；只有在后续模型放宽这些规则而使性质失效时，
才把辅助约束作为必要内容。辅助变量首次出现时直接说明其现实数学作用，不让符号先于
定义，也不让实现细节压过主要决策逻辑。

模型名的推荐表达结构为：

`现实机制说明 + 规范术语 + 本题对象映射`

例如不只说“采用二分图匹配”，而要说明在给定时间阈值下只保留能够及时到达的
“平台—出口”连接，再判断是否存在覆盖全部出口且平台互不重复的匹配；这一判定构成
本文的二分图阈值匹配。

### 求解方法

以“状态怎样变化、候选怎样比较、何时停止”为主线：

1. 初始候选或搜索区间从何而来；
2. 每一步新增、删除、分支或固定什么；
3. 用什么指标接受、排除或排序候选；
4. 停止条件是什么；
5. 停止后能证明可行、局部不可改进，还是全局最优。

算法通用定义只保留理解本文所必需的部分。不得用软件名称、函数名或“返回最优状态”
替代上述逻辑。

### 结果与图表

采用“基准—变化—原因—代价—决策含义”：

- 先给比较基准和口径，再报告改善或恶化；
- 说明变化由哪个约束、目标阶段或瓶颈对象造成；
- 同时报告收益和代价，避免单向赞美；
- 图表解读先陈述可见现象，再作不超过证据强度的解释；
- 结尾直接回答应选择什么、在什么条件下有效。

结果句至少包含对象、条件、指标和数值四要素中的必要部分。“效果较好”“基本合理”
不能替代量化结果或可复核证据。

### 验证、局限与结论

- 验证句写清检验对象、操作、判定标准和结论边界；
- 局限句说明省略机制可能使结果向何方向偏移，以及何时需要扩展；
- 结论按题号归纳“决策 + 核心证据 + 适用条件”，不复刻摘要的建模过程；
- “证明”仅用于证据足以排除反例的命题；其余使用“复算一致”“支持”“表明”或
  “在所考察范围内保持”。

## 逐句因果闭合检查

改写论文句子前，先识别其中的判断，不得先凭语感润色、再补数学理由。分类、等价、
上下界、分支排除、最优性、改善原因、稳健性和适用性均属于需要依据的判断。

对每个判断依次执行：

1. 写清判断对象和结论，例如“连续松弛的最优值是整数最优值的下界”；
2. 定位能够推出该结论的数学关系、数据事实、约束、对照或检验；
3. 将理由放在同句或紧邻前句，使读者不依赖后文也能回答“为什么”；
4. 先用本题对象解释机制，再给出“连续松弛、分支定界、词典序”等规范术语；
5. 把候选域、约束、参数范围、比较基准和检验范围紧邻其限定的结论；
6. 核对理由能够支持的最强措辞，只复算指标时写“复算一致”，排除全部更优候选后
   才写“全局最优”，有限扰动未改变结果时只写“在所考察范围内保持”；
7. 完成改写后遮去术语，确认剩余文字仍能复述对象、机制、理由和结论。

定义句、题面事实和直接报告数据的句子不必人为补写原因；但其来源、适用条件或数值
身份仍须明确。缺少真实依据时，不得为满足句式虚构因果，应删除判断、降低结论强度，
或回到模型和证据链补充验证。

对高风险判断、证明强度争议或深度专项审计，可记录“当前判断—邻近理由—规范术语—
证明范围—修改动作”；常态逐句检查不强制生成五字段记录。任一判断没有邻近理由，
术语先于机制，或结论超出证据范围时，不得定稿。

## 句法和用词规则

- 优先使用有数学动作的谓语：定义、保留、固定、枚举、比较、排除、复算、界定。
- 少用无对象的“考虑、分析、处理、优化、验证”；使用时必须补出对象和判据。
- 条件置于动作之前，结论置于证据之后，避免读者读到句末才发现适用范围。
- 比较句必须写明比较对象、指标和方向；“优于原方案”须说明原方案是哪一个。
- 指代词只在前文存在唯一对象时使用，否则重复准确名称。
- 并列项保持同一语法层级，模型、约束、指标和结果不得混列。
- 括号仅承载短缩写、公式编号或必要单位，不用来塞入完整条件、理由和结论。
- 不用“首先—然后—最后”掩盖缺失的因果关系；每个顺序词之后必须是真实依赖步骤。

## 对照改写法

逐段建立三列表：

| 当前句的功能 | 当前缺陷 | 只针对缺陷的改写动作 |
|---|---|---|
| 说明方法 | 只报术语 | 增加本题对象、关键动作和判据 |
| 报告结果 | 缺比较基准 | 补充基线、指标口径与变化方向 |
| 解释约束 | 只复述公式 | 说明违反约束会产生的错误方案 |
| 声明验证 | 证明能力不明 | 写明检验操作及其能、不能证明什么 |
| 承接下问 | 标题硬切换 | 写清继承项、新增项及重新建模原因 |

禁止为了模仿“优秀语气”而全段重写。只有当段落的功能次序本身混乱时，才进行结构性
重写；若只是术语、主语、证据或边界缺失，应作局部修复。

## 定稿检测

- 只读每段首句，能否看出本段来意及与前段关系；
- 只读每段末句，能否看出证据落点或下一步输入；
- 遮去模型名，剩余文字能否说明模型怎样工作；
- 遮去形容词，结论是否仍由数据或证明支撑；
- 将每句标为来意、定义、动作、理由、证据或落点，是否存在无功能句；
- 每个“因此”前是否有充分前提，每个“证明”后是否没有超出证据；
- 改写后的对象、公式、数字、目标顺序和证明强度是否仍与代码及输出一致。
