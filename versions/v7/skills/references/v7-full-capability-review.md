## 活动架构结论

1. `SKILL.md` 是唯一阶段、权限、回退和晋升控制器；`rules/00` 仅是详细编排参考。
2. `planning/` 保存分析、决策、状态和论文落点，不承担连续论文正文。
3. `docs/<task-id>/solution_brief.md` 是逐问队友讲解稿，采用模型建立与求解的解释骨架，
   但不是论文草稿，也不取得论文批准。
4. `paper/` 是唯一论文工作区和评阅载体；S7 才允许论文正文变更与正式晋升。
5. 历史版本和映射保留来源身份，但不再用历史整文件哈希冻结 V7 活动规则。V6→V7
   活动语义由逐块账本、逐字保留检查、改写理由和失败回归证明。

## 改写保护

- `T-PRESERVE-EXACT`：每个 `preserve` 能力必须仍逐字存在于声明的 V7 owner；删除或
  owner 漂移使严格闭合失败。
- `T-V7-REWRITE-CONTRACT`：控制器、比例恢复、职责目录、逐问讲解稿、假设时机、活动
  路径、数据候选身份、编号、治理和不确定性 owner 等改写由专项回归保护。
- 测试 ID 必须存在于 `capability-test-registry.json`；任意字符串不能满足闭合。
