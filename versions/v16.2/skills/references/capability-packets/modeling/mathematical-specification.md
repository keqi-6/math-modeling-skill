# 可实现、可验证的数学规格

适用于把已选择的方法冻结成代码和验证可以共同消费的规格。规格不是模型名称、公式清单或实现草稿，而是现实对象、数学关系、算法和允许主张之间的完整合同。

来源保留：V8 `25-model-results-acceptance.md`、`31-modeling-minimum.md` 的对象—关系—公式—作用、辅助变量、多目标和边界规则，结合 V14 的 frozen identity 与消费者失效。

## 规格必须回答的问题

- 现实对象如何映射为集合、索引、变量、状态或节点；
- 统计单位、变量域、形状、类型和单位是什么；
- 目标、状态方程、关系和硬/软约束是什么；
- 参数、初始条件和边界条件来自哪里；
- 假设是什么，每项失败会破坏哪一部分主张；
- 候选域或搜索范围怎样形成；
- 输入/输出接口、失败信号和正式结果 schema 是什么；
- 算法如何初始化、比较、处理不可行、停止和报告失败；
- 验证会检查哪些性质、容差依据是什么；
- 该方法明确不能支持哪些陈述。

随机方法还要规定种子策略、重复次数依据和分布性输出；数值方法规定尺度、容差和收敛判断。

## 对象—关系—公式—作用

每个主要构造按以下顺序闭合：

`现实对象 → 需要表达的关系 → 数学公式 → 在模型中的作用 → 缺失时的错误方案`

公式前说明为什么需要这条关系；符号首次出现附近给出含义、单位、定义域和来源。关键公式从原始关系展开到可计算形式，不跳过决定含义或等价性的步骤。公式组后用普通语言说明输入怎样变成输出。

### 连续与状态依赖模型的可计算化

以守恒或收支关系建立连续模型时，补足决定计算含义的环节：守恒对象及其计量基准 → 储存、通量和源项 → 题设支持的降维 → 坐标与未知量 → 初边值问题。实际采用数值方法时，再给出相应离散更新；解析求解或不以收支建立的微分模型按各自关系给出计算链，不制造控制体或通量。先由本题关系推出方程，文献用于支撑适用条件；不要因为领域常见而加入题面没有且对当前回答无必要的机制。

状态依赖系数先写清自变量及导数。例如一维光滑情形中，若 a=a(u,T)，则 ∂x(a∂x u)=a∂xx u+(a_u∂x u+a_T∂x T)∂x u；不能把 a 当常数移出导数。这个展开用于核对，不规定只能差分展开式：采用有限体积时也可直接离散面通量，说明界面系数的重构与非线性更新，保持同一面流入与流出配对。若采用解析 Jacobian，再从实际离散残差对各状态分量求导，包含界面系数、跨场项和状态依赖分母；这些迭代导数不能再次作为物理源项添加。储存项 s(u)∂t T 与 ∂t[s(u)T] 并不等价，后者多出 T s'(u)∂t u；采用哪一个来自原始储存定义，不能靠形式整齐补项或删项。

采用网格离散时，用一个代表单元或时间层说明所用节点、控制体及面索引、通量正方向、中心/外边界处理和启动步骤；其中控制体、面通量只适用于采用相应表示的方法。算法图分清更新残差的直接模板、预测或首步所用的历史导数、联立求解后的间接影响；斜线存在与否取决于实际方法及其版本，不能凭常见模板增删。试探首步、首个接受步和物理过程的起始阶段也分别命名。N 个区间、N+1 个节点与控制体数并非同一概念，数量由所用离散约定决定。空间二阶、边界重构二阶、时间方法阶数与整体误差分开说明，不能由内部差分的阶数替边界背书。启动时历史层不足、输入节点切换、初边值不相容及非线性迭代等，仅展开真实存在的困难。

移动区域另行注明导数保持哪个坐标不变、状态量按总体积还是物质质量计量、边界在何处；先作坐标/守恒变换，再判断是否产生输运或压缩项。坐标运动与材料运动相消须说明速度假设；质量比与单位体积浓度的压缩响应不同，不能移植同名变量的项。由较完整守恒式得到约化输运式时，列明闭合前提，不用离散收支残差替代完整组分守恒的证明。几何图不能代替这些关系，也不预设所有移动边界都采用相同附加项。

## 主求解合同与辅助验证合同

冻结规格时，同时登记每种计算方法的角色，而不把所有出现过的算法并列成“模型”：

- `primary_model`：决定现实对象、数学关系、目标、约束或允许主张的正式模型；
- `primary_solver`：把正式模型变成可执行计算的主求解链；
- `auxiliary_validator`：从不同路径检查实现、数值近似或模型结构，不产生正式答案身份。

主求解链必须能从前述对象、关系和公式追到可计算化变形、比较或更新规则、停止与失败条件。若隐藏算法名后，仍无法说明每一步为何由模型公式推出，规格尚未闭合。相反，具体运行使用多少线程、哪次种子、实际迭代数或某次日志状态通常属于执行记录；只有它们会改变候选域、数学语义、精度承诺或失败判据时才进入冻结规格。

辅助验证器若需要另一套较长、独立的数学合同才能解释，必须作出明确分流：若该合同实际决定正式答案或主张能力，就把方法升格为主方法并重新完成选择与冻结；否则完整推导只进入内部技术证据，面向评审或一般交接的材料只报告检验对象、设置、指标、结果和证明边界。这里的判据不是“方法复杂就隐藏”：承担核心比较、共同求解或正式证明的方法不能降格规避解释；一个简单且有信息增量的独立检查也可以在正文中简要说明。

## 辅助变量与约束

辅助量采用：

`原始现实量 → 辅助变量/等价变形 → 可计算形式 → 等价理由 → 现实作用`

增加连通、排序、流量、绝对值拆分或上界约束前，先检查它是否已由变量定义、基础规则或目标自然推出。需要证明不可省略时，保持数据、目标、顺序和容差不变，只移除该约束构造最小反例，并说明现实错误。

最大值上界等变量应解释为何在最优解处取等；固定方案下的恒等关系与全体方案中的优化作用分层说明。

## 多目标、权重和容差

建立：

`现实优先级 → 目标名称 → 数学表达 → 求解阶段 → 保留条件 → 方案变化 → 决策含义`

- 词典序优化说明前一级最优值如何进入下一阶段可行域。
- ε-约束说明主目标和阈值目标以及阈值依据。
- 线性加权先处理量纲、归一化和权重来源，并做权重扫描。
- 数值容差说明误差来源、方向、量纲和尺度，不能把容差伪装成牺牲前级目标的许可。
- 声称某一级有边际作用时，比较加入该级前后，而不是只比较初始与最终方案。

异量纲目标不能未经处理直接相加；硬阈值不能用加权平均掩盖。

## 规格一致性检查

冻结前执行：

1. 量纲、符号、索引和域检查；
2. 最小手算例、边界例和已知不可行例；
3. 目标与约束方向检查；
4. 输入/输出形状、单位和失败信号检查；
5. 公式—伪代码—验收 oracle 的双向核对；
6. 每条允许主张是否有规格内依据；
7. 每条禁止外推是否在结果消费者中可见。

## 冻结和变更

冻结对象是整份无歧义规格 identity，不是“存在一个规格文件”。实现、验证、结果、图表和论文主张绑定该 identity。

规格变化不是普通措辞修订。先取得授权，识别受影响消费者，执行合法重开并重新冻结；不改变语义的排版或注释修改只检查直接闭包，不机械使全部消费者失效。
