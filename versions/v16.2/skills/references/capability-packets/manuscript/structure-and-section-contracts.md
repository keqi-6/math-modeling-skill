# 论文结构与章节职责合同

适用于首次建立论文结构、结构性重写、补齐缺失章节职责、调整跨节顺序，以及章节或全文完成审计。它说明怎样把题目任务组织成读者可追踪的论证，不规定状态迁移、修改授权或发布门；这些仍由 V14 控制器与当前命中的规则原子决定。

来源保留：V1 `03-paper-content-rules.md`、V2 `17-reader-first-manuscript-audit.md`、V3 的 B/F/M/S 稳定规则及 V4–V5 的章节职责原子。删除固定章节数量、固定标题层级、固定图表/字数配额和日常全文门禁，保留题目链、章节边界、依赖顺序和失败修复方法。

## 何时读取本包

读取本包，当任务实际涉及以下任一情形：

- 从题目或已有研究产物建立正文提纲；
- 新建、合并、拆分、移动或改名一个承担论证职责的章节；
- 某一小问虽有公式或结果，却找不到完整的题意—方法—证据—回答链；
- 背景、重述、分析、假设、方法、结果或结论之间职责混杂；
- 进行章节完成、整稿完成或正式交付前的结构审计。

错别字、标点、局部句法润色、单个交叉引用或不改变章节责任的版面修复，不因此触发结构重建。是否扩大修改闭包由 V14 判定，本包不把结构检查变成每次编辑的前置门。

## 一、先从任务和主张建结构

### 1. 核对当前项目合同

先确认当前题目、用户指定模板和现行提交要求真正规定了什么：必须回答的任务、原题量词与情景、必需交付物、匿名与格式约束，以及允许的附录或支撑材料。公开优秀论文只用于观察信息次序、标题层级和模型—结果的邻接方式，不能替当前题目决定模型、结论或固定目录。

若当前项目没有规定某种章节名，不把历史赛事模板、个人偏好或一篇样例的目录升级为硬要求。先确定职责，后确定标题。

### 2. 建立逐问主张链

对每个可独立回答的任务，先用内部提纲写清：

`题目对象与动作 → 必须给出的直接答案 → 主要数学构造 → 主证据 → 必要检验 → 成立边界`

同时记录：

- 本问继承前文哪些数据、定义、模型对象、基准或已冻结结果；
- 本问新增或改变哪些决策、约束、情景、评价口径或输出；
- 本问与前问是递进、对照、推广、重新优化还是独立验证；
- 哪些内容是多问共享基础，哪些必须在本问就地实例化。

共享模型可以集中说明，但不能吞掉各问自己的输入、变化、结果和直接回答。一个读者在任一小问入口都应知道“继承什么、改变什么、最后回答什么”。

### 3. 给章节分配唯一的主要责任

为每个现有或计划章节写一句内部责任说明：

`本节回答读者的什么问题；接收什么上游；产出什么可供下游使用的主张或定义。`

一句话可以跨多个自然段实现；一个章节也可承担相邻责任，但不能只因标题常见就存在。若章节没有可核对的读者问题，先判断应删除、合并还是补齐内容。若同一责任在多处重复，保留最适合首次解释的位置，其他位置只留下维持局部推理所需的短回指。

### 4. 按依赖而不是工作日志排序

先在无标题提纲中排出真实依赖：

`题意与对象 → 数据和定义 → 假设或边界 → 数学关系 → 求解或推导 → 结果证据 → 解释与回答`

然后检查每个章节的入口是否已有所需定义和证据，出口是否被下游实际消费。禁止按代码文件、Agent 分工、执行日期、试错历史或“先写了哪一段”组织评审可见正文。

只有依赖成立后才设置标题层级。标题负责导航并预告本节实质内容，不负责制造创新感；没有独立内容时不增加空层级。主题式结构比逐问结构更合适时可以采用，但仍须让每项原题任务有显式入口和可追踪回答。

## 二、常见章节的职责合同

下表描述内容职责，不要求机械设置同名章节。

| 内容职责 | 应完成什么 | 不应越界到什么 |
|---|---|---|
| 题目、摘要与关键词 | 准确标识真实对象、主要方法职责、核心结果与边界；与正文一致 | 未证明的亮点、正文没有的结论、实现日志 |
| 问题背景 | 用普通语言说明现实对象、研究价值、影响条件和题目希望支持的分析或决策 | 本文模型、公式、算法步骤和结果预告 |
| 问题重述 | 保留原题对象、量词、时态、情景、严格边界、数据结构和待回答任务 | 主动增加强条件、本文方法、参数或答案 |
| 问题分析 | 解释困难、可利用的数据或结构、主要方法方向、选型理由、预期输出与边界 | 变量公式、完整目标层级、求解器参数、计算结果 |
| 模型假设 | 只声明题面未给出但模型成立所需的条件，并给出必要理由、实际用途和适用边界 | 抄录题面事实、指标定义、模型约束、实现步骤或章节预告 |
| 符号与数据接口 | 定义反复使用的符号、单位、集合、统计口径、清洗与派生量，以及进入模型的接口 | 为填表收录一次性中间量；把数据审计过程写成工作日志 |
| 模型建立 | 首次完整承载对象、变量、关系、目标、约束、可计算化变形及由公式自然推出的主求解逻辑，使模型身份和算法合法性可复推 | 把决定含义的推导推迟到求解；用模型名、软件名或验证器代替正式数学合同 |
| 模型求解 | 回指既有公式，说明本次输入、初始化、参数、执行步骤、停止/失败判据和输出生成 | 首次引入或完整重复一套新的目标、等价变形、可行域或竞争数学合同 |
| 模型检验与验证 | 报告检验对象与风险、设置、预先判据或指标、观测结果、结论强度和边界 | 展开非主方法的第二套强数学合同；把复算同值夸成模型正确、全局最优或普遍稳健 |
| 结果与直接回答 | 绑定结果身份、条件、基准和指标；解释机制、例外与题目含义 | 只堆数字；把外部参照或内部诊断冒充当前项目正式结果 |
| 评价、局限与改进 | 用已发现的证据说明优势、真实失效边界、影响方向和可行改进 | 通用优缺点套话、没有依据的未来工作 |
| 结论 | 按任务回收决策、核心证据、成立条件和必要边界 | 重演建模过程、引入新方法或新结果 |
| 参考文献、附录与声明 | 让外部主张、补充推导、复现材料和适用披露各归其位 | 用参考文献表的“存在”替代正文就近支撑 |

### 问题分析的专门边界

保留历史中最准确的职责句：

> 问题分析解释“这是什么问题、为什么这样分问、通常怎样处理、本文为何选择当前方向”，但不提前展开具体算法实现。

写作时可按下列次序组织，但不必变成固定小标题：

`现实困难 → 数据能够表达什么 → 可利用的结构 → 方法方向与关键替代 → 当前选择理由 → 预期输出和边界`

若一句同时包含合规的选型理由和越界的操作顺序，保留前者，把变量、公式、参数和求解流程移到正式方法位置，不整句删除。

### 模型建立—求解—检验的专门边界

这是方法内容的专项规则：在它与通用的“定义—证据—推导—结论”章节依赖发生重合时，以本节更具体的职责链覆盖该重合部分，不要求同时满足两套平行措辞。通用规则继续约束非方法章节及全稿跨节依赖，专项规则负责方法内部的建立、执行与检验边界。

上述三项是语义责任，不要求使用固定标题、固定节数或相邻排版。短文可以把它们放在同一方法章节，闭式推导也可以不设独立求解节；但首次阅读顺序仍应是“数学合同与可计算化 → 本次执行 → 检验证据”。后文可以简短回指，不得要求读者从代码、内部报告或更晚的检验段反推正式模型是什么。

按内容的数学职能判断归属，而不按“看起来像算法”判断。把连续判据变成可判定问题所必需的等价变形、括区间逻辑、接受规则或主算法步骤，属于模型建立；实际使用的种子、网格数、计算预算和运行停止状态通常属于模型求解。若某个网格或容差本身改变模型语义、候选域或允许主张，则它仍是规格的一部分，不能仅放入求解日志。

模型检验允许就地定义读者理解指标或 oracle 所需的简短关系，但不应借“验证”首次建立决定正式答案的数学模型。一个辅助验证器若需要另一套较长、独立的数学合同，先判断其角色：若它承担正式共同求解、核心证明或主要比较，就升格到模型建立；否则完整推导进入内部技术证据，正文只报告它检查了什么、怎样判断、观察到什么以及能证明到哪里。多个算法同值只能增强数值一致性，不能替代模型结构和现实适用性证据。

### 假设的分类与删除检验

审计每条“假设”时，分别判断它是：题面事实、为填补缺失信息而增加的条件、指标定义、决策域/约束、求解安排，还是由假设产生的边界。假设章节只保留第二类及其必要理由、下游用途和边界，其余移回承担相应责任的位置。

每条保留假设至少能定位一个受影响的变量、距离、时间、候选域、目标、约束或结论。没有下游用途的条目不是为了显得完整而保留；改变后会显著改变答案但尚未检验的条件，应诚实限定适用范围。

### 每一问都要有自己的闭环

多问共用数学基础时，每一问仍需让读者找到：

- 当前输入及相对前问的变化；
- 当前决策对象、目标或判据；
- 关键约束或推导怎样作用于本问；
- 当前求解/计算输出及其身份；
- 主结果、必要验证、直接答案和边界。

共享基础只需短回指，不重复整段定义；但不能让读者必须跨越多个远端章节自行拼出当前问题链。

## 三、标题、文件与章节交界

### 标题从逻辑生成

先列真实步骤及其并列、从属和依赖，再映射为项目允许的标题层级。普通组织性标题可以保留；只有本节确有独特机制、约束、阈值、证明、反事实或权衡时，才在标题中预告。避免空泛宣传语、完整结论、数字清单和没有独立内容的单子项层级。

隐藏正文只读标题时，应能定位各项任务和推进顺序；遮去标题只读正文时，段落本身仍应成立。标题不能代替首段对本节输入、动作和输出的说明。

### 文件只是维护边界

短稿可以单文件。长稿或多人协作时，只有拆分能降低误放、冲突或协作成本，才按稳定的评审可见职责拆源；唯一入口按最终阅读顺序组装。文件名不决定章节合格，也不要求一个标题恰好对应一个文件。

拆分或移动后，检查环境、标签、引用和命令参数未跨文件断裂，并连续阅读新交界；“仍能编译”只证明语法没有致命失败，不证明职责正确。

### 关系驱动的交界

章节或小问交界只补真实关系：继承项、新增项、为何需要重新建模、上节输出怎样成为本节输入。不要用“下面进行分析”“首先—其次—最后”掩盖没有依赖的拼接，也不要为避免标题相邻而添加无信息的报幕段。

## 四、完成标准

结构工作在当前批准范围内完成，当且仅当：

- 当前项目要求的每项任务都能定位到直接回答及其主证据；
- 每节有可说明的读者问题、上游输入和下游产出；
- 定义、证据、推导和结论按依赖顺序出现，首次阅读无需依靠后文倒推；
- 背景、重述、分析、假设、方法、结果和结论没有以重复或越界互相代替；
- 共享基础与逐问实例化同时存在，没有任何小问只剩标题或结果表；
- 标题、交叉引用和源码边界与实际职责一致；
- 当前审计结论不超过实际检查的章节或全文范围。

可用两个快速测试：隐藏内部文件名和工作状态后，正文结构仍面向读者；按任一任务从题意追到结论时，链条中没有必须靠代码、聊天或内部笔记补齐的空缺。

## 五、常见失败与局部修复

| 失败 | 先修哪里 | 局部修复 |
|---|---|---|
| 按代码或执行顺序写论文 | 结构来源 | 改成任务与论证依赖；保留真实内容，移动到承担其职责的位置 |
| 问题分析提前写完整算法 | 章节边界 | 留下困难、方法方向和选择理由；将变量、公式、参数、流程移到方法节 |
| 假设表抄题面与约束 | 条目分类 | 逐分句分类，只保留真实补充条件及边界 |
| 共享模型使某一问无入口 | 逐问实例化 | 在该问补继承/变化、当前输出、主证据、直接答案，不重复共享定义 |
| 章节标题存在但正文无责任 | 章节合同 | 合并、删除空层级，或补足该节必须交付的主张 |
| 同一条件跨节近乎逐字重复 | 首次正式承载点 | 集中正式定义，其他位置只保留必要的原因、作用或短回指 |
| 结论与摘要都是工作清单 | 回答链 | 按题目逐项回收决策、证据、条件和边界，删除过程复述 |
| 局部结构修复引发全稿重排 | 修改闭包 | 只移动受影响职责及其直接交界；没有跨节依赖就不升级全文审计 |

## 六、必要人工确认点

本包不新增回执、审批层级或每节门禁。只在以下决定确实出现且尚未由用户授权时请求人工确认：

- 当前官方要求、用户模板与既有结构发生真实冲突；
- 合并、删除或重排章节会改变题目回答路径、模型叙事或主要主张；
- 主题式与逐问式组织存在实质取舍，且两者会改变评审定位方式；
- 正式候选要被提升为已批准稿或覆盖已发布版本。

在已授权范围内补标题、修章节交界、移动明显错位内容、消除同职能重复，按 V14 的一个连贯 ChangeSet 实施和验收即可，不逐项增加人工门。
