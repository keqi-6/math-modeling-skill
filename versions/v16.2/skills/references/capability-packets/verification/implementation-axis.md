# E1/E2：实现符合性与数值解验证

适用于验证代码是否实现冻结规格，以及数值近似、离散、搜索、容差或舍入是否足以支持当前结果。E1 与 E2 可以互相发现问题，但不能互相替代；`rules/verification.json` 拥有证据要求和 S6 效果。

来源保留：V8 `05-audit-protocol.md`、`09-robustness-checker.md`、`25-model-results-acceptance.md`、`32-verification-minimum.md`，结合 V14 的精确 input/claim binding。

## 先写风险和 oracle

不要从“跑哪些测试”开始。先列出当前实现最可能错在哪里、错误会影响哪条主张，以及什么独立观察能区分正确与错误。

`规格条款 → 实现路径 → 失败风险 → 测试输入 → oracle/判据 → 受影响主张`

退出码为零只证明进程结束；字段存在、哈希稳定、重复运行同值和测试脚本自报通过都不是结果 oracle。

## E1：实现符合性

E1 检查代码和冻结规格是否同义，可组合：

- 输入 schema、单位、索引、候选域和非法输入；
- 目标、约束、状态更新和边界条件的逐项对应；
- 正式入口、影响结论的分支、错误路径和失败信号；
- 最小可手算实例、退化实例、边界实例、已知不可行实例；
- 固定种子复现、随机状态隔离和输出 schema；
- 公式—代码—正式输出之间的代表性双向追踪。

测试代码应尽量直接读取权威输入和正式输出，避免调用被测实现的同一辅助函数重新计算“期望值”。

## E2：数值或求解可信度

E2 在存在数值风险时检查解的稳定与误差，可选：

- 独立公式或另一种推导；
- 另一求解器、另一实现或高精度版本；
- 解析特例、小规模穷举或有效上下界；
- 网格/步长加密、容差收紧和有序收敛序列；
- 约束残差、最优性条件、守恒和重构误差；
- 多种子分布、失败率和解质量界。

容差来自尺度、数值方法阶数、可用误差界或决策敏感度，不从已经观察到的差异倒推。收敛检查观察残差、收敛率或决策稳定；舍入、截断、平滑和图形相似不能隐藏原始波动。

若当前问题确实不存在数值近似、搜索、随机、离散化、容差或独立比较风险，E2 可以使用状态机允许的 `justified_not_triggered`，但不能把它伪写成 PASS。记录必须绑定当前模型规格 artifact identity，引用一个已解决的人工适用性决定，说明为何没有数值风险，并列出因此不能声称的数值稳定性、精度或最优性边界；规格变化后原 N/A 自动失效。机器不能判断理由是否诚实，人工确认不可由字符串长度替代。裸 N/A、只写“闭式解”或把尚未执行的适用重算说成不适用，都不能关闭 E2。

### 显示精度与阈值决策

有严格阈值时，核对未舍入原始值、实际判定规则和显示位数；显示为 0.1500 不能区分严格小于、等于或大于 0.15。若阈值定义连续演化过程的终点，再核对连续事件估计、题目要求的离散输出时刻及适用的两侧取值。单网格上相邻输出时刻跨过阈值，只支持该近似解的判定；若需证明首次达标，还须说明先前没有遗漏的穿越，不能默认非单调过程只有一个根。静态或纯离散判定不为此虚构连续事件。

按实际风险区分空间离散、时间积分和事件定位误差。相邻网格差小或几次舍入同值支持相应尺度的经验稳定性，不自动构成连续解误差界或正确舍入证明。声称某位小数正确或离散秒数唯一时，检查有依据的误差范围是否跨越舍入/决策边界；只证明两位小时稳定时，就保留这一精度结论，不把它扩成精确到秒。

局部截断阶、代数残差、离散守恒残差和最终状态/终点误差也各有对象。瞬时离散守恒接近机器精度说明该离散平衡实现良好，不能单独证明整体数值误差或现实预测准确。

## 证明边界

- 独立复算相容：支持数值一致，不自动证明模型适合现实。
- 删除当前元素后方案变差：支持局部必要性，不证明全局最优。
- 另一算法同值：增强可信度，不自动排除共同建模错误。
- 穷尽候选或有效上下界闭合：才支持相应候选域全局最优。
- 固定方案代入新参数：只支持该方案的响应，不支持重新优化后的决策稳定。

## 内部验证器与评审可见摘要

为每条独立路径登记它是正式主求解链还是 `auxiliary_validator`，以及它实际支持哪项 E1/E2 主张。独立路径与主算法同值可以增强实现和数值可信度，但不能自动排除共同建模错误，也不能替代 E3/E4；因此不得为了“显得更可靠”把所有验证器并列成多个正式模型。

辅助验证器若需要一套较长、独立的数学合同，完整公式、分支、反例和中间诊断保存在内部技术证据。论文或已触发的人类讲解只需让读者知道：检验了什么对象或风险，使用什么设置和预先判据，观察到什么差异或残差，结论能支持到哪里。若这条独立方法实际决定正式输出、承担核心证明或是论文的主要方法比较，则不能以“验证器”为名隐藏；应升格为正式方法并回到选择、规格与稿件方法链中解释。

这不是禁止正文出现验证数学。定义误差、残差、收敛指标或简单 oracle 所必需的关系可以就地给出；边界只排除不属于主模型、且会在检验段建立第二套竞争合同的完整推导。公开摘要是否存在属于内容责任，不是新增 S6/S7 状态门。

## 失败处理

失败先定位到输入解析、规格映射、算法实现、数值设置、输出登记或规格本身。只失效引用相关 identity 或主张的消费者；不因一个局部失败抹掉无关证据，也不通过降低论文措辞掩盖尚未修复的实现错误。

修复后重新运行能区分旧错与新对的最小测试，并复核直接消费者。正式执行仍需用户请求和当前 runtime action 授权。

## 输出

每条证据记录对象、操作、输入 identity、oracle、实际结果、容差依据、方法角色、完整技术证据位置、允许的公开摘要、证明边界、支持/反驳的主张和未覆盖路径。S6 关闭时只接受当前有效的精确绑定，不以“测试很多”代替覆盖当前风险。
