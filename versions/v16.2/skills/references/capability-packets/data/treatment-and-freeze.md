# 数据处理、转换与冻结

适用于清洗、插补、纠正、重新编码、合并、派生字段、接口晋升和正式冻结。开始前应已有当前输入 identity 与审计结论；缺失时返回数据审计，而不是用处理后结果反推原始问题。

来源保留：V8 `16-data-audit-methodology.md`、`30-data-minimum.md`；采用 V14 的 ChangeSet、人工授权和消费者精确失效语义。

## 候选先于正式接口

处理方案先作为待审候选。纯读取、对账、标记和不改变观测的诊断可以先实施，但保持可撤销、可定位。删除、插补、纠正、缩尾、平滑、合并、重编码未知类别、改变单位或口径会影响下游结果时，应向人工说明：

- 问题证据与涉及记录；
- 可选处理及“不处理”基线；
- 对偏差、方差、可解释性、样本量和主张边界的影响；
- 哪些模型、图表和稿件数字会成为消费者。

只有所选方案得到确认后，才成为正式数据接口。已明确批准的规则在同一影响闭包内可批量执行，不逐记录重复确认；出现新的不可逆取舍或结论方向变化时再提交决定。

如果当前请求只是“给建议，不修改数据”，使用只读 proposal：列出包括“不处理”在内的备选、各自影响与风险、以及什么新证据或人工决定会触发选择。proposal 明确标为未执行、未冻结、未生成 processed identity；它不能登记 `treatment_decision`，也不能满足 D1→D2。只有用户授权执行并确认实际方案后，才进入下面的转换、谱系和冻结闭包。

## 不可变输入与显式转换

从不可变原始输入生成新候选，不覆盖原始证据。每个转换至少可回答：

- 使用哪个精确输入；
- 执行什么规则与参数；
- 为什么适合当前统计层次；
- 是否可逆，失败时如何识别；
- 产生哪个输出和 identity；
- 哪些下游对象消费它。

| 类型 | 最低记录 |
|---|---|
| 确定性解析 | 原文定位、布局依据、失败分支 |
| 派生字段 | 公式、单位、输入字段、边界与手算样例 |
| 纠正 | 原值、新值、直接证据、确认者、影响范围 |
| 排除/删除 | 原因、记录 ID、不处理基线、敏感性影响 |
| 插补 | 缺失机制假设、训练范围、参数、不确定性 |
| 合并/重编码 | 键、冲突策略、未匹配项、前后计数 |

响应值不能因相邻单元格非空而自动填充；结构性不存在不能与未知缺失统一插补。

## 方法选择与影响分析

缺失处理可比较完整案例、规则插补、统计/模型插补和显式缺失指示；异常处理可比较保留、稳健损失、分层建模、截尾和基于领域证据的纠正。选择不应只优化当前模型分数。

没有现实错误证据时，合理极端值默认保留，并通过稳健方法或影响分析评估。处理会改变主要结果时，至少比较“不处理”或另一合理方案，记录结论是否翻转。

## 处理后对账

处理完成后核对：

- 前后行数、列数、键和未匹配项；
- 每类增删改记录及原因；
- 单位、类型、合法域和结构性空值；
- 关键统计、合计、守恒和题面约束；
- 原始定位能否从清洁记录反向追踪；
- 代表性样例和所有关键公式能否独立复算。

审计证据必须绑定处理前输入。先改变数据再用处理后数据回填“原始审计”，无法证明审计先于处理。

## 独立复核

高风险或正式冻结前的独立验证直接读取权威输入和候选输出，不导入主处理实现或复用其解析函数。它复核关键计数、主键、公式、原始—清洁对账、关键解析样例和 identity。

另一实现得到相容结果只能支持实现一致性，不能自动证明处理方法合理；方法合理性仍依赖设计、证据和人工决定。

## 冻结与传播

冻结前复算模式签名、关键统计、约束、泄漏检查、处理决定和接口 schema。正式接口至少声明路径、identity、主键、字段/单位、适用范围、生产者与消费者。

冻结 identity 改变时，仅使真实引用旧 identity 的模型运行、图表、证据和稿件消费者失效；不按“整个项目变过”重做无关工作。重新处理后逐项核销当前闭包，不用新文件名掩盖未解决的差异。
