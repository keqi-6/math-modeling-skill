# 05 — 项目生命周期与逐问阶段门

## L-01 恢复

“接着做、继续、回顾、审计现有项目”、新会话、上下文压缩和继承工作区均触发恢复。
先把 `HANDOFF.md` 和 `project_state.json` 当作导航假设，再执行入口 K-02。全量读取
关闭前不得接受其完成状态、页数、验证或同步声明，也不得修改项目。

## L-02 项目定向

从官方材料确定竞赛、年份、题号、题内任务、期限、交付物、模板、AI 规则、团队能力和
环境。不得由文件夹名、旧 `qN` 目录或通用模板增生任务。建立原题、任务矩阵和论文标题
三处一致性。

## L-03 逐问状态

对每个独立任务记录：

| 职能 | 最小关闭证据 | 未关闭时禁止 |
|---|---|---|
| 题意 | 原题任务卡及必要人工确认 | 正式选模 |
| 数据接口 | 字段、单位、统计层次、缺测和能力边界 | 正式求解 |
| 文献导向 | 触发判断；触发时有已读来源和影响记录 | 先选模后装饰性补引用 |
| 证据重审 | 数据与来源共同支持和禁止的声明 | 把探索观察升级为结论 |
| 简单基线 | 可手检参照、结果和局限 | 只展示复杂模型 |
| 候选比较 | 含“不新增模型”的充分性与验证比较 | 把 AI 建议视为决定 |
| 人工决定 | 明确批准的模型角色与边界 | 正式实现 |
| 数学规格 | 变量、目标、约束、参数、输出、验收标准 | 边实现边改变问题 |
| 实现求解 | 与规格一致的代码和结构化结果 | 抄控制台结论 |
| 独立验证 | 独立复算关键约束与指标 | 声称技术完成 |
| 稳健解释 | 风险匹配的压力测试、机制和边界 | 无条件推广 |
| 复审冻结映射 | 人工复审、版本冻结和论文落点 | 打开依赖本问的下一问 |

简单问题可以同轮关闭多项，但每项分别记录证据。越级产物标记为 provisional，不得
反向证明上游已完成。

## L-04 文献触发

出现陌生领域机理、外部事实、辅助变量解释、方法谱系、参数依据、评价指标或验证设计时，
必须先完成文献导向。只有题面与数据已经完全决定该问且不引入外部主张时，才可在回执中
记录有证据的免检理由。

## L-05 人工理解

材料方法采用双层说明：

1. 技术层：定义、数学关系、复现与验证；
2. 读者层：问题、最小例子、本题数据对应、方法动作、结果含义、替代方案和限制。

用户明确确认读者层才关闭理解门。“继续”“可以”、沉默或成功运行均不等于理解确认，
也不等于模型、参数、实现或论文批准。

## L-06 候选晋升

候选方法、检验或图件一旦通过验证，必须重新评估其对题目答案、失败风险识别和读者理解
的信息增量。满足正文准入条件时迁入正式生产链；不准入时登记其后台证据职责。不得仅因
最初位于 `candidates/` 就永久排除。

## L-07 传播与收尾

题意、数据、假设、模型、参数或结果变化时，从最早变化层列出直接和传递消费者，重新
生成或明确失效。自然暂停、里程碑和终稿节点更新机器检查点、人工交接、当前审计和交付
镜像；同步以内容比较证明，不以复制命令证明。
