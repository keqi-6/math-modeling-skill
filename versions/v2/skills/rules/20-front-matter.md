# 题目、摘要与关键词专项规则

## 题目

题目应准确覆盖研究对象和主要任务，不虚构题号、模型能力或最优范围，不把内部算法名
堆入标题。题目必须能追溯到原题和已确认任务。

题目不使用手工换行命令强制造型；是否换行由模板、页面宽度和最终渲染决定。

## 摘要

摘要开头简洁说明研究对象、主要矛盾和全文主线，不用空泛行业套话。每项独立任务提供
与原题一致的醒目入口，并形成：

`任务 → 主要方法及本题职能 → 关键结果 → 数据说明什么 → 必要边界`

该结构先服从普通读者的理解顺序。每问先说题目要判断什么、本文实际比较或限制了什么，
再给确有辨识价值的规范方法名。方法名称不能缺席，也不能代替工作说明；当方法名陌生、
过长或同段存在多个名称时，先写白话动作，再在同句或紧邻句给出名称。不得为了满足
“写出方法”而把术语机械插进结果句。

摘要采用无编号标题并按论文正文栏宽排版；在 `ctexart`/`article` 中优先使用
`\section*{摘要}` 后接普通正文，不直接使用会通过 `quotation` 等机制自动增加左右
缩进的标准 `abstract` 环境。只有官方模板明确要求窄栏摘要时才保留其缩进。编译后须
把摘要左右边界与正文文本区实际比较，不能只检查“摘要是否位于第一页”。

要求：

- 多问任务使用与原题一致的加粗入口，使评委能立即定位每问；只加粗入口，不加粗整段；
- 覆盖原题全部任务和正文全部 A 级工作；
- 主要模型名称与具体动作就近对应，不能只列名称或完全隐去方法；摘要保留的每个名称
  都必须帮助区分主要路线，否则移回正文；
- 每问前一至两句必须先让读者明白“要回答什么、实际怎样比较或选择”，不得以
  “采用某模型、构造某指标、进行某检验”的并列术语清单开篇；
- 执行全文通用的术语预算：连续出现三个新名称、缩写或外文词时必须拆分，并移除不
  影响摘要判断的名称；不能靠括号和顿号压缩术语；
- 关键数字按全文通用数据闭环解释，不形成数字清单；
- 正文已有证据的结构性亮点必须进入摘要，不能自称创新；
- 摘要不得依赖正文解释首次术语；
- 原则上不放展示公式和图表；
- 编译后摘要和关键词完整位于第一页，二者之间留一行，正文从下一页开始；
- 摘要超过一页时先报告冲突并提出删改候选，未经用户确认不得删减必要内容或压缩字号、
  行距、标题和关键词间距。

动笔前将候选信息分为：直接改变答案或成立条件的A项、影响可靠性或边界理解的B项、
实现和重复诊断的C项。摘要必须保留A项，按篇幅选择可自足解释的B项，C项留在正文；
完成成本高或技术名称多不构成进入摘要的理由。

摘要定稿前建立双向映射：

1. 正文关键工作 → 摘要对应句；
2. 摘要术语和结论 → 正文首次定义、公式或结果证据。

任一方向存在空项，摘要不得通过。

## 摘要盲读与去术语门

定稿前把摘要单独交给不了解正文的普通读者视角检查，逐问完成两次复述：

1. **完整盲读**：能够说明题目要解决什么、本文具体做了什么、得到什么、结果为何回答
   题目以及重要边界；
2. **去术语盲读**：遮去模型名、指标名、缩写、公式和结果数字后，剩余文字仍能说明
   比较对象、操作、判断方向和决策意义。

任一问只能复述“用了某方法”“某指标更好”或必须翻到正文才能理解时，摘要判为
`fail`。不得通过追加更多术语定义修补；先删除非必要术语，把必要方法改写为白话动作，
再就近恢复最少的规范名称。

摘要审计暴露的是全文回归风险。若摘要中的术语、对象、数字身份或判断理由失败，应搜索
正文首次使用、公式解释、表头图注、结果讨论和结论中的同类表达；不得只改摘要后宣布
问题关闭。

## 关键词

关键词反映研究对象、主要模型和任务类型，通常不放实现工具、内部缩写或未在正文稳定
使用的自造名称。
