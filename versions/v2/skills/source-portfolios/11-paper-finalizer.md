# 11 — 论文终稿组装

> 来源：Hermes skill `mathmodel/paper-finalizer`
>
> **唯一职责：**把已通过内容与证据审计的材料组装成合规提交包，并判定交付边界。
> 本文件不替代 `03` 的内容规范，也不重复 `05` 的全文审计。

---

## 强度

当届提交、匿名、文件完整性和已核验 AI 义务为 A/C；标准目录、附录形态、固定流程和
句法检查为 D。

## 论文结构示例

终稿必须从项目唯一 LaTeX 主入口编译生成，不接受从 Word、Markdown 或其他平行主稿
导出的 PDF 冒充当前论文版本。排版固定执行 `02` 中经用户确认的《数模论文模板
（修改版）》正文明示条款；DOCX 隐藏页面设置不得冒充模板要求。若当届官方文件与之
冲突，先提交用户裁决。下列结构用于检查常见组成；文档类、标题层级和章节组织按
`02` 执行，摘要段数、页边距、分页命令和附录形态按已确认项目设置与官方要求审计：

```latex
\documentclass[12pt,a4paper]{ctexart}
% preamble 见 skills/02-latex-setup.md

\begin{document}

% === 摘要（无编号，独占一页）===
\section*{摘要}
... [按实际问题数量组织]
\textbf{关键词}：从摘要中选取能够检索论文主题与核心方法的规范术语

\newpage

% === 正文 ===
\section{问题重述}
\subsection{问题背景}
\subsection{问题提出}

\section{问题分析}

\section{基本假设}

\section{符号说明}         % 表格或逐项说明须服从指定模板

\section{模型建立与求解}
% 按原题任务设置醒目入口；内部标题按实际模型、求解、结果和检验组织
% 检验紧邻其支撑的模型、结果或结论，不机械集中到独立总章

\section{模型评价与推广}
\subsection{模型评价}
% 评价优势、局限、成立条件和适用范围
\subsection{模型推广}
% 说明可迁移对象、必要调整和不能直接外推的边界

\section{结论}

% === 参考文献 ===
\begin{thebibliography}{99}
\bibitem{...} ...
\end{thebibliography}

% === 附录 ===
\newpage
\section*{附录}
% 源码、文件清单与复现材料的形态服从项目用途和当届官方规则

\end{document}
```

只有多个任务共享同一组不确定性来源，且统一分析能够形成新的跨任务结论时，才单独
设置稳健性章节；即使单设，也必须逐项回指其检验的模型、结果和结论。否则将灵敏度、
独立验证、反事实或复算放在对应任务附近，形成就地证据闭环。

## 先执行官方提交检查

本节仅适用于正式 CUMCM 参赛提交。教学练习、课程报告或期刊投稿应先在项目 README 中声明适用规范，不得把竞赛提交要求无条件套用到所有项目。

项目启动时记录“项目用途—适用年份—附录源码要求—支撑材料要求”，终稿阶段重新
核验。正式参加要求在论文附录中列出完整可运行源码的竞赛时，必须嵌入全部建模源码
及必要运行命令，文件清单不能替代源码正文，并按规定在支撑材料中提交对应可运行文件。
当适用规范允许源码只放独立支撑材料，或项目属于教学练习、往届复盘、期刊等其他用途
时，不机械把全部源码塞入论文附录；附录至少提供适用规则要求的文件清单、复现说明和
正文实际引用的必要材料。

- 摘要页、正文页数、电子文件格式和大小符合当届规范；
- 论文与支撑材料中无身份、学校和赛区信息；
- 附录和支撑材料按当届规则放置源码、文件清单与复现说明；不把“全部源码必须打印在
  正文附录”当作通用要求；
- 自主查阅的数据资料随支撑材料提交；
- 所有公开资料在正文标注并列入参考文献；
- AI 使用方式符合当届专项规定，作者对原创性、真实性和准确性负责。

### AI 使用专项检查

现有依据为《全国大学生数学建模竞赛人工智能工具使用规定（2025 年试行）》，且 2026 竞赛规则继续要求遵守该规定。提交前仍需检查是否有新版。

使用 AI 时：

- [ ] AI 生成内容已在正文相应位置标注；
- [ ] 参考文献列出工具名称、版本或型号、开发机构或公司、使用日期；
- [ ] 支撑材料中存在文件名为 `AI 工具使用详情.pdf` 的说明文件；
- [ ] 说明文件列出所有工具名称和版本；
- [ ] 逐项说明具体使用目的和环节；
- [ ] 保存关键交互记录，包括重要提示词与回复；
- [ ] 说明哪些内容被采纳、哪些未采纳以及人工修改情况；
- [ ] 核心建模与分析由参赛队独立完成。
- [ ] AI披露说明辅助范围、采纳程度、人工判断、修改和验证，没有把AI参与过的整章
      笼统标成AI生成，也没有把工具启发误写成AI对成果或思想的所有权；
- [ ] AI辅助代码生成的确定性数据图按代码辅助披露，未误标为生成式AI图像；只有AI
      直接生成或实质修改图像内容时，才在对应图件位置披露图像生成或编辑；
- [ ] “人工审计后采用”具体说明核查了哪些假设、推导、边界和结果，而不是用一句
      “已审核”替代采纳、修改和验证记录；
- [ ] 以人类是否具有理解、选择、修改、验证和责任能力判断实质控制；空白纸推导、
      反例、变式、纠错和迁移只作为参赛者自检，不声称AI能够认证人的内在思考或
      裁定成果归属。

未使用 AI 时：

- [ ] 在参考文献之后明确声明“本参赛队未使用任何 AI 工具”。

上述披露要求缺失会被视为违反竞赛规则，并导致取消评奖资格。

### 用 Nature Portfolio 框架解释 AI 使用边界

该框架既可用于教学练习和科研报告，也可帮助解释 CUMCM 规则未定义的概念，但不能
取代或削弱竞赛正文标注、工具书目和详情文件等明文义务。规则位阶与解释原则见
`12-source-audit-and-provenance.md`。

- 大语言模型不具备作者资格，作者对最终内容承担责任。
- 仅用于可读性、风格、语法、拼写、标点和语气改进的 AI-assisted copy editing，
  按 Nature 政策不属于需要声明的实质性生成；若竞赛详情文件要求记录全部用途，仍
  应如实记录为“表达整理”。
- 模型讨论、代码生成、数据分析、图表生成或自主生成正文属于实质性使用，应在 Methods 中记录；没有 Methods 时可放在等效的独立说明中。
- Nature 场景通常可集中披露；正式竞赛是否还需对应位置标注，以当届竞赛明文为准。
- 说明至少包括工具名称和版本、使用范围、作者如何复核与修改。
- AI 辅助编写确定性绘图代码属于代码辅助，不自动把程序图转化为生成式 AI 图像；
  AI 直接合成或实质修改像素时，才按生成式图像处理并审查来源和可追溯性。

建议集中声明：

> 本文在模型讨论、程序实现与文字初稿整理过程中使用了大语言模型辅助。所有数学定义、算法选择、程序输出、图表和结论均由作者结合原始数据独立检查、复算并修改，作者对最终内容承担全部责任。

## 内容质量自检

- [ ] 逐项对照题目原文，所有问题和小问均有明确结论
- [ ] 先梳理模型步骤及并列、从属、依赖关系，再形成标题；不存在两个标题之间没有正文
- [ ] 每问开头有总括段，模型求解前已交代已知量、未知量、参数、完整目标与约束关系
- [ ] 关键公式前说明目的和对象，公式后解释数学作用或现实含义；相邻同职能公式组可
      共享解释
- [ ] 图表数量由表达需要决定；每幅图表都在正文被引用、解释并提供不可替代的信息
- [ ] 已从任务、模型和主要声明反向检查图表完整性；不存在应图示/列表却只藏在正文、
      代码或内部文件中的关键空间关系、趋势、阈值、权衡、完整方案或精确对照
- [ ] 已审计载体选择：精确查询与完整清单用表，空间、路径、趋势、分布、阈值和权衡
      用图，简单单值用正文；已有图表不存在明显的载体错配
- [ ] 图表通过双向删除检验；同一数据没有仅因载体不同而被表格和图像完整重复表达
- [ ] 同时保留的图表职责明确：表格负责精确查询或完整清单，图像负责空间、趋势、阈值或机制增量
- [ ] 关键图表的解读包含关系、现象和结论，必要时说明其决策作用
- [ ] 每幅图和每张表均通过内容审计：对象、数值、单位、版本、编码、标题和支持声明
      可追溯且一致，无漏项、错配、重复统计或结论外推
- [ ] 每幅图和每张表均通过质量审计：最终PDF尺寸下清晰可读，无模糊裁切、标签碰撞、
      图例遮挡、表格越界截断、浮动错位、跨页断裂或整页压迫
- [ ] 每幅图表均按“首次实质引用—图表—紧随其后的就地解释”形成局部闭环，中间没有
      无关标题、其他图表或论证；使用 `[htbp]`、浮动屏障或 `[H]` 后已检查当前页及
      相邻页，没有用大块空白、越界或不可读缩放换取表面邻近
- [ ] 全篇按 Nature 规范统一颜色语义、符号、字体、线宽、面板编号和坐标单位；颜色
      不是唯一编码，红绿组合与彩虹色阶已避免，灰度和低对比条件下仍可辨认
- [ ] 图内英文与数字优先使用 Arial 或 Helvetica，普通文字原则上为 `5--7 pt`，
      多面板标号为 `8 pt` 粗体正体小写字母；最终 PDF 尺寸下全部清晰可读
- [ ] 线图和结构图优先保留为可编辑矢量图，照片类位图在最终尺寸下至少为 `300 dpi`，
      没有用插值放大冒充真实分辨率
- [ ] 标题字号逐级与指定模板核对，低级标题没有未经允许小于正文
- [ ] 检验覆盖关键模型与关键结论，形式可为灵敏度、独立求解、反事实或手工复算
- [ ] 摘要覆盖全部小问、全部 A 级工作、关键结果和可核验亮点，并按需纳入可自足解释
      的 B 级证据；C 级实现与重复验证留在正文
- [ ] 已从正文建立 A/B/C 内容表；改变可行域、目标顺序、政策条件、推荐结论或适用
      边界的 A 级工作均能定位到摘要中的对应动作或结论
- [ ] 摘要按原题实际任务与正文逐项对应，每项具有醒目且一致的加粗入口；多问题且原题
      使用“问题一、第（1）小问”等编号时，优先使用加粗的“针对问题一，”“针对
      问题一第（1）小问，”等直接映射形式，只加粗入口且没有合并任务或虚构层级；
      原题采用其他结构时未被强行改写成该句式
- [ ] 隐藏正文后，仅凭标题即可快速定位各项任务、主要模型、关键结果和检验；模型建立、
      求解、结果解释、检验和必要小结等内容职能均得到覆盖，但未被机械拆成固定五段
- [ ] 摘要中的主要模型与亮点均能映射到正文标题及公式、结果或检验证据；名称一致，
      不需要逐段搜索才能找到
- [ ] 摘要逐问说明模型解决的问题、关键动作和重要结果；保留的检验或边界说明了对象、
      操作与结论含义，没有“复核最优值”等悬空短语
- [ ] 摘要术语可理解，不以模型名称代替工作说明
- [ ] 所有术语判断前已从当前权威导航定位并读取唯一术语口径表；摘要、符号表、正文
      多数用法和代码名称均未被反向当作术语权威
- [ ] 摘要中的每个模型名、约束名和评价指标都能定位到对应正文的显式定义、公式和结果
- [ ] 已将摘要审计暴露出的对象落地、动作闭合、指标定义、条件绑定、比较基线、数值
      身份、概念分层和证明强度规则反查全文；正常且唯一的近距离回指未被误判为缺陷
- [ ] 摘要—正文—结果追踪同时核对题意与已确认任务、方法、公式、代码、冻结结果、
      图表、正文、摘要和结论，没有把任一处文字或文件当作孤立基准；冲突已定位到
      最早的无证据或错误层，并从该层向全部下游传播修正
- [ ] 每项修改均完成“一修全修”：已搜索术语全称、简称、同义表达、关联数字和条件，
      并同步复核摘要、正文首次定义、公式解释、表头图注、结果讨论、结论、双向映射、
      当前审计、复现文档和交付副本；不存在只修暴露句而保留其他旧口径的情况
- [ ] 除题号、公式、文献与必要缩写外，括号不承载完整条件、结论或长解释
- [ ] 摘要与关键词隔开一行，且编译后两者均在第一页
- [ ] 存在实质替代方案时已比较关键方法；不存在时说明为何无需为凑数增加模型
- [ ] 模型局限诚实陈述
- [ ] 每个“模型求解”小节均能在不阅读代码的情况下沿数学逻辑复推
- [ ] 遮去模型名称和结果数字后，正文仍能解释现实矛盾、选模理由、变量联动和作用机制
- [ ] 从摘要到结论连续顺读后，各段只有一个主要功能，段首说明来意，段末给出落点或过渡
- [ ] 深度语言审计或高风险段落可给句子标注来意、定义、动作、理由、证据或落点；
      常态检查只要求句子功能可辨，不机械生成六类标注
- [ ] 分类、等价、上下界、分支排除、最优性、改善原因、稳健性和适用性等判断均有
      同句或紧邻前句的真实理由；机制先于规范术语，证明范围紧邻结论
- [ ] 借鉴只修复本稿具体不足，没有复制原句、套用异题表述或继承参考论文的表达缺陷
- [ ] 相邻问题之间说明评价口径的继承或研究尺度的变化，小结不重复完整结果清单
- [ ] 政策建议与真实求解情景一致，从零重构、固定数量搬迁和保留原址增量建设不混用
- [ ] 关键约束均说明违反后会出现的错误方案，目标函数说明怎样推动方案变化
- [ ] 每个完整模型在公式后有白话总括，结果段解释改善来源、代价和未解决问题
- [ ] 正文说明候选方案如何形成、如何比较和排除，以及停止条件或最优性依据
- [ ] 可行性、当前解不可删、全局最优和稳健性没有被混为同一命题
- [ ] 软件版本、接口名、函数名、文件路径、运行状态和序列化细节留在附录或复现文档
- [ ] “变量/约束规模”“求解器返回最优”“最优性间隙”为补充证据，而非算法主体
- [ ] 参考文献数量和语种足以支撑正文，没有凑数
- [ ] 正文引用所有参考文献
- [ ] 已按项目用途、适用年份和当届规则处理源码；要求附录含完整源码时，代码真实、
      完整、可运行且未被文件清单替代；允许独立支撑材料时，附录与支撑材料分工合规
- [ ] 只写入评审能够从最终 PDF 直接看到并使用的附录内容；不要用项目目录清单代替可见证据

## 摘要的工作版与定稿

摘要可在早期建立工作版，用于任务映射、术语统一和缺口检查，但不得把工作版视为最终
证据。正文、主要结果、检验或文献发生变化后，必须同步更新摘要；只有这些内容稳定且
完成摘要与正文、结果之间的双向追踪后，摘要方可定稿。具体日程服从项目进度与依赖，
不固定为三天流程。

摘要定稿必须同时通过内容检查与版面检查。内容检查关注全题覆盖、具体动作、结果和
亮点；版面检查必须查看最终 PDF，确认摘要不跨页、关键词醒目、正文从下一页开始。
超过一页时按 A/B/C 级别列出套话、实现信息、局部诊断和重复验证等候选删减项，不能
把解释主要模型如何工作的 A 级短语作为单纯版面压缩对象；所有文字精简必须经用户
确认，不得通过压缩规范版式解决。

版面检查只报告问题，不自动授权修复。若摘要超过一页、正文超过规定页数，或出现跨页、
孤悬、留白、图表漂移，必须保留已确认内容并报告变化。仅可在图件仍清晰完整且不改变
内容和视觉语义时先行调整其论文显示尺寸；未经用户明确确认，不得删改正文，也不得
调整字号、字体、行距、字距、页边距、段间距、标题间距、分页、图表顺序或浮动参数。
既有页数不是高于内容完整性的硬约束。

## 常见反模式

| 反模式 | 修正 |
|--------|------|
| "我们的模型最优" | "在测试方案中，X 方法在 Y 指标表现最好" |
