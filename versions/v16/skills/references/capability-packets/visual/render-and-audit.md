# 图件渲染、版面与人工视觉审计

适用于独立图件验收、LaTeX/PDF 图表排版、字体检查、最终页面审计和图件准入。选中本包后应检查实际渲染产物；源码正确、脚本退出码为零或文件存在都不能代替视觉判断。

来源保留：V8 `04-figure-generator.md` 的三组/三轮审计、`27-visual-layout-acceptance.md` 的字体与 PDF 检查、`34-visuals-minimum.md` 的最低质量边界，以及 V14 的 identity 与影响闭包。

## 四层验收

| 层 | 要回答的问题 |
|---|---|
| 身份 | 输入、生成器、图源、矢量输出、审阅位图和论文引用是否属于同一版本 |
| 内容 | 对象、数据、单位、排序、阈值、公式、拓扑和图注是否正确 |
| 可读 | 字号、线宽、颜色、图例、标注、遮挡和灰度退化是否合格 |
| 版面 | 最终栏宽、分页、裁切、浮动、留白、分辨率和嵌入是否合格 |

四层分别判定。内容正确不能抵消不可读，画面漂亮不能抵消数据或拓扑错误。

新建图件绑定 `artifact/A0` 时，A0 只表示尚未人工批准，并不豁免本次创建步骤的验收。只要本步已经生成、渲染或审计实际图件，就必须在晋升 A1 前选择并完成来源/拓扑真实性、最终渲染实看、源—输出同步、标签、字体、最终尺寸可读性和非纯颜色编码等适用 atom。图注与论文放置仅在实际发生 `visual_embed` 时选择，独立图件审计不为二者制造 N/A。创建步骤不能以“以后再 audit”为由留下一个已经对外使用却从未看过的 A0 渲染件。

## 全文载体审计

从题目任务、关键模型结构、主要结果、完整方案、空间关系、趋势、分布、阈值和权衡反向建立“读者必须看见什么”的清单：

- 是否有关键证据只藏在正文、代码或内部文件；
- 每项主要结论是否有合适载体，但不机械要求每条结论配图；
- 图、表和正文是否各有不可替代职责；
- 图表是否展示了正文声称的完整对象或条件；
- 不增加图表时，理由是否是关系简单、数据不足或只能重复现有证据。

禁止设定“至少五幅图”等与任务无关的固定数量。

## 单件内容审计

逐图、逐表核对：

- 回答哪个问题、支持哪条主张、为何需要这种载体；
- 对象集合、筛选、单位、舍入、排序和版本是否与冻结结果一致；
- 点、线、颜色、形状、阈值、面板、表格行列和最优标记是否均有定义；
- 图题、图注、表注和正文的对象、情景、符号与例外是否一致；
- 可直接观察的现象是否真的支持正文结论；
- 局部案例、相关性和单一情景是否被过度外推；
- 与相邻载体双向删除后是否暴露完整重复。

概念示意图必须明确标为非数据图；示意性距离、面积和位置不能让读者误认为定量比例。

## 三轮视觉审计

### 1. 独立图件

实际打开 PDF、SVG 渲染图或 PNG，检查：

- 标签、节点、引线、数据点和图例是否重叠；
- 线条是否被节点或填色完全遮挡；
- 坐标、单位、面板标号和数学符号是否一致；
- 背景信息是否压过关键结果；
- 关键结论能否在数秒内定位。

### 2. 最终 PDF 页内尺寸

编译论文并查看受影响页面及相邻页：

- 缩印后最小文字、细线和标记是否仍可见；
- 首次引用、图件、题注和图后解释是否形成连续闭环；
- 图表是否造成整页压迫、大块留白、孤行、孤题或叙事顺序错乱；
- 是否裁切、拉伸、压缩失真或发生表格越界；
- 图表编号、引用和浮动顺序是否一致。

### 3. 退化与可访问性

- 转灰度后关键系列是否仍可区分；
- 低对比显示和普通打印下是否仍可读；
- 颜色相近时是否还有形状、线型、明度、空心/实心或标签冗余；
- 最终页内最小字体和线宽是否仍清楚。

发现问题后重新生成、重新编译并复查。表格即使没有独立图像文件，也必须核对源数据并在最终 PDF 中检查列宽、换行、对齐、分页和表注。

## 字体与 LaTeX

官方当期模板和用户确认优先。字体名称描述排版角色，不等于当前编译环境一定安装：

1. 首次编译、迁移机器或切换 TeX 环境后，确认实际编译器路径与版本；
2. 在该编译器所在环境查询中文衬线、中文无衬线和西文衬线字体；
3. 先编译包含中文题目、各级标题、正文、标点、英文、数字、单位、公式、粗斜体和题注的最小样张；
4. 检查日志中的字体错误、缺字、未定义引用和越界盒；
5. 用 `pdffonts` 或等价工具核对字体嵌入，并目视查看代表页面。

精确模板字体不可用但草稿允许工程替代时，记录“要求字体—实际字体—替代理由—适用范围”，并明确它不等于精确模板合规。精确字体属于正式交付硬条件时，不得静默替代。

正式稿只保留一个权威主入口。编译成功不能证明 Markdown/LaTeX 源边界、字体、引用、分页或图表含义正确。

## 机械检查支持

当图件合同要求同时交付可编辑源、SVG、单页 PDF 和审阅 PNG 时，可运行历史机械检查器：

```bash
python3 -B scripts/validate_figure_assets.py \
  --source "<figure-source>" --svg "<figure.svg>" \
  --pdf "<figure.pdf>" --png "<figure.png>"
```

它检查配套文件、SVG `viewBox` 与可检查矢量内容、未经许可的栅格嵌入、PNG 像素、PDF 签名/页数和 Type 3 字体；阈值和允许项应来自当前载体合同，不把默认值冒充所有项目规范。`pdfinfo` 或 `pdffonts` 不可用时相应结果是未检查，不得写成通过。若当前图件不要求四种载体，不为迎合脚本机械制造文件，应改做适合当前载体的检查。

该脚本的 `passed` 只代表上述机械条件。它不能判断拓扑、受力、几何、数据真实性、标签实际拥挤或审美，也不能替代本包三轮目检和必要人工确认。

## 版面修复边界

先定位留白、漂移、越界或孤题的真实原因。在保持清晰度的前提下，可先调整图像显示尺寸并复查页面；不得为了塞版静默删除必要证据、缩小到不可读字号、裁剪图件或改变数据语义。

改变正文顺序、必要内容、字体、行距、页边距、标题间距、图表顺序或浮动策略可能影响全文，应按用户授权和最小一致性闭包处理。已获授权的局部版面修复不需要反复确认每个微调，但新的内容取舍或正式模板偏离必须提交人工决定。

## 自动与人工的边界

自动工具适合检查：文件配套、SVG 结构、像素尺寸、PDF 页面、字体嵌入、引用和基础碰撞信号。它不能判断拓扑是否忠于题面、力是否正确、数据是否支持结论、标签是否真的拥挤，或图是否美观。

自动通过与脚本无报错都不能替代独立图件、最终页面和退化条件下的人工验收。正式准入记录至少包含审阅对象 identity、实际打开的产物、发现、修复和复检结论。
