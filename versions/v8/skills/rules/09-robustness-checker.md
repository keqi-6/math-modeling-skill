# 09 — 稳健性与灵敏度检查

> 来源：Hermes skill `mathmodel/robustness-checker`

---

## 职责与强度

本文件从声明失效机制设计验证、灵敏度和不确定性试验。冻结归 `10`，论文表述归 `03`，
充分性判定归 `05`。现实扰动、基准一致和禁止外推为 A/B；脚本拆分、格式和网格为 C/D。

## 检查类型速查

### 0. 模型结构检验

每问S6必须先从模型主张识别一种实质失败风险，再选择能够击中该风险的结构检验。可选
方法包括量纲与不变量、极限或退化情形、对称或守恒关系、单调与边界行为、已知解析解、
反例、约束消融、支配或排序反转。检验必须使用模型之外的必要性质、独立关系或可证反例，
不能把重复代入同一公式、产物哈希一致或另一实现同值当作模型结构检验。

V3模型结构检验是每问硬出口，不得标记`not_triggered`。没有实测数据只影响V4现实模型
确认：可依据题面理想用途把V4记为`not_triggered`，同时明确现实域没有得到确认。

### 1. 参数灵敏度

扰动范围应来自测量误差、业务场景、文献区间或阈值政策；±5%、±10%、±20% 只能作为缺少先验时的探索网格，不能冒充现实不确定性。

优先检查会改变可行域、最优决策或主要结论的参数，并分别标注其来源、基准值、现实区间和扰动机制。

### 2. 模型对比记分牌

在同一特征集上对比不同模型：
- 基线方法 vs 改进方法
- 记录端到端指标（不是中间指标）

对比必须使用同一输入、约束口径和评价指标，并包含现实基线或简单基线。

### 3. 数据扰动

- 删除、加噪、重采样之前先说明它模拟的现实机制；
- 图网络删点可能改变连通性，必须同时报告连通分量、不可达对和可行性；
- 优化问题报告目标变化、决策稳定性、约束违例和最优性界，不只报告“位置是否相同”。

### 4. 约束松弛

对关键阈值分别收紧与放松，观察可行性、资源需求、目标值和决策结构的变化。阈值范围必须有现实或政策含义。

### 5. 小规模穷举或独立求解验证

对缩小实例或可枚举子空间求精确解，与主算法比较；同时做约束逐条复算、单位测试和手算样例。测试规模与结果必须冻结，不能把小规模正确性外推为大规模全局最优。

## 执行模式

灵敏度检查必须可复现，并把支撑论文声明或下游使用的输入、输出与结论冻结到适合的
结构化产物。可按共同输入、运行成本和职责组织一个或多个脚本，不强制一项一脚本或
统一使用 JSON。例如：

```
src/q1/10_robustness.py → output/q1/robustness.json
```

若选择 JSON 作为该检查的产物格式，至少包含检查名称、输入扰动、输出变化和结论；
使用其他结构化格式时保存等价字段或模式。

每问另建“模型主张—结构失败风险—V3检验—判据—结果—证明边界—论文拟落点”映射。
灵敏度只有在参数依赖或决策切换确为结构风险时才进入该映射，不是V3的固定同义词。

先从声明台账建立“声明—失效机制—可观测指标—测试”映射。对固定方案代入新参数与
参数变化后重新优化分别命名、分别报告；二者回答不同问题。若多个不确定量可能共同
变化，采用联合情景、抽样或结构化试验，但不为显示复杂而强制固定参数数目、抽样方法
或图表数量。

## 反模式

- 灵敏度结果只在论文文字中提及且没有可复核的冻结证据 → 不可验证
- 声称"结论稳定"但未给出扰动边界
- 扰动范围没有现实误差、阈值距离、政策区间或探索目的依据 → 无法支撑稳健性主张；
  ±1% 是否有意义取决于系统敏感度和结论所在尺度
