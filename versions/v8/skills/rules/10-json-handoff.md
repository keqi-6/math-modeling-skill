# 10 — 可追溯产物交接规范

> 来源：Hermes skill `methodology/pipeline-json-handoff`

---

## 职责与强度

本文件维护机器产物的生产者、模式、消费者、版本、失效和真实性。格式、编号和路径是
实现选择，不能反向定义证据链。生产者—消费者、输入版本、真实性和失效传播为 A/B；
JSON/NPZ/CSV、编号与头部格式为 C/D。

## 核心规则

每段跨脚本流转的数据必须有明确生产者、消费者和模式。JSON 用于小型结构化元数据；
矩阵可用 NPZ，表格可用 CSV/Parquet。数据图、统计图和数值结果图必须追溯到冻结的
数据产物及生成程序；流程图、结构图、几何或机制示意图等非数据图，必须追溯到明确的
模型定义、公式、拓扑关系、设计说明或其他权威来源，并登记生成方式与版本。不得为
满足形式要求虚构数据产物，也不得仅靠 stdout 或从论文反向抄数。

每个当前有效的生成产物都必须登记生产者、用途、版本以及至少一个直接消费者。消费者
可以是下游脚本、图表生成过程、论文或方法文档中的声明、独立验证、审计检查或者最终
交付材料，不限于脚本。无生产者、无登记用途、无有效消费者、版本状态不明，被新版本
替代却仍标为当前权威，或者临时调试文件混入正式输出目录时，判为孤儿文件；没有下游
脚本读取本身不构成孤儿，终端证据必须登记其支撑的声明、图表、验证或交付职责。

## 依赖顺序

- 用清单、入口脚本、工作流配置或明确文档表达无环依赖图；文件名可使用编号帮助阅读，
  但不要求连续，也不以编号大小证明生产者先于消费者

## 脚本头部规范

产生结论、冻结产物或被其他脚本调用的程序必须提供中文可读的输入、输出和职责声明；
可用中文 docstring、文件头注释、集中清单或工作流配置表达，不固定载体。无论采用
哪种载体，都必须能从脚本快速定位，且与真实读写行为一致；集中载体中的字段也必须
具有足以让人理解的中文解释。单文件脚本或没有集中工作流清单时，极其推荐使用：
```
# 输入: upstream_file_1.json + upstream_file_2.npz
# 输出: output_file.json
# 职责: 用中文说明该脚本完成的数学或数据动作
```

输入：列出所有读取的文件
输出：列出冻结输出文件

支撑论文声明、供下游消费或复核所需的数字不得只存在于 stdout；进度、调试和临时
诊断可以只打印，不因“值得打印”就全部冻结。

## 基线模式

下游脚本需要“基线”时，应由数据准备或前期基线脚本生成独立、冻结且带版本的权威
基线产物。产物格式根据结构选择 JSON、NPZ、CSV、Parquet 或其他可复核格式，不固定
为 JSON。

- 下游模型、验证和比较程序读取同一权威基线产物，不分别重算出多个口径；
- 不读取后期模型选择、优化或结果汇总产物来反向定义基线；
- 登记基线的生成时点、输入版本、定义口径、生产者和消费者；
- 保持依赖关系无环。

## 审计检查清单

流水线完成后从正式产物清单出发逐项核对，不从某一种写入函数反推产物是否完整：

1. 每个正式产物具有生产者、实际生成路径、格式或模式、输入版本、产物版本和哈希；
2. 声明输出与实际文件一致，文件能够读取且内容非空；
3. 每个产物具有有效消费者或终端证据职责；
4. JSON、NPZ、CSV、Parquet、图像对应数据及其他正式格式都进入检查范围；
5. 写入函数搜索只用于发现可能遗漏的读写点，不能单独作为通过依据。

辅助搜索可按项目实际库和封装方式调整，例如：

```bash
rg "json\\.dump|savez|to_csv|to_parquet|savefig" src/
rg "KEPT\\s*=\\s*\\[" src/  # 结果须逐项做数字角色与来源审计
```

搜索未命中不证明没有输出，命中也不证明声明、模式、版本和消费者闭合。

## 运行清单与版本

每次正式运行保存运行清单：脚本版本或 Git 提交、输入文件哈希、参数、随机种子、求解器版本、开始结束时间和产物哈希。升级时优先保持单一代码源和可区分的运行目录，避免复制整套脚本造成分叉漂移。

每个冻结产物还应登记生产者、直接消费者和支撑的声明。上游解释、数据、假设、目标、
约束或参数发生实质变化时，将直接消费者和传递消费者写入
`project_state.json.invalidation_queue`；完成重跑、复核或确认不受影响后，才能关闭。
旧产物可以保留追溯，但不得继续标记为当前权威。

## 工作日志的真实性边界

- 从项目开始按实际发生顺序记录关键修改、运行、验证和交付，记录时间、对象、原因与结果；
- 不得为补齐档案而虚构过去的时间戳或操作。只能根据文件哈希、运行清单和产物依赖重建
  “可确认的历史”，并显式标为事后重建；
- 区分“完整流水线重跑”“局部脚本重跑”“只修改并编译论文”，不得用一次编译冒充全部
  数值重新生成；
- 论文或结果改变后同步更新运行清单和产物哈希，使工作日志、冻结结果与最终交付版本一致。
