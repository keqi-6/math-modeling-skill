# V7 大型 Skill 架构决策记录

状态：研究结论已形成；规则迁移尚未闭合；不得据此宣称 V7 完成。

## 1. 本轮要解决的问题

V7 的目标不是缩短规则总量，而是在不丢失既有能力的前提下，解决以下问题：

1. 入口文件过载，启动时加载成本高；
2. 同一职责被多个文件重复声明，但权威归属、覆盖关系与冲突优先级不清；
3. 部分规则存在却没有稳定触发路径，属于“有内容但不可达”；
4. 旧版验证偏重文件、路径和哈希，不能证明真实任务能力没有退化；
5. 迭代时缺少逐条能力映射，容易把“精简入口”错误地变成“删除语义”。

## 2. 外部架构证据

### 2.1 渐进披露压缩加载量，不压缩能力总量

Agent Skills 开放规范把内容分为三层：启动时只加载名称和描述；触发后加载 `SKILL.md`；详细资料、脚本和资产按需加载。规范建议主入口少于 500 行、引用保持一层深度，同时允许详细资源继续保存在独立文件中。

本项目据此采用：短入口 + 一层确定性路由 + 完整详细规则。禁止把“入口应短”解释为“规则应少”。

### 2.2 模块按任务情境拆分，不按字数机械合并

Anthropic 的工程说明建议：互斥或很少共同使用的情境应走不同引用路径；确定性工作应交给脚本。模块边界因此应由触发条件、职责和验证方式决定，而不是由文件数量或总行数决定。

### 2.3 大型 Skill 的难点是选择、编排与冲突，不只是目录结构

Agent Skills 综述把大规模技能选择、组合编排、冲突解决、权限和验证列为仍需解决的核心问题。因此 V7 必须显式维护触发条件、责任所有者、依赖、冲突优先级和失败回退，不能仅靠自然语言“需要时阅读”。

### 2.4 验证必须覆盖真实行为和结果

Agent 评测实践区分任务、执行轨迹和最终环境结果，并建议组合代码检查、轨迹检查和结果检查。V7 因此不能把“文件存在、哈希相同、关键词出现”当作能力保持的充分证据。

## 3. V7 不可违反的反压缩原则

1. **完整基线原则**：V6 全量内容是 V7 的迁移输入，不从早期精简版重新起步。
2. **原子能力原则**：每个规范性要求都必须获得稳定标识，并映射到 V7 的唯一主责位置。
3. **零孤儿原则**：任何原子能力都必须拥有触发路径、主责文件、适用阶段和至少一种验证方式。
4. **先映射后改写原则**：能力账本闭合前，不删除、不合并、不降级任何详细条款。
5. **语义保持原则**：允许修改历史规则的表达与组织，但迁移必须证明行为覆盖；字节不变不是目标，能力不退化才是目标。
6. **重复显式化原则**：重复内容只能标为“主责、摘要镜像、交叉验收或真正冗余”之一；真正冗余的删除需要来源映射和回归测试。
7. **可达性原则**：入口到详细规则最多一层引用；所有条件触发规则必须能由机器注册表枚举。
8. **真实评测原则**：结构校验只能证明包可用；能力保持必须另有正例、反例、冲突例和恢复例。
9. **批准隔离原则**：题意批准、模型批准、结果批准、草稿批准和正式稿晋升是不同事件，不得相互推定。
10. **历史证据原则**：旧版本保留为迁移证据和回归来源，但不再作为不可修改的活动权威层。

## 4. 目标架构

V7 采用五层结构，各层职责不得混用：

1. **发现层**：frontmatter 只负责说明何时触发本 Skill。
2. **控制层**：`SKILL.md` 只负责状态机、权限边界、必读门、冲突优先级和一级路由。
3. **规则层**：`rules/` 保存完整的领域程序、质量标准、阶段门和例外；细节不因入口瘦身而删除。
4. **注册与证据层**：`references/` 保存机器可读的责任注册表、原子能力账本、迁移映射、决策记录和 schema。
5. **执行与验证层**：`scripts/` 保存确定性操作、结构校验、可达性校验、迁移覆盖校验和行为回归。

## 5. 三个必须闭合的机器接口

### 5.1 原子能力账本

每条至少包含：

- `capability_id`
- `source_version`
- `source_file`
- `source_anchor`
- `normative_text`
- `strength`
- `v7_owner`
- `treatment`：`preserve`、`move`、`rewrite`、`merge`、`remove`
- `rationale`
- `trigger_ids`
- `test_ids`
- `status`

任何 `merge` 或 `remove` 项如果缺少目标能力、理由或行为测试，迁移失败。

### 5.2 责任与路由注册表

每个路由至少包含：

- 触发条件与排除条件；
- 所属阶段和所需批准；
- 唯一主责文件；
- 必须共同读取的交叉规则；
- 冲突优先级；
- 预期产物；
- 完成证据与失败回退。

### 5.3 行为回归套件

至少覆盖：

- 正常触发与不应触发；
- 多规则共同触发；
- 权限冲突和优先级；
- 阶段越级拒绝；
- 失败后的回退与下游失效；
- 草稿、正式稿和批准状态隔离；
- 删除任一原子能力后验证器必须失败；
- 真实项目夹具中的产物、轨迹和最终状态。

## 6. 本轮迁移顺序

1. 冻结 V6 全量基线并完成阅读/检查证据；
2. 生成原子能力账本，只登记，不改写；
3. 生成责任与路由注册表，识别重复、冲突和不可达项；
4. 为拟合并或拟删除项先写失败测试；
5. 再实施移动、改写和职责收敛；
6. 运行结构、迁移、行为和真实夹具四级验证；
7. 只有能力账本零孤儿、路由零不可达、回归全通过后，才能冻结 V7。

## 7. 当前禁止事项

- 不以减少文件数、行数或 token 数作为迁移成功指标；
- 不用早期精简版本覆盖 V6；
- 不在缺少原子映射时删除重复段落；
- 不把哈希一致当作能力一致；
- 不把关键词命中当作规则已被执行；
- 不把某一阶段批准自动传播为论文草稿或正式稿批准。
