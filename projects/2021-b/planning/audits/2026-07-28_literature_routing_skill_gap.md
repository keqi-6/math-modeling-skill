# 文献调查路由与skill组织缺口审计

## 1. 触发事件

项目进入第（1）问后，先整理数据证据和候选方法，直到用户询问化学机理才临时检索文献。
用户指出文献调查本应为问题背景、问题分析、变量解释和方法启发提供前置依据。

## 2. 根因

原skill的文献规则内容较完整，但组织存在断裂：

1. `08-literature-search.md`按专业职责横向存在，逐问闭环未把它列为基线前的显式步骤；
2. Stage 4同时容纳文献、基线和选模，没有阻止agent直接滑到后两者；
3. 初始化模板仍生成“全局探索—全局基线—全局选模—逐问求解”的旧横向计划；
4. `planning/inspiration.md`模板是孤立文件，没有逐问触发、产物和关闭条件；
5. 没有要求文献调查向负责人解释领域机理、辅助变量角色和具体分析启发；
6. 初始化模板要求同步 `literature.json` 和 `references.bib`，却没有创建这两个权威载体。

因此，本次属于“规则存在但路由和完成门失效”。

## 3. 结构性修复

| 层次 | 修改 | 作用 |
|---|---|---|
| 入口 | `skills/SKILL.md` | Stage 4在基线和选模前调用逐问文献导向门 |
| 流程 | `skills/15-pipeline-methodology.md` | 逐问闭环加入文献导向，并建立责任模块路由表 |
| 专责 | `skills/08-literature-search.md` | 增加触发条件、导向稿、来源同步和完成门 |
| 初始化 | `skills/scripts/bootstrap_project.py` | 新项目计划改为逐问闭环，并在每问基线前检查文献 |
| 证据载体 | `skills/scripts/bootstrap_project.py` | 初始化时创建人读总表、机器元数据和BibTeX载体 |

## 4. 新的执行不变量

当题目涉及陌生领域、辅助变量、现实机理、方法谱系、参数或外部主张时：

`题意与数据事实 → 文献导向 → 证据重审 → 基线 → 候选方法 → 人工决定`

文献前候选只能作为检索线索，不能升级为正式方法。文献调查必须说明怎样改变变量解释、
派生指标、图表、模型、验证或论文主张，不能只形成书目列表。

## 5. 未迁移内容

当前赛题名称、催化剂、产物、温度、已找到论文和具体机理均不进入通用skill，只进入项目
文献库。skill只保存跨项目触发、顺序、产物和验收规则。

## 6. 当前项目影响

- 第（1）问数据审计和探索事实仍有效；
- 第（1）问候选路线降级为文献前初步想法；
- 方法人工决定门暂时关闭；
- 下一步先建立正式文献记录、机理导向、方法谱系与论文主张矩阵。

## 7. 验收计划

1. skill结构校验；
2. 初始化脚本语法检查；
3. 在新鲜临时目录运行初始化，检查新计划是否包含逐问文献导向；
4. 检查skill未混入当前题目的专属词和结果；
5. 检查项目状态不再要求用户提前审定文献前候选方法。

## 8. 验收结果

- skill结构校验通过；
- 初始化脚本语法检查通过；
- 新鲜临时项目成功生成逐问文献导向计划；
- 新鲜项目同时生成 `references/README.md`、`literature.json` 和 `references.bib`；
- 通用skill未检出当前赛题的催化剂、产物、温度和结论；
- 当前项目已退回第（1）问文献导向阶段，文献前候选不再等待用户审定。

本次缺口关闭。
