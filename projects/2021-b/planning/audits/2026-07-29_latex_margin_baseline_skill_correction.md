# LaTeX 页边距实现基线 Skill 修正

日期：2026-07-29

## 触发问题

`skills/02-latex-setup.md` 已说明 DOCX 样例的上下 2.54 cm、左右 3.175 cm 不是模板
正文硬要求，但其 preamble 实现基线仍直接采用该值。这会诱导执行者机械复制样例隐藏
属性，并跳过项目确认。本项目实际发生了这一错误，用户要求同步修正通用 Skill。

## 通用修正

- 保留 DOCX 样例隐藏页边距的来源事实，只用于解释样例，不再作为新项目生成基线。
- 建立页边距优先级：官方/实际模板明示值优先，其次为用户确认值；二者均缺失时，才
  使用四边 2.5 cm 的中性工程默认值。
- 明确默认值不是官方要求，必须写入项目版式记录，并允许后续确认覆盖。
- preamble 示例改为 `margin=2.5cm`，注释同时提示替换条件。

## 迁移边界

本项目用户确认的四边 2.5 cm 是触发实例，不作为“所有竞赛必须 2.5 cm”的规则。
进入 Skill 的是来源分层、确认优先级和中性默认值，未写入本题名称、数据、模型或答案。

## 验证

- 搜索 Skill 后，2.54/3.175 cm 只保留在 DOCX 样例来源说明中；
- 可执行 preamble 不再含 3.175 cm；
- 规则同时覆盖官方明示、用户确认和均未确认三种情形；
- 运行 Skill 结构验证，并在修改后重读相关完整文件。

## 二次完整性审计

用户追问“该写的东西是否都写清楚”后，按触发条件、优先级、跨模块冲突、代码示例、
草稿治理和初始化残留再次检查。发现并修正两项遗漏：

1. “官方/模板明示值”对官方指定交付模板的可核验页面几何表述过窄，现改为既覆盖
   官方文字要求，也覆盖确需沿用的官方交付模板，同时排除普通样例和来源不明属性；
2. 唯一正式主稿规则没有说明 LaTeX 内容草稿如何合法存在，现增加目录、文件名、可见
   标记、PDF 元数据、人工迁入、协作镜像、正式交付排除和旧稿归档规则。

初始化脚本中未发现 2.54/3.175 cm 或其他页边距代码残留，因此不为本次问题修改脚本。
跨模块复核还发现 `01` 的“交付镜像”可能与 `02` 的“协作镜像”表面冲突，并且
`paper/*.tex` 容易被狭义理解为不含草稿子目录。现已明确：协作镜像可带显式草稿，
正式提交包和正式交付镜像不得带入；LaTeX 源文件统一位于 `paper/` 树下，草稿隔离
细则由 `02` 管理。

最终搜索发现初始化脚本生成的根 README 和 planning README 也含有狭义
`paper/*.tex` 表述。脚本已同步改为“`paper/`目录树中的`.tex`源文件”，并把草稿与
正式稿隔离路由到 `02`。脚本不预建空草稿目录，避免尚未进入草稿阶段便制造无职责
内容；需要 LaTeX 草稿时再按 `02` 建立。
