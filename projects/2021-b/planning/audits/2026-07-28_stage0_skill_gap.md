# 第0步项目建立与跨项目Skill缺口审计

## 审计触发

用户指出两次必须经人工纠正后才完成的启动动作：

1. 标准目录建立后，题面和附件没有立即落入 `data/`；
2. 总步骤清单最初以阶段管理和提交事项为主，没有把数据审计、探索分析、基线、候选
   模型、选模理由、人工选模、逐问求解与验证组成醒目的技术主线。

这两个问题均发生在具体模型选择之前，属于跨项目启动流程缺口，不是B题专用问题。

## 根因

### G0-01　目录契约有定义但没有关闭条件

- 既有规则说明了 `data/` 保存官方输入或指针，也要求复制前说明和批准。
- 既有规则没有要求初始化后逐目录验证“职责已经真实落地”。
- 因此执行可能把“目录已创建”误当作“项目已初始化”，留下空的 `data/`。

### G0-02　阶段地图存在但缺少面向用户的技术计划载体

- 既有管道完整覆盖SOURCE、DATA、DESIGN、SOLVE、VERIFY等阶段。
- 既有规则没有要求 `project_plan` 的主体首先回答“本题具体怎样做出来”。
- 因此通用阶段、协作治理和提交规范可能淹没数据—模型—求解—验证的技术主线。

## 跨项目修正

### R0-01　目录职责落地门

在 `skills/SKILL.md` 的强制启动动作和 `01-contest-project-pattern.md` 中新增：

- 初始化后逐目录检查真实职责，不以目录存在判定完成；
- 对已确认官方输入使用非破坏性副本落入 `data/` 并校验一致；复制不合理时建立明确
  指针；
- 临时锁、缓存和来源未定文件不得混入官方数据；
- 用户接受标准结构后，已确认官方输入的可逆职责落地无需再次逐文件确认；身份、冲突、
  移动或来源不确定时仍须返回用户。

### R0-02　技术做题计划优先

新增 `planning/project_plan.md` 为总技术步骤权威，主体采用：

`题意 → 数据审计 → 探索分析 → 简单基线 → 候选模型与理由 → 人工选模 → 数学规格
→ 逐问求解与冻结 → 独立验证 → 稳健性与边界 → 跨问整合 → 论文 → 全链复现`

时间排程、治理和提交合规置于附录或并列保障项，不允许通用阶段名代替当前题目的具体
动作。

### R0-03　初始化模板补强

更新 `skills/scripts/bootstrap_project.py`，新项目自动建立：

- `planning/README.md`；
- `planning/project_plan.md`；
- `planning/ai_usage_log.md`；
- `planning/analysis/`、`planning/audits/`、`planning/archive/`。

初始化输出的下一动作明确要求先完成目录职责落地。

### R0-04　Markdown与LaTeX格式边界

用户指出规划Markdown中混入了LaTeX数学命令。跨项目skill现明确要求项目的README、
HANDOFF、planning和docs Markdown只使用Markdown语法；数学关系使用普通文字、代码、
引用块或表格表达。正式论文LaTeX只进入 `paper/*.tex`。初始化模板同步写入该边界。

## 验证

- Skill结构校验：`Skill is valid!`
- 初始化脚本语法检查：通过，缓存定向至 `/tmp`。
- 新鲜临时项目测试：识别1份样本输入，非覆盖创建规划文件和三个规划子目录。
- 内容断言：`planning/project_plan.md` 含技术主线模板；初始化下一动作含目录职责落地。
- Markdown格式规则已进入skill入口、工程约定和初始化模板。
- 第一次测试中的只读缓存错误和错误样本路径属于测试命令缺陷；修正后完整重测通过。

## 影响与边界

- 修正规则适用于其他数学建模题，不包含B题参数、结论或专用路径。
- 没有删除既有独立规则；只增加缺失的触发条件、动作和完成判据。
- 本轮未推进B题题意、数据、模型、代码或论文。
