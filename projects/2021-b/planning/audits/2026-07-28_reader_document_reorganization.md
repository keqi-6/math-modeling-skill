# 面向负责人的文档重组审计

## 结论

需要重组的是负责人必须阅读、理解或据此决策的文档，不是全项目所有Markdown文件。

## 本轮已重组

| 文档 | 调整 |
|---|---|
| `planning/understanding.md` | 前置四句题意主线 |
| `planning/data_audit_methodology.md` | 前置五条数据处理原则 |
| `docs/data_audit/data_audit_report.md` | 前置阅读重点并解释两个内部用词 |
| `docs/eda/eda_report.md` | 用实际动作作为标题，专业名称后置 |
| `planning/project_plan.md` | 解释三个反复出现的项目用词 |
| 两份第一问分析稿 | 普通话结论和数字例子前置，统一四项决定 |

## 不重写但继续保留

- `references/`承担来源核验，必须保留论文题名、方法名称和DOI；
- 三份日志承担历史追溯，不能为了可读性改写已经发生的记录；
- `planning/audits/`承担问题与修正规则证据，主要供审计；
- 代码、表字段和复现说明保留必要名称，但新增负责人说明时先用普通话解释。

## 后续完成门

每进入一个新问题，只重组该问题当前需要阅读的材料。禁止提前把后续问题的术语一次性
交给负责人。
