## 1. 总体架构

不为五问各写一套互不相干的模型。共享内核负责输入、运动学、完整圆柱遮蔽、多烟幕联合
覆盖和连续区间求精；共享的“服务单元生成器”把一组平台航迹与投爆控制转换为可验证的
时空覆盖。各问题只逐层增加资源组织方式：评价、优化、同平台调度、多平台协调和多目标分配。

建议的逻辑组件：

| 组件 | 职责 | 主要消费者 |
|---|---|---|
| `SHARED_INPUT` | 题面常量、单位、模板字段和输入指纹 | Q1–Q5、验证、交付 |
| `SHARED_KINEMATICS` | 导弹、无人机、烟幕弹和烟幕云轨迹 | Q1–Q5 |
| `SHARED_GEOMETRY` | 完整圆柱遮蔽、线段条件、多烟幕共同覆盖 | Q1–Q5、独立验证 |
| `SHARED_INTERVALS` | 候选时间扫描、进入/退出括区间、根求精、区间并集 | Q1–Q5 |
| `SHARED_SERVICE` | 由物理可达走廊生成服务单元，并调用严格评价核返回有效时间集合 | Q2–Q5 |
| `SHARED_SOLVER` | 服务单元生成、组合调度、局部精修、缓存和日志 | Q2–Q5 |
| `Q1`–`Q5` | 各问参数化、约束、优化与专用输出 | 论文、表格 |
| `VERIFICATION` | 独立公式、收敛、约束、回读和回归测试 | 所有最终主张 |
| `MANUSCRIPT` | 从题意主轴组织模型、结果、解释和图表 | 最终论文 |
| `DELIVERY` | Excel、代码、环境、运行说明和清单 | 最终提交包 |

## 3. 各问求解策略

### Q1：把它做成全项目回归测试

- 输出起爆点、烟幕有效窗口、导弹位置和完整遮蔽的进入/退出时刻；
- 同时显示中心点简化约 1.434 s 与完整圆柱约 1.3916 s 的差别，解释为什么正式模型更严格；
- 之后每次修改共享几何内核都自动复算 Q1。

### Q2：针对稀疏零平台设计求解流程

- 从 Q1 和视线几何反推烟幕应出现的空间—时间走廊，生成可行种子；
- 采用多启动的差分进化、CMA-ES 或其他全局无导数方法，再用局部方法精修；
- 保存零平台失败运行，作为算法选择依据而非隐藏失败；
- 比较多组近最优参数，报告非唯一性和约束余量。

### Q3、Q4：复用同一服务单元，改变资源耦合

- Q3 中同一无人机的航向和速度共享；固定航迹后，用航迹—视线水平交点和下沉方程反解
  可行投爆事件，再调度三个满足相邻投放至少 1 s 的事件；
- Q4 中三架无人机各有一条独立航迹和一个服务事件，因此取消同机投放间隔耦合，改为组合
  三个平台的候选服务单元；
- 两题的目标函数均直接调用“烟幕集合对完整目标的共同覆盖时长”，而不是先算单弹时长再求和；
- 报告原始单弹贡献、边际贡献、重叠时长和协同产生的新增时长，但不把“三弹都必须贡献”
  或“必须出现纯协同”写成正式约束。

### Q5：分层而非 40 维盲搜

1. 复用 Q2 的单服务单元生成和 Q3 的同平台多事件调度，为每个“无人机—导弹”组合生成
   经严格复算的候选服务单元/服务束；
2. 用整数规划、最大覆盖或可解释的组合搜索分配候选及任务标签；该阶段只负责缩小组合规模；
3. 在选定组合附近回到原始连续变量联合优化；
4. 用逐导弹求值器重新计算，不依赖分配标签替代物理遮蔽；
5. 如无法证明全局最优，给出多启动下界、松弛/候选上界和稳定性，而不写“必为最优”。

## 4. 四层验证门

- **E1 输入与约束**：坐标、单位、速度、弹数、投放间隔、起爆高度、20 s 有效窗、模板字段和回读值。
- **E2 数值与实现**：独立几何实现、解析/高密度采样互验、时间网格收敛、根端点残差、确定性种子和运行环境。
- **E3 任务语义**：完整圆柱而非中心点；烟幕在线段方向；重叠不重复计时；多个部分烟幕可以共同覆盖。
- **E4 假设边界**：题面理想烟幕是主模型；风、扩散、浓度等未给机制只作局限性讨论，不伪造参数。

任何最终表格必须在 E1–E4 通过后生成；表格写出后再读取舍入值跑一遍 E1–E3。

## 5. 论文可理解性主线

论文不按“我们用了算法 A、B、C”罗列。建议叙事为：

1. 为什么本题本质上是移动视线与时空遮蔽体的相交问题；
2. 从四类运动方程推导烟幕的可达时空区域；
3. 为什么完整圆柱与线段方向是决定性几何难点；
4. 如何把瞬时遮蔽转成连续时间区间，并避免重叠双计；
5. 五问怎样逐层增加决策和协同复杂度；
6. 为什么求解器需要可行走廊、分层候选和独立验证；
7. 结果在几何、时间、资源分配上意味着什么，以及有哪些适用边界。

### 5.1 模型建立—求解—检验的写作边界

- **模型建立自含数学逻辑**：在模型公式之后立即完成必要的可计算化变形，并说明主求解步骤如何由这些公式推出；决定模型身份和主算法合法性的数学内容不能推迟到“模型求解”。
- **模型求解承接而不重建合同**：自然引用模型建立中的公式，只交代实际算法流程、初始化与参数、终止条件、输出生成和必要的计算复杂度，不重复推导，也不另立一套数学合同。
- **模型检验报告证据而不展开验证器**：只写检验对象、设置、指标、观测结果和结论边界；不展开临界角实根法、高密度求值器等内部交叉路径的数学推导。
- **强合同内部化**：任何只有依赖较长、独立的数学合同才能被解释清楚的方法，若不是正式主模型不可缺少的一部分，就降为内部验证器；不得出现在论文或队友讲解稿中。
- **外部数值不出稿**：公开论文、官方讲评或其他复现中的数值只作内部回归告警，不进入论文正文、摘要、表图、附录或队友讲解稿。

上述边界不削弱内部 E1/E2 技术验证；内部报告可以完整保存复现、残差和交叉求值记录，但它们不是面向评审或队友的写作素材。

最值得制作的四类图：

- 导弹—烟幕球—圆柱目标的几何示意图；
- 投放、起爆、下沉和遮蔽的同轴时间线；
- 各烟幕/各导弹有效区间及重叠的 Gantt 图；
- Q5 无人机—烟幕束—导弹的任务分配与空间轨迹图。

每张图都服务于一个难以只靠文字理解的关系，不为“显得丰富”而堆图。

## 6. 近期执行顺序与停线条件

WP0 的题面、模板和语义复核已形成工作问题定义；尚未执行 G2 状态晋级。实际执行顺序和阻塞关系以 `.modeling/state.json` 的 `next_actions` 为唯一准据。下一步先为 INPUTS 的身份/来源与 Q1 的 scope/problem_definition 组织类型化 checkpoint 证据，再申请相应状态迁移；通过后只推进 WP1–WP4，先把 Q1 做成高精度回归基准，再进入 Q2 优化。

遇到以下情况必须停线排查：

- Q1 完整圆柱时长无法稳定复现约 1.3916 s；
- 高密度独立采样与主几何判据在边界外仍有系统差异；
- 时间网格加密后结果持续漂移；
- 优化结果只有目标值，没有约束余量和可重放参数；
- 多弹总时长等于单弹时长简单求和但没有重叠/协同解释；
- 写入 Excel 后复算失去可行性。

## 7. V12 统一项目平台

下列是工件角色与规范路径，不是要求一次性创建的目录树。目录只在首个真实工件通过准入时按需建立；测试代码随其生产者归入 `src/<task-id>/tests/` 或 `src/_utils/tests/`，不另设无角色的顶层 `tests/`：

```text
A题/
├─ data/                   # 官方题面、附件、模板与原始输入，只读
├─ references/             # 外部文献、来源记录与合法取得的证据
├─ planning/               # 题意理解、计划、决定、审计与主张映射
├─ docs/                   # 推导、验证、复现、答辩等技术说明
├─ src/_utils/             # 共享运动学、几何、区间模块及共享测试
├─ src/q1/ ... src/q5/     # 分问题求解入口
├─ output/                 # 按问题或稳定生产阶段组织的机器结果
├─ paper/                  # 唯一面向评审的论文工作区
└─ delivery/               # 明确的最终交付暂存或镜像，非工作权威
```
