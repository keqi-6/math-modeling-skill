# Q5_v2 当前 13 枚弹方案有限结构审计规格

状态：G1 工作验证规格，不冻结 Q5_v2，不改变目标、候选域或当前结果身份。执行授权来自用户“去进行下一步吧”，对应 `planning/49_q5_v2_scope_and_manuscript_chain_decision.md` 的第一项下一动作。

## 1. 风险与待检主张

当前候选使用 13 枚烟幕弹，FY1 仅投 1 枚，其余四个平台各投 3 枚。结构审计针对两个可能推翻当前解释的风险：

1. 某枚烟幕弹或某个平台删除后 `J_sum` 不下降，说明它对题意第一目标冗余，不能把 13 枚弹全部写成必要资源；
2. FY1 的两个空槽在现有确定性平台计划族内可以直接换成更优多弹计划，说明当前候选仍存在无需扩大求解器的明显改进。

删除消融只支持当前方案的局部结构必要性，不证明全局最优；有限计划族未发现改进，也不能证明连续候选域不存在加弹改进。

## 2. 统一比较口径

- 基线决策来自 `docs/q5_v2_precise.json`，必须与 `docs/q5_v2_result.json` 的当前候选绑定；
- 逐弹和逐平台删除均保持其余航向、速度、投放和引信参数不变；
- 所有删除方案先回代速度、容量、投放间隔、非负时刻和起爆高度约束；
- 主比较统一使用 `SCREEN` 完整圆柱、有限视线段、多烟团联合覆盖和连续端点求根；
- 删除资源不可能创造新的遮蔽时段，因此删除复算可严格限制在当前 PRECISE 基线的逐导弹区间内；
- 以同层 SCREEN 基线减去删除方案的四项指标，主边际为 `Delta J_sum`，同时保留逐导弹损失、`Delta J_fair`、`Delta J_all` 和 `Delta L_all`；
- `Delta J_sum > 2e-4` 导弹·s 才在 SCREEN 层记为可分辨的正边际，该阈值沿用现有 `screen_strict` 排序容差，不从观察结果倒推。

## 3. 消融与空槽检查

1. 对 13 枚弹逐一删除，记录损失区间、指标差和约束余量；
2. 对 FY1—FY5 逐一删除整个平台；FY1 平台删除与其唯一烟幕删除复用同一结果；
3. 统计每个平台已用/未用槽位；
4. 只在现有确定性列生成器产生的 FY1 多弹完整计划中进行有限替换检查：保持 FY2—FY5 不变，以离散代理排序，取前 3 个方案作全时域 SCREEN 严格复算；
5. 若出现 SCREEN 严格改善，优先对该方案执行 PRECISE；否则在墙钟预算允许时，对逐弹删除中 `Delta J_sum` 最小者执行 PRECISE 定向确认。

FY1 多弹检查允许替换 FY1 的整条航迹和计划，属于现有候选库内的局部反例搜索；它不是固定当前航迹后对两个空槽的连续完备搜索。

## 4. 监管、停止与失败信号

执行墙钟预算为约 60 s。脚本必须在基线、每个逐弹消融、每个平台消融、候选库生成、每个 FY1 多弹候选和 PRECISE 确认后输出一条 JSON 进度，并原子更新 checkpoint。若高精度确认来不及，已完成的全部 SCREEN 消融仍保存，但报告必须标记 `PRECISE_CONFIRMATION_SKIPPED_BUDGET`，不得伪装成完整高精度审计。

失败信号包括：输入身份不一致、删除后约束不满足、删除方案指标超过同层基线的单调性违反、候选生成失败、严格评价异常或墙钟预算在完成全部 SCREEN 消融前耗尽。任一失败保留部分 checkpoint，不用缺失项补零。

## 5. 输出与主张边界

输出为：

- `docs/q5_v2_structural_audit.json`：逐弹、逐平台、空槽和候选替换的机读结果；
- `docs/q5_v2_structural_audit.md`：面向后续验证与讲解稿的工作摘要；
- `output/q5_v2/structural_audit_checkpoint.json`：运行中监管状态。

稳定工作主张 `A.Q5V2.STRUCTURAL_AUDIT.001` 只有在全部 13 枚弹和 5 个平台的 SCREEN 消融完成后才能形成；其允许表述限于“在固定其余参数和当前严格 SCREEN 口径下的删除边际”。PRECISE 只确认实际执行的单个或少量关键消融，不能把未确认项目统一升级为 PRECISE 证据。
