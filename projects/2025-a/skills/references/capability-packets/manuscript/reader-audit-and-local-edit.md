# 读者审计与局部修改

适用于从评审者首次阅读顺序检查论文，以及在不扩大任务的前提下完成局部正文修订。核心原则是：审计范围由实际修改和依赖决定，审计结论不得超过真正阅读与验证的范围。

来源保留：V1 `03-paper-content-rules.md`、`05-audit-protocol.md`，V2 `17-reader-first-manuscript-audit.md`，以及 V3–V5 的 reader/local/acceptance 原子；结合 V14 的最小一致性闭包重写。旧版完整规则阅读证明、每段固定表、七级日程、每次局部改动全文重审和逐句重复确认均不恢复。

## 一、先选正确审计范围

V14 控制器拥有权限、状态、路由和闭包解释权。本包只说明命中相应范围后怎样读、怎样修，不自建第二套门禁。

| 实际任务 | 默认阅读与复核面 | 不自动触发 |
|---|---|---|
| 错字、标点、纯句法且语义不变 | 目标句、完整段落、直接交叉引用 | 章节重构、全文读审、上游结果重绑 |
| 段落润色 | 目标段、相邻段、语义不变量、直接引用 | 全文风格统一、所有章节重验 |
| 术语、符号、单位、数字、数据身份或主张强度改变 | 目标段/节及该 identity 或主张的直接消费者 | 与该变化无关的章节和项目状态 |
| 局部实质改写 | 目标文本、所在章节、关联主张、直接重复与交叉引用 | 无依赖依据的整稿审计 |
| 章节完成或结构调整 | 目标章节、进入它的定义/证据、从它流出的主张及直接跨节依赖 | 其他独立章节 |
| 明确的全文审计、里程碑或发布候选 | 标题、摘要、正文、图表、结论、引用和最终渲染的完整适用范围 | 无关工作区、历史版本和未交付内部材料 |

局部改动触发跨章节依赖时，扩大到真实依赖面；扩大并不等于全文。只有用户要求整稿结论、正式检查或依赖确实贯穿全文时，才进入完整读者审计。

## 二、局部修改的完整程序

### 1. 固定请求与语义不变量

先写清用户要改什么，以及什么必须保持不变，例如事实、数值、模型对象、公式含义、结果身份、不确定性、论证强度、标题责任或版面语义。对纯润色，修改前后主张应等价；若无法保持等价，这不是普通润色，应按实质变化处理。

普通 G1 修改不要求把这一步持久化成回执。只需让实际 ChangeSet 能解释为什么改到这些位置。

### 2. 阅读真实上下文

至少阅读目标句所在完整段落；涉及承接、定义、因果或结论时，再读必要的相邻段和直接引用。搜索可以定位术语和消费者，不能代替连续阅读。

后文可用于核对重复和口径冲突，但不能倒推证明当前位置已经解释清楚。邻近上文已有唯一对象、定义和持续条件时，允许正常简称与回指，不把省略机械判错。

保留历史中的核心问法：

> 逐句审计不能只问“这句话是否正确”，还要问“它在当前位置承担什么职责、前一句能否推出它、后一句是否仍需要它”。

### 3. 判定缺陷属于哪一层

在动笔前把问题分成三类：

- **表达/沟通遗漏**：模型和证据正确，但正文缺对象、理由、定义、边界、比较基准或落点；可在稿件层局部修。
- **实现或规格冲突**：正文与公式、代码、数据口径、冻结结果或图表身份不一致；先定位真实权威链与最早错误层，不能靠改写把冲突抹平。
- **建模或证据遗漏**：当前模型没有题目所需变量、约束、机制、验证或可支持主张；稿件层只能报告缺口并收窄主张，不能凭文字补造能力。

修复最早的错误层，再传播到其真实消费者。若问题在上游，本次纯论文任务没有修改上游的授权，就停止在诊断/候选措辞，不静默改规格、代码或正式结果，也不因下游措辞调整重新绑定未改变的上游 identity。

### 4. 画出最小依赖面

根据改变的语义对象检查：

- 术语：首次定义、简称、同义表达及直接使用处；
- 符号/单位/索引：定义、公式、表头图注、结果和直接结论；
- 数字/数据身份：正式结果、正文、图表、摘要与结论中的直接消费者；
- 主张强度/成立条件：证据句、限定语、摘要、结论和引用它的段落；
- 标题或章节责任：目录入口、首末段、交叉引用和相邻交界；
- 局部措辞且语义不变：目标段、相邻语境和直接引用即可。

一个语义变化可跨多个文件；把这些直接消费者作为一个连贯 ChangeSet 同步，不按“每次只改一个文件”拆成互相不一致的中间态。没有真实依赖的命中不纳入修改。

### 5. 做最小充分修复

先修导致读者失败的最小成分：缺主语补主语，缺对象补对象，缺基准补基准，缺因果桥补最小机制，术语未解释补本题动作，主张过强收窄证据范围。只有段落职责或功能顺序整体错误时才重写整段。

若一句同时包含正确内容与缺陷，拆开处理；不要因一个越界短语删除整句，也不要借局部修订顺手统一无关风格。

### 6. 按依赖验收

修改后：

1. 连续重读改后的完整段落及必要邻接；
2. 比较修改前后语义不变量；
3. 检查新句是否造成重复、指代漂移、因果倒置或证明范围变化；
4. 核对直接消费者已同步且无悬空标签、引用、术语或数字；
5. 涉及 LaTeX 时编译并查看受影响页与必要相邻页；
6. 只对实际范围作通过/未通过结论。

局部验收通过不等于章节或全文通过。反之，局部修改没有依赖扩散时，不得为了“保险”强制重读全文。

## 三、读者视角的诊断方法

### 白话复述

对方法、结果或高密度段落，在内部补全：

`这一段实际上是在说：为什么做；对什么对象怎样做；得到什么判断；它回答什么；不能推出什么。`

复述尽量不依赖原段专业名称。若仍只能说“采用某模型、指标更好、结果可靠”，说明正文缺少机制、判据或落点。

> 复述是审计工具，不机械写入论文；论文正文应吸收其中必要的白话解释。

### 遮蔽测试

- 遮去模型名：剩余文字能否说明它怎样工作、为何适用；
- 遮去结果数字：剩余文字能否说明比较口径和形成机制；
- 遮去形容词：结论是否仍由数据、推导或检验支持；
- 只读段首：能否看出段落来意与承接；
- 只读段末：能否看出证据落点或下游输入。

遮蔽测试是诊断，不是要求正文删除术语和数字，也不要求每段保存审计记录。

### 首次使用与邻近因果

按首次阅读顺序检查：术语、符号、指标、数据字段和判断规则是否在首次实质使用处可懂；“因此、导致、等价、最优、验证、稳健”等判断附近是否有能推出它的理由及范围。

区分数学类别：题意定义任务边界，约束决定可行，目标在可行方案中排序，算法寻找或排除候选，验证只支持其实际检查的性质。把这些职责互相归因，是实质逻辑错误，不是文风偏好。

## 四、章节审计怎么做

当任务是完成或审计一个章节时：

1. 用一句话说明本节应回答的读者问题；
2. 列出本节真实接收的定义、数据、假设、模型或上节结果；
3. 顺序阅读本节，不只扫标题和关键词；
4. 检查每个主要主张的对象、理由、证据和边界；
5. 检查公式、图表和数字是否有正文解释并指向同一身份；
6. 检查本节输出是否被后续摘要、结果、结论或下一问正确消费；
7. 按本节专属职责判定完成，不用统一标题清单替代内容验收。

若本节的输入或输出跨章节冲突，只扩展到相关定义、主张和直接消费者。独立章节不因一个局部失败自动失效。

## 五、完整读者审计怎么做

只有在明确的全文审计、完整候选、里程碑或正式交付范围内执行本节。审计前确认实际可见稿件、对应源入口和正式结果/图件身份；审计后声明真正阅读和验证了什么，不从抽查声称整稿通过。

### 第一遍：结构与前置内容

- 题目、摘要和关键词是否准确代表正文，不增加未证明亮点；
- 每项原题任务能否定位到方法、结果和直接回答；
- 章节按定义—证据—推导—结论依赖组织，而不是工作日志；
- 背景、重述、分析、假设和方法职责是否混杂；
- 标题是否能导航而不代替内容。

### 第二遍：按首次阅读顺序连续阅读

- 术语、符号、单位、数据口径在首次实质使用处是否可懂；
- 段落来意、承接和落点是否自然；
- 公式、算法、数字和图表是否嵌入解释链；
- 每个因果、比较、最优性和稳健性措辞是否有邻近依据；
- 正文是否必须依赖代码、聊天、审计表或内部说明才能理解。

### 第三遍：逐问证据与边界

对每一问沿以下链反向核对：

`直接答案 → 主结果/证据 → 计算或推导 → 模型规格 → 输入与题意`

确认摘要、正文、图表、结论使用同一对象、口径、数字和证明强度；辅助检验说明其能排除什么风险以及不能证明什么。共享基础不能替代每问自己的结果与回答。

### 第四遍：跨载体与最终可见稿

- 标签、引用、图表题注、表头、公式编号和参考文献没有悬空或错配；
- 评审可见正文没有“已通过审计、待 Agent 检查、内部状态”等流程元语言；
- 结果、限制与结论没有被版面、浮动或分页切断；
- 最终 PDF 的相关页面真实可读，而非只看源文件或编译退出码。

完整审计的发现可按影响和位置组织，不需要把每段转成固定多字段矩阵。完成声称必须绑定实际读审范围与未决项。

## 六、常见失败与局部修复

| 读者失败 | 诊断 | 最小修复 |
|---|---|---|
| 首次出现模型名但不知其作用 | 就地解释缺失 | 在首次实质使用处补对象、动作、判据；严格公式仍留正式位置 |
| “其、该指标、最优值”对象不唯一 | 回指失败 | 重复准确名称并补候选域/条件 |
| 只报数或贴表 | 解释链断裂 | 补身份、基准、可见现象、题目含义和必要边界 |
| 前后都正确但“因此”不成立 | 因果桥缺失 | 补能推出结论的最小关系，或降低为观察性措辞 |
| 问题分析与模型节重复流程 | 章节错位 | 前者保留困难与选型理由，后者承载变量、公式和操作 |
| 多处定义近似但口径漂移 | identity 冲突 | 回到当前权威定义，统一直接消费者，不按出现次数投票 |
| 为解释一处修改新增整段 | 修复过度 | 收回到缺失职能；保留未变句序和语义 |
| 正文出现内部审计语言 | 载体污染 | 删除流程叙述，改写为读者所需事实/证据；不做单纯关键词删除 |
| 稿件主张与代码/结果冲突 | 上游或 identity 问题 | 定位最早错误层；无上游授权时只报告并收窄稿件主张 |
| 修一个错字却启动全文审计 | 范围过度 | 回到目标段与直接依赖；无扩散就结束局部验收 |

## 七、完成标准

局部任务完成，当修改范围可由请求与直接依赖解释、语义不变量保持、直接消费者一致、受影响文本连续可读，且结论只覆盖实际复核范围。

章节任务完成，当该节责任闭合、输入输出可追踪、主张证据相称、直接跨节依赖一致。

整稿任务完成，当完整读者路径、逐问证据链、跨载体 identity、前置内容、结论、引用和最终渲染都在实际范围内通过，并明确保留仍存在的材料性限制。

任何层级都不以“脚本成功、编译通过、表格填满或没有命中禁词”作为充分条件。

## 八、必要人工确认点

以下情形需要人工决定，前提是当前任务尚未给出相应授权：

- 两种合理题意、模型口径或主张边界会导向不同正文；
- 局部修复必须改变正式数字、结果身份、因果/证明强度或上游规格；
- 删除、合并或重写会改变主要论证或读者回答路径；
- 发现正式候选与已发布版本、官方要求或人工批准内容冲突；
- 要从局部结论升级为章节/全文通过或正式状态。

普通的拼写、句法、指代、邻近解释和直接依赖同步，在既有授权内完成即可。不得把本包变成每句询问、每文件回执或每次改动重走全文的控制器。
