# 文献、来源与交付方法提示（非规范性）

本文件不授予联网、写入或交付权限。当前路由原子决定必须满足的要求。

## 检索与来源评价

把检索问题写成“哪个来源能支持或反驳主张 C 的范围 R”。可组合对象、机制、场景、指标、年份和来源类型构造查询。技术事实优先查原始论文或官方文档；数据事实优先查发布者；规则、格式、日期和资格问题优先查当期官方通知。

来源评价可以分为：身份是否明确、内容是否实际访问、方法是否适合主张、时间是否仍有效、利益冲突是否影响解释、许可是否允许当前用途。搜索片段适合发现候选，不适合承担正文证据。

一个轻量的主张映射可直接保存在现有稿件引用系统、项目数据库或权威状态中；无需同时生成多种清单文件。

## 精确身份绑定

V11 的证据不再绑定“整个组件当前长什么样”。每条证据只声明自己实际使用的输入和实际支持、核对或反驳的主张：

- `input_refs` 是规范化数组；每项包含 `kind`、`id`、`identity` 和 `facet`。工件输入使用项目相对路径作为 `id`，使用该版本的 SHA-256 作为 `identity`。
- `claim_refs` 是排序、去重后的稳定主张 ID。没有主张对象的纯接口或文件验证可以为空，但不得虚构主张来满足字段。
- 当一条证据把另一主张作为输入时，另在 `input_refs` 中使用 `kind: claim`、稳定主张 ID 和该主张旧版本的精确 identity。这样只有该主张版本真的改变时才沿主张依赖传播；同组件的其他主张不会被捆绑失效。
- `binding_hash` 只由 `component_id`、证据 `level`、`input_refs` 和 `claim_refs` 计算。文件位置、组件中其他工件或不相关决定发生变化，不会改变该证据的绑定。
- locator 继续证明“观察是怎样取得的”；input refs 证明“观察依赖哪个版本”。两者不能互相替代。

例如，一条核对论文表格数值的证据可以绑定结果文件的确切 identity，并把表格主张 ID 放入 `claim_refs`。以后只改论文标点时，该结果证据仍有效；结果文件 identity 改变时，只有引用旧 identity 的证据变为 stale。

### 失效边界

发现变化后先区分事实和后果：

1. 新登记一个工件只是增加身份记录，不推翻任何已有证据。
2. 更新 working identity 时，清除该工件自身的验证状态，并只失效精确引用旧 identity 的证据。
3. milestone、frozen 或 final identity 改变时，除了上述定点失效，还可使其真实生产者、声明消费者和传递下游进入待复核状态。
4. 下游稿件、图表或排版变化默认不得使模型、数据或早期问题证据失效。若复核暴露真实上游错误，应把该错误记录为新的上游 identity/claim 变化，再按下游方向传播。

若某个工件的具名 `artifact_validation` 证据因精确输入变化而 stale，只撤销该工件的 validated 标记；这不是把整个组件或所有历史证据一并作废。

组件复核只补当前阶段要求中已 stale 或缺失的证据。仍绑定当前输入、且主张范围未改变的 pass 证据可以继续使用；不得为了形成“新 epoch”机械重录全部历史门。

### 恢复与检查层级

G1 的普通编辑和状态提交不创建 execution，也不构造或比较全工作区 manifest。默认恢复只核对当前仍正式生效的 milestone、frozen、final 登记 identity；working 与已 superseded identity 不进入恢复扫描。只有权威状态损坏、身份归属冲突或用户显式要求全量恢复时进入 R2；G3 发布审计本身不是 R2。正式 identity 的可定位变化进入 R1，并只覆盖其生产者、声明消费者和真实下游。

## delivery

交付复核可从白名单反向检查：

| 对象 | 需要重建的身份 |
|---|---|
| 数据 | 来源、版本、哈希、处理谱系 |
| 代码 | 入口、环境、参数、随机种子 |
| 结果 | 运行 ID、指标、单位、输出哈希 |
| 稿件 | 源、渲染稿、引用和图表版本 |
| 外部材料 | 来源、访问日期、许可处置 |

交付包中的缓存、临时中间量、环境凭据和无法授权再分发的材料通常不应出现。
