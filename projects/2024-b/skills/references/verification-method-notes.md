# 验证方法提示（非规范性）

## implementation-axis

E1 可组合接口契约、单位检查、边界输入、异常路径、固定种子复现和小规模穷举。E2 可使用独立公式、另一求解器、高精度版本、解析特例或网格加密。容差应来自尺度、数值方法阶数或决策敏感度，而不是来自观测到的差异。

E1 的路径清单应区分正式入口、影响结论的分支和错误路径。退出码为零只说明进程结束，不是结果 oracle。E2 的 convergence 使用有序加严序列观察残差、收敛率或决策稳定；舍入、截断和图形平滑不能隐藏原始数值波动。

## model-axis

E3 关注模型内部结构：可行性残差、守恒量、单调性、对称性、极限行为、反例和敏感性。E4 关注现实映射：假设适用性、参数识别、数量级、场景覆盖、因果边界和结果可解释性。

敏感性把关键输入、参数或结构选择映射到输出与决策响应。机制核验比较模型表达的过程方向、约束和相互作用；reality fit 再比较观测模式、范围、上下文和预定用途。二者不同于“数量级看起来合理”。

| 失败现象 | 更可能暴露的层级 |
|---|---|
| 输入形状崩溃 | E1 |
| 换步长后结论翻转 | E2 |
| 解违反资源约束 | E3 |
| 参数远超现实范围 | E4 |

## 不确定性与稳健性

先区分数据噪声、参数不确定、结构不确定和数值误差。概率信息充分时可用蒙特卡洛、bootstrap 或贝叶斯后验传播；只有范围信息时可用区间、情景或最坏情形分析。稳健性结果最好给出结论翻转边界，而不只是“扰动后变化不大”。

不确定性结果至少是可复核的量或有依据的界，并映射到受影响主张；模板化限制段落不替代分析。稳健性分析在查看扰动结果之前登记指标、尺度、方向、决策阈值和名义基线，以免事后挑选有利比较。视觉相似可用于展示，不能单独成为稳健性证明。

## s6-closure

S5→S6 表示实现和数值轴已具备通过证据，项目进入完整验证阶段。S6→S7 只核验当前 E1–E4 四轴证据；结果主张在结果边界闭合，交付验收在后续 artifact/交付边界闭合，不再错位塞进 S6。若任何证据后来失效，依赖图决定精确回退范围。

S7 仍允许只读复核 E1–E4、不确定性和稳健性。若复核推翻既有证据，后续修复不能在 S7 原地覆盖：共享 route/state contract 应先失效消费者并执行合法重开。当前验证原子均为 `agent_obligation / selection_verified`，因此它们证明选择与声明边界，不声称脚本已自动执行领域 oracle 或自动完成状态回退。
