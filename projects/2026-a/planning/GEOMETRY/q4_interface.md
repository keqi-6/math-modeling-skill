# 问题4半径接口

本文件定义 GEOMETRY 对 Q4 的唯一半径输入合同。数据决定及原始审计见 `planning/GEOMETRY/data_audit.md`。本合同的技术选择由本轮用户自主推进授权承接，不表示已经取得完整稿人读或 E4 实测确认。

## 精确原件与候选

输入 `附件/附件2.xlsx`，SHA256 `5563acbfa4b4afb10cc6c03e2207e5369bf39da27576672aff14cc5c32e704af`，Sheet1!A2:B146；145节点，每1800 s一条，覆盖0–259200 s。输出候选为 `output/GEOMETRY/q4_radius.json`，主键 `nodes[].time_s`，每项包括原始 `radius_cm` 和 `source_row`。不提前转换或舍入节点，也不复制一套舍入后的米制观测。schema_version=1.0。

JSON 包含原件路径/字节数/哈希/工作表/范围、字段单位、范围、插值与延拓规则、生产者和消费者。其 SHA 是正式冻结身份，消费者必须核对该身份及所声明的原件身份；改变任一原始节点或规则都属于接口变化。

## 求值规则

对于 t_i≤t≤t_(i+1)，令 w=(t−t_i)/1800，则

R(t)=0.01[(1−w)R_i,cm+w R_(i+1),cm] m。

恰在原节点返回该节点半径×0.01。R为正且不增，无局部过冲；连续时间派生值不是新增观测。例：R(900 s)=0.019365 m，R(2700 s)=0.018335 m，R(0)=0.02000 m，R(259200)=0.01198 m。900 s处在原始第2、3行之间，权重1/2。

Q4材料坐标主方程只要求 R(t)，不要求 Rdot。若诊断输出分段斜率，则开区间内 Rdot=0.01(R_(i+1),cm−R_i,cm)/1800 m/s；节点导数可不定义，不能将某个单侧值当成测量。这不是对Q4生产求解器的新接口要求。

敏感性 `pchip` 使用全部145个节点的形状保持分段三次插值，先在 cm 上求值，再乘0.01。它是另一明确记录的输入情景，不改主接口原节点或默认方法。不能用其场输出冒充线性主情景。

## 范围与错误

正常支持域为闭区间[0,259200] s。非有限时间、负时间、未知方法或未知延拓策略必须报错；默认 t>259200 也报错。消费者只有在实际需要超过72 h时才显式指定 `hold_last` 并记录首次使用与使用范围，此时返回0.01198 m。不删除负半径或非法时间后继续运行，不默默外推。

## 独立核对与接受条件

主转换只读取 openpyxl 单元格，独立核对另行打开原件ZIP/XML并以 Decimal 解析原值。逐项核对145条主键、145个原半径与145个源行号（435字段）；半径与独立解析原XML所得binary64位值精确一致。JSON最短十进制与原XML长十进制可表示同一binary64数值，这种文本差单列诊断，不作为观测修改；原XML十进制仍用于下述Decimal曲线参照。元数据、正性、顺序、覆盖、单位和方法声明一致。遍历全部259201个整数秒，候选线性求值与独立 Decimal 权威线性参照的最大差应≤1e−14 m，且不超出相邻端点。每区间再核对一个非整数时刻以覆盖求解器的连续时间消费。

检查 −1、NaN、Inf、259201 s 的默认报错，以及显式 hold_last 的末值行为；这是输入接口验证，不是温湿求解。PCHIP只对节点保持、正性和单调性作辅助检查；不能以此代替Q4场敏感性运行。报告必须绑定本候选、原件及实际执行的生成/核对脚本哈希。
