# 产物谱系、机器交接与双向证据链

适用于跨脚本数据流、正式结果登记、图表和论文主张绑定、项目交接与上游变化传播。格式和文件数量按项目需要选择，不能反向定义证据链。

来源保留：V8 `10-json-handoff.md`、`28-evidence-acceptance.md`、`35-provenance-delivery-minimum.md`，结合 V14 的工件 identity、精确消费者和恢复合同。

## 双向链

正向：

`题面/原始数据 → 解释 → 处理/设计 → 规格 → 代码 → 正式输出 → 验证 → 图表/正文 → 结论`

反向：

`重要主张 → 图表/正式输出 → 代码 → 规格 → 解释 → 原始输入`

每个关键主张记录证据路径、验证状态、适用范围和禁止外推。发生冲突时定位最早的不受支持层，再传播到真实消费者；不能让论文、状态文件、README 或交接摘要单独覆盖其他证据。

## 生产者—产物—消费者

每个当前正式产物登记：

- 生产者与实际生成路径；
- 精确输入、规格/决定 identity 和参数；
- schema、单位、维度、版本和哈希；
- 直接消费者、支撑主张和当前状态；
- 生成/验证时间或运行身份。

消费者可以是下游脚本、图表、稿件主张、独立验证或交付材料。没有脚本读取不等于孤儿；没有生产者、用途、消费者或版本状态的文件不能作为当前证据。

选择适合结构的载体：小型元数据可用 JSON，表可用 CSV/Parquet，矩阵可用 NPZ，图件保留可编辑源与渲染物。不得为满足格式虚构 JSON，也不得把 stdout 或从论文反抄的数字当正式输出。

## 代码和运行交接

影响结论、产生正式工件或供下游调用的程序，应能快速定位中文可读的输入、输出和数学职责；可放在 docstring、头部注释、工作流配置或集中清单，但必须与真实读写一致。

正式运行记录输入 identity、代码版本/提交、参数、种子、环境/求解器版本、开始结束状态和输出 identity。进度和调试可留 stdout；支撑主张的数字必须进入可检查载体。

基线由前期权威生产者冻结，下游统一消费，不能从后期最优结果反向定义。依赖图保持无环；文件编号可帮助阅读，不能证明依赖顺序。

## 真实性和独立复核

- 原始输入只读，结构化、派生、设置和纠正分开。
- 代码声明的输入输出与真实行为一致。
- 验证尽量不复用主实现的结论逻辑。
- 数值按题设常量、分析设置和运行结果区分；临界值、最优值和推荐方案不能硬写回求解逻辑。
- 搜索写入函数只能发现候选读写点，不能证明产物完整。

## 数值身份、方法角色与消费者

数值的字面内容不能决定其身份。对会进入结果解释、图表、论文、讲解或交付的数值，保存：

`value → authority/source identity → use role → producing run（若有）→ verification → permitted consumers → actual consumers`

当前项目正式输出必须回到自己的输入、冻结规格和运行；外部参数、现实基准、公开答案和内部诊断分别登记，不能从论文、图表或公开参考反抄成机器结果。一个项目输出与外部参照相同不改变其生产身份；一个外部参照被正确引用也不自动取得正式结果身份。

消费者边界是谱系的一部分。标为内部回归、候选启发或内部诊断的外部数值，只能留在获准的技术证据和告警中，不进入论文、已触发的人类讲解或正式验收。辅助验证方法也登记 `primary_model`、`primary_solver` 或 `auxiliary_validator`：若非主验证器需要独立强数学合同，其完整推导指向内部技术证据，面向评审或一般交接的消费者只读取检验对象、设置、指标、结果和结论边界。若它实际决定正式答案或核心证明，则应改变方法角色并重新处理上游规格，而不是只放宽消费者列表。

消费者政策不强制创建新的台账或讲解稿。只有现有产物真实消费该数值或方法时才登记；用户明确要求或明确人类交接触发讲解后，讲解才成为需要核对的消费者。这项核对是内容与谱系约束，不是 S7 状态门。

## 队友来稿与独立数值

审阅上传稿时按用户所需深度核对求解逻辑、公式、表格和实际实现，不因行文不同就重写原稿。未知来源的数字先记为待核，不凭本机没有记录判为捏造；取得授权复现后，先对齐输入、计量基准、模型情境、边界延续、数值设置和判据。结果接近只能支持已比较范围，不能倒推出队友使用的代码、网格或算法；同一仓库的多个版本也不天然构成独立证据。

教材原理、稿中算法名与产生现有结果的实际实现分别核对，例如固定二阶示例不能直接冒充变阶方法，某种界面平均本身合理也不代表当前程序用了它。发现冲突先判断是稿件描述错误还是实现偏离规格，不为迎合稿件而默认重算。参考与来稿保留其来源身份；只有获准的消费者才接收复核后内容。

## 变化传播

上游解释、数据、假设、目标、约束、参数、代码语义或正式 output identity 变化时，列出直接与传递消费者。每个消费者选择：重新生成、证明仍有效，或明确标记 stale/provisional。

只有精确引用旧 identity 或已变主张的对象失效；下游文字或排版变化不反向推翻数据和模型。旧版本可以保留追溯，但不能继续标为当前权威。题意解释或批准归属被纠正时，同样检查仍被当前入口引用的早期诊断、审计摘要和交接说明；保留原始历史身份时给出勘误或替代入口，不静默改写历史。不再被消费的旧记录无需批量重写。

## 交接和恢复

交接保存当前权威 identity、已确认决定、未决问题、下一合法动作、运行/验证边界和已知变化。摘要用于导航，不替代实际文件读取和证据。

不得为补齐档案虚构历史操作、时间戳或完整流水线重跑。只能陈述日志记录的事实，或把 identity/依赖支持的内容标为“事后可确认的重建”。恢复范围由 V14/V15 控制契约按当前动作决定，本包不要求每次接手全项目复读。
